## Body

## TL;DR

The ordinary comparison model fixes the activity probability to 100%, but the convergence check was treating that fixed value as if it had been sampled. Its R-hat and effective sample size are mathematically undefined, so the GPU probe falsely failed both allowed attempts. This change checks convergence only for variables PyMC actually sampled, while still counting every divergence and checking all sampled activity variables in the candidate model.

## Trigger and resulting behavior

During the registered #384 probe, the ordinary/null task wrote a terminal failure saying `activity_probability` had non-finite R-hat diagnostics. That field is an analytic constant in the ordinary arm, so the failure would have affected all 360 ordinary tasks and prevented paired finalization.

`summarize_sampler_diagnostics` now accepts an explicit, validated tuple of posterior variables. `fit_spatial_activity_graph` supplies the exact names from `model.free_RVs`:

- ordinary arm: conditional process, cohort effects, and concentration;
- spatial-activity arm: the same variables plus every sampled activity-process parameter.

Requested names must exist in the posterior. Divergences still come from the complete sampler-statistics array and are never filtered.

Closes #388. Advances #384. Implements the convergence refusal boundary in design §§7, 8, and 12.
