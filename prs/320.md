### Full-vector synthetic execution evidence

I ran the stacked `d98794b` implementation on the frozen synthetic full-vector workload: 510 variants, 80 populations, 32,640 training cells, 8,160 held-out cells, four chains, 500 posterior draws, 1,000 tuning draws, and seed 42. This is a capacity and execution probe; it is not scientific or publication evidence.

- Total runtime was **1,521.63 s (25.36 min)**: 123.50 s fitting and 1,398.12 s exact held-out scoring.
- Sampling finished with 0 divergences, maximum R-hat 1.0137, minimum bulk ESS 1,639.5, and minimum tail ESS 965.3.
- Peak process RSS was 2.745 GiB; peak observed GPU memory was 2,963 MiB. Across 1,454 observations, GPU utilization was 24.9% mean, 22% median, 32.9% p95, and 97% maximum.
- All 55 retrieved evidence files (27,500,052 bytes) were rehashed, and the posterior arrays and all 8,160 diagnostic rows passed terminal validation.

For context, the earlier traced run on the same frozen input/configuration took 5,944.71 s (99.08 min) and peaked at 14.56 GiB RSS. That is an observed 3.91× end-to-end capacity difference, **not an isolated code-speedup claim**: the earlier source differed and only that run carried the profiler.

One probe represents one fold-equivalent. The frozen comparison matrix contains 24 members × 5 folds = 120 fold-equivalents, giving a simple projection of **50.72 sequential GPU-hours**, or **12.68 hours at four perfectly concurrent workers**. That concurrent figure is an idealized lower bound; it excludes provisioning, transfer, contention, refusals, and retries. It does not establish real-data eligibility or support launching the real matrix before calibration passes.
