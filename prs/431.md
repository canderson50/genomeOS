## What this changes, and why

These are review follow-ups to #429, as one commit on top of its head (`03dbe3c`), to merge into `feat/site-analytics`.

1. **Quebec and Turkey join the opt-in regions.**
   - Quebec's Law 25 is widely read as requiring tracking and profiling technology, analytics included, to be off by default.
   - Turkey's KVKK cookie guideline asks for explicit consent for non-essential cookies, and GA is third-party.
   - **Google's IP region default** gains `TR` and `CA-QC`. `CA-QC` is an ISO 3166-2 code, a form Consent Mode's `region` accepts.
   - **Browser opt-in zones** gain `Europe/Istanbul` and `Asia/Istanbul` (Turkey), and `America/Toronto`, `America/Montreal` and `America/Blanc-Sablon` (Quebec).
   - **Ontario is asked too.** Browsers in Quebec report `America/Toronto`, which Ontario shares. That over-inclusion was the deliberate choice, and it matches how #429 already treats zones: asking a visitor elsewhere first costs only a prompt.
   - The Magdalen Islands keep Atlantic time (`America/Halifax`, shared with the Maritimes), so they rely on Google's IP default.
2. **`atlas_dataset_open` is sent only after an explicit opt-in, worldwide.**
   - Which dataset someone opens (a sickle-cell or G6PD map, say) can hint at a health interest.
   - Washington's My Health My Data Act has no nonprofit exemption and requires opt-in consent to collect "consumer health data". Nevada and Connecticut have similar laws. Whether "opened a public genetics map" counts is untested, so this takes the safe side.
   - An explicit opt-in is a stored `granted` from Accept or the analytics switch. The opt-out default outside the opt-in regions does not count.
   - Without that, the event is not sent at all. `atlas_view_change` and `atlas_inspector_open` are unchanged.
   - The choice is read when the event is sent, so an Accept on the page counts from the next dataset open. A dropped open leaves no dedupe memory and is not replayed.
3. **`/privacy/`** names the new regions, says Eastern Time in Canada is asked too, and says datasets are counted only after Accept or the switch.

The GA settings are already done: "Page changes based on browser history events" is off, and the URL query parameters `lat`, `lon`, `height`, `heading`, `pitch` and `cell` are redacted.

### bschilder, COMMENTED, 2026-10-11T16:30:12Z (https://github.com/genomeOS/genomeOS/pull/431#pullrequestreview-5484055568)

Thanks, this reads well. The code matches the description, and the gate sits inside `createEventTracker`'s `try`, so a storage error can't throw. One blocker is outside the diff, in GA Admin, plus two small points.

**1. History-event page views are still on in the live tag, so the dataset id still reaches GA.** `gtag/js?id=<our ID>` (fetched with cache-busting, both `gtag/js` and `gtag/destination`) still serves:

```
"__ogt_auto_events" … "vtp_enableHistoryEvents":true
"__ccd_auto_redact" … "vtp_redactQueryParams":"lat,lon,height,heading,pitch,cell"
```

The redaction did reach the tag, so edits are propagating. The history toggle didn't take, perhaps because the Enhanced measurement panel wasn't saved.

While it is on, every Atlas `replaceState` fires an automatic `page_view` whose `page_location` is the full URL. That URL always carries `?entity=<dataset id>` (`url-state.ts:494`), and `entity` is not in the redaction list. So the dataset reaches GA in opt-out regions with no explicit opt-in. That undoes item 2 here and makes the new `/privacy/` sentence untrue.

The config's own `page_view` and `page_referrer` already strip the query (`ga.mjs`), so only the history events leak it. Two GA Admin steps fix it:

- Admin → Data streams → (web stream) → Enhanced measurement → ⚙ Page views → Show advanced settings → untick **Page changes based on browser history events** → **Save**.
- Add `entity` to the redacted query parameters, as defence in depth.

Once the tag serves `"vtp_enableHistoryEvents":false`, this is resolved.

**2. In practice, dataset opens will be counted only for opt-in-region visitors who choose Accept.** Outside those regions the switch is already on, so "turned analytics on yourself" means switching it off and back on, which hardly anyone does. That's a defensible reading of the health-data laws. It is also the main metric #422 set out to collect, so the owner should knowingly sign off on losing it. (I'm flagging this, not asking for a change.)

**3. Minor, privacy page:** western Ontario is on Central time (`America/Winnipeg`), so "covers Ontario" might be "covers most of Ontario". It's optional.

The three phone failures of "Atlas icon … rides in the credit row" that you saw on `03dbe3c` are a known flake on #429 (#430). A root-cause fix is in progress on `feat/site-analytics`, and it touches a different part of `analytics.spec.ts` from this PR.
