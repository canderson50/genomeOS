## What this changes, and why

`tests/test_contract_frozen.py::test_frozen_contract_matches_the_live_schemas` runs `scripts/freeze_contract.py --check` in a subprocess.

**The cause.** Running a script puts the script's directory on `sys.path`, not the cwd. So the subprocess imported `genomeos` through the editable install, and in a git worktree that is a different checkout.

**The fix** is the one the issue proposes: pass `PYTHONPATH=REPO` so the subprocess imports the tree under test. A comment says why.

**The trap bites in two directions, and I verified both:**

1. **A false alarm (the issue's case).** A worktree branch that adds a module fails with `ModuleNotFoundError`, and the failure reads as contract drift.
2. **A false pass (worse, and not in the issue).** With genuine schema drift in a worktree, the old test passes. It compares the worktree's `contract/*.json` against the main checkout's schemas, so drift on the branch under review goes unnoticed.

This PR fixes both.
