## Body

Closes #134. Design sections: §4 (provenance), §6 (schema), §9 (refusal is a valid output), §12.

## The bug

AFND ships four data families and a `group` column saying which is which. The adapter ignored that
column and hardcoded `hla:` on every id.

| group | rows | genes | what it is |
|---|---|---|---|
| `hla` | 111,399 | 8 | classical HLA alleles |
| `kir` | 6,714 | 18 | KIR genes, copy-number variable |
| `cyt` | 4,517 | 29 | cytokine promoter genotypes |
| `mic` | 872 | 2 | MICA / MICB |

So `KIR2DL1` became `hla:2dl1` and an IL-6 promoter genotype became `hla:il-6-174`. Only 4 variants
over 121 observations survived the coverage filter wearing the wrong prefix, but an id is a
provenance claim and a false one is a bug under §4, not a naming preference.

## What the mislabelling was hiding

Three of the four families are not allele frequencies, and this adapter's output column is an
allele count.

- **Cytokine rows are diploid genotypes.** All 4,517 are genotype-level (`AIF-1/ -932 CC`,
  `-932 CT`); none are gene-presence. `ac = round(af * 2n)` is a category error on every one, and
  recovering an allele count needs Hardy-Weinberg — an assumption about the population, not a
  parsing detail, and exactly the silent substitution the invariants forbid. **Refused.**
- **KIR is mostly gene presence/absence.** 3,790 of 6,714 rows have `allele == gene` (`2DL1`,
  `2DL1`), reporting the fraction of individuals *carrying* a copy-number-variable gene: a carrier
  frequency over individuals, not an allele frequency over chromosomes. **Refused.** The 2,924
  allele-level rows (`3DL1*007`) are kept under `kir:`.
- **MIC is the same measurement type as HLA** and is kept under `mic:`.

## The refusal report got substantially more honest

Family refusals run *before* the parsing refusals, so:

```
  refused  25157  below_min_populations
  refused   7014  ascertainment_not_stated
  refused   4517  cytokine_genotype_not_allele_frequency
  refused   3790  kir_gene_presence_not_allele_frequency
  refused   1791  no_frequency_reported     <- was 10,031
  refused    851  population_not_in_registry
```

**`no_frequency_reported` drops from 10,031 to 1,791.** Those 8,240 rows were never missing a
frequency; they were the wrong data type, being reported as though AFND had failed to publish a
number. That is the kind of misreporting that makes a refusal list useless as a diagnostic.

Retained rows are unchanged at 80,382 of 123,502, and the arithmetic is still exact:
80,382 + 25,157 + 7,014 + 4,517 + 3,790 + 1,791 + 851 = 123,502.

## Interface change

`variant_id(gene, allele, group)` — `group` is **required**, not defaulted. A default would put the
burden of remembering the family on every caller and silently mislabel the ones that forget, which
is the bug this signature exists to prevent. An unrecognised group raises rather than guessing,
because a new AFND family needs a namespace *and* a decision about whether it is an allele
frequency at all.

`VARIANT_ID_PATTERN` gains `kir|mic|cyt`; `contract/` refrozen (one line). `cyt:` is reserved
rather than used, since those rows are refused at ingest.

## Artifact immutability

Unaffected. The store holds only `chr11-5227002-T-A__v1__map-2026-08` and
`phenotype__g6pd-deficiency__v1__map-2026-08`, so no published id anyone could have cited is
renamed. Had an HLA surface been published this would have needed a migration note instead.

## Left for #133

KIR carrier frequencies and cytokine genotypes are real measurements with real geography; they
simply cannot share a column with an allele count. Whether they get a second measurement type, a
separate store, or an HWE-derived value with its assumption attached is a decision, not a patch.

## Verification

`pytest`: **348 passed, 0 failed**, including 4 new tests — one per namespace, one for the
unknown-family refusal, and one each for the cytokine and KIR-presence refusals. `ruff check .`,
`scripts/freeze_contract.py --check`, `scripts/check_module_size.py`,
`scripts/check_private_files.py` and `scripts/smoke.py` all pass.

## What an expert should check

- That `allele == gene` is the right test for KIR gene-presence rows. It matches all 3,790 rows
  that look like presence data in this release, but if AFND ever writes a presence row differently
  the test would miss it.
- Whether refusing the whole `cyt` family is too blunt. Some cytokine loci may be reported as
  alleles rather than genotypes somewhere in the corpus; I found none, but I checked by pattern
  rather than exhaustively.
