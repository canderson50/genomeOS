## TL;DR

I added rules four days ago that made it look like you have to run a literature search before you can contribute a paper. You do not, and you never did. Papers often arrive because a colleague mentions one or an expert already knows it, and those are perfectly good — sometimes better than a search. This removes that false requirement from four places, while keeping the genuine rules about whether the numbers are correct.

---

Removes a barrier **I introduced four days ago in #239**, after @bschilder pushed back on it: *"i dont want to introduce any artificial barriers for people contributing data and papers. if it's essential for reproducibility or some other fundamental reason, we can have rules about that. but not if it's arbitrary."*

## What was wrong

Four places I wrote said, in effect, run a search first:

| file | text |
|---|---|
| curation doc | heading: *"Discovery is one existing tool, and it is not optional"* |
| curation doc | workflow: *"a review blocker, not a style choice"* |
| `CONTRIBUTING.md` | *"do not write your own fetcher"* |
| PR template | a checkbox a contributor who never searched cannot tick |

**Nothing in the system requires a search.** The evidence ledger has no search or manifest column — a record needs a citation, a locator and a source URL. A paper always could enter without one. I wrote a precondition that the architecture never had.

## The corpus proves the point

Of the LCT slice's three queries, two are `Enattah[Author]` and `Bersaglieri[Author]`. You only write those if you already know whose paper you want — they are retrievals of papers already chosen, not discovery. **Both included papers came from those two.** The one genuine discovery query included nothing.

So the papers arrived because someone knew them, and the manifest documents a search performed around a conclusion already reached. Which also deflates #272: the truncated query is the one that contributed zero records.

## What changes

The curation doc now leads with how a paper may arrive, and why a missed paper cannot invalidate a transcribed record — these are measurements each checkable against their own source, not pooled estimates where exclusions move the answer. Selection bias here is controlled by the per-observation ascertainment fields that have no defaults, not by proving a search was exhaustive.

The tool mandate is **kept but scoped to searching**. It is about the quality of a search you chose to run, not a gate on contributing. The workflow marks its first two steps as describing a search, with an explicit skip for everything else. The PR template asks how the source reached you rather than assuming.

## Kept, for a narrower reason

Commit the raw payload **if you searched** — not as provenance ceremony, but because a silently truncated fetch is indistinguishable from a complete one without it. That is how a capture missing 33 candidates sat merged for a week.

## What survives unchanged

Every rule about whether a number is true: never invent a coordinate, citation, reviewer or count; locators must point at the real table; derived counts must recompute; licence checks bind. None of those care how a paper arrived.
