## Discovery and screening are separate versions

Discovery runs through the documented tool rather than a bespoke fetcher:

```
python scripts/fetch_pubmed_manifest.py \
    --corpus-id hbb-rs334-salih-2010 \
    --query "<exact query>" \
    --executed-at 2026-09-09T04:23:22Z \
    --manifest-version hbb-rs334-salih-2010@2026-09-09.1 \
    --out <path>
```

Every candidate begins `pending`. Screening is a later, immutable manifest version over exactly those rows (design §5.1), committed as `searches.tsv`; the 13 exclusion reasons are data in that revision rather than verdicts in code. Two tests bind this: one re-derives each query's rows from the committed payload through `build_manifest` and asserts they equal the committed snapshot, and one asserts the screening revision describes exactly the snapshot it revises (same `search_id` and `candidate_id` set, same query and `executed_at`, decisions and version advanced).

One provenance note, stated plainly: these payloads were captured on 2026-09-09 with a direct NCBI ESearch call, before this workflow was applied to the slice, and `PROVENANCE.json` says that rather than implying the tool produced the original capture. No live re-fetch has been run since, so the screened candidate set is the one that was reviewed. A later query is a new manifest version, never an edit to a past screening decision.

## The builder

`scripts/build_hbb_salih_fixture.py` does only the part with no existing implementation: the deterministic transcription and derivation of the 2 records and 38 field rows.

```
python scripts/build_hbb_salih_fixture.py \
    --out tests/fixtures/literature/hbb-rs334-salih-2010 \
    --extracted-at 2026-09-09T04:23:22Z
```

`--out` and `--extracted-at` are required arguments, in the shape of `fetch_pubmed_manifest.py` and the sibling builders. The wall clock is never read, so a rebuild is reproducible and cannot mint a new version silently. The field rows are driven off `TRACKED_FIELDS` (with a check that the mapping covers it exactly once each), and the docstring cites the design sections. `test_builder_replay_reproduces_the_committed_ledgers` runs the builder and diffs its output against the committed files, which normalises line endings because a Windows checkout with `core.autocrlf` shows these files as CRLF while the committed blobs are LF.

Single corpus, not generalised. #150, #151 and #182 are queued, but there is no shared abstraction here yet.

## The design that gets there

The honest split is between what can be deterministic and what cannot. PubMed is a live, growing corpus, so re-running a search will never be byte-for-byte reproducible — that is inherent, not a bug to fix. So stop trying to reproduce the *search* and start replaying it.

**1. Commit the raw ESearch payloads as fixtures.** They are already being written, just to [a personal directory](https://github.com/manpreetbola/genomeOS/blob/e4d13cbb384c6e07c3e7121c8bd7aedc987453ce/scripts/build_hbb_salih_fixture.py#L41-L45). Put them under the corpus fixture directory instead and track them. This is strictly better provenance than either this script today or #156: the actual source responses become auditable.

**2. Replay by default, fetch only on an explicit flag.** `--payloads <dir>` reads the committed JSON; `--refresh` is what hits NCBI. The network call becomes opt-in, so nobody reruns the builder and silently gets a different manifest.

**3. Pin both timestamps.** `executed_at` should come from the committed payload's own capture metadata, not [the wall clock](https://github.com/manpreetbola/genomeOS/blob/e4d13cbb384c6e07c3e7121c8bd7aedc987453ce/scripts/build_hbb_salih_fixture.py#L232-L236), because `make_search_id` hashes it. `EXTRACTED_AT` likewise ([line 38](https://github.com/manpreetbola/genomeOS/blob/e4d13cbb384c6e07c3e7121c8bd7aedc987453ce/scripts/build_hbb_salih_fixture.py#L36-L40)). Once those are fixed the whole build is deterministic.

**4. Then assert it in CI.** A test that runs the builder in replay mode and diffs its output against the committed TSVs. That is the payoff: it converts "reproducible builder" from a docstring claim into a proof, and it is what makes the script worth committing at all.

**5. `argparse` for every path**, matching `build_registry.py` and `build_observations.py`, and a design-section citation in the docstring. Item 5 also dissolves the personal-path problem on its own.

**6. Drive the 19 field rows off `TRACKED_FIELDS`.** [Line 141](https://github.com/manpreetbola/genomeOS/blob/e4d13cbb384c6e07c3e7121c8bd7aedc987453ce/scripts/build_hbb_salih_fixture.py#L139-L143) already claims that order; importing the constant and iterating it makes the claim true by construction and clears one of the two `F401`s.
