## Body

## TL;DR

The calibration campaign now runs five independent cases at once while one coordinator remains solely responsible for the evidence database. On a repeated 32-case A100 benchmark, this completed 2.010× as many cases per hour and cut GPU cost per case by 50.2%. `--workers 1` remains available when the original serial behavior is required.

Finished worker results are saved before publication. If the coordinator restarts, it publishes the exact saved result instead of repeating that scientific stage.

## What changed

- Split each calibration stage into preparation, scientific execution, and publication without changing the scientific call.
- Added long-lived spawned worker processes; workers never open SQLite.
- Added a durable, checksummed publication spool written before database publication.
- Added recovery for exact packets returned by a previous process owner, while start-only process loss remains permanently non-redeliverable.
- Stops new stage admission after a worker or publication failure, drains already-running workers, and preserves every returned packet.
- Caps inherited BLAS/OpenMP thread pools before numerical libraries load.
- Sets the measured calibration default to five workers; choosing a higher default requires a new resource measurement.

This implements Atlas design §§5 and 7–8 and closes #337. It changes no priors, sampler configuration, case identities, seeds, reduction gates, serving interfaces, or scientific artifact schemas.

## Performance evidence

The exploratory 16-case matrix measured 1–4 workers twice. Four workers reached 1.947× the serial throughput and reduced cost per case by 49%, but did not pass the predeclared 2× gate.

All repetitions produced identical case and terminal-stage classifications. Independent GPU sampling processes did not produce byte-identical raw posterior arrays, including two serial processes with the same seed and environment. The report states this explicitly and does not represent those raw bytes as equivalent. Deterministic scheduler fixtures still require exact completion and reduction bytes.

The full evidence note is `docs/research/b0h-scheduler-optimization-2026-09-21.md`. Compact public JSON reports accompany it; private posterior and reference artifacts remain outside Git.
