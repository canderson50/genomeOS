## Summary

Until the exact (f64) detail tier arrives, hover and the inspector used to show only "Loading cell values…". They now show the cell's mean and SD from the render tier already in memory, marked as approximate. When the detail tier lands, they switch to exactly today's output.

Closes #444.

## Behaviour

- **While loading:**
  - the visible text reads `≈12.34%`;
  - an accessible note says the value is approximate and the exact value is loading;
  - the 95% interval and the nearest-observation distance, which only the detail tier has, read "Loading…".
- **Once loaded:** today's exact output, with no marker.
- **If the detail tier fails or stalls:**
  - the provisional values stay up, alongside the existing "Cell values unavailable" message and retry;
  - the rows only the detail tier has read "Unavailable", because "Loading…" would no longer be true.
- **Support semantics are respected.** Wherever the exact view hides a number for a support code, the provisional view hides it too.

## How exact and provisional stay apart

- Exact numbers still come only from `cellAt`.
- Provisional values are their own type, `ProvisionalCellValues`, keyed by a module-private brand. They have their own formatter, which always adds the marker. The type system therefore stops a provisional value from being rendered as an exact one.

## Precision

Measured over all 30 published surfaces (77,844 cells each, mean and SD), formatted the way the site does it:
- **77 of 4,670,640 readouts differ** from the f64 value, each by one unit in the last digit (0.01 percentage points).
- The issue originally said only one value differs. The corrected figure is posted on #444 and recorded in spec §B.2, which this PR amends with a dated note.
