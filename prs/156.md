## Scientific objective

Closes #159. Implements the literature-evidence design (docs/superpowers/specs/2026-09-05-literature-evidence-design.md) §§5.1-5.3, 6, and 8-10: a real, small, predeclared corpus slice — 12 rs4988235 (LCT/MCM6 -13910 C>T) population measurements transcribed from the ORIGINAL paper's genotype counts (Enattah et al. 2007 Am J Hum Genet 81:615, PMID 17701907), staged under the frozen literature contracts.

Why genotype counts: our pilot corpus (manpreetbola/protective-alleles-gnomad-v4) was transcribed from compiled frequency tables (Liebert 2017 Supp Table 3), which print allele frequencies, not counts. Frequencies cannot promote as exact counts. Enattah 2007 Table 3 prints N and CC/CT/TT genotype counts, which yield exact T-13910 counts via the allowlisted derivation `allele_count_from_genotypes`. Comparing our compiled-table values against the original genotype counts for all 34 pilot rows citing this paper: 24 match exactly, 9 were corrected upstream (pilot repo v3, commit 31eda87), 1 (French) is internally inconsistent in the source and left for adjudication.

Thanks for putting together this LCT corpus slice. The allele-count reconstruction is directionally solid, and I appreciate that the records remain pending rather than being prematurely promoted. I found several issues that need to be corrected before this can merge:

1. **The submitted search manifest does not validate.** Running `validate_search_manifest()` on `searches.tsv` raises `ValueError: search_id disagrees with database, query, and executed_at` for all three unique search IDs. Please regenerate them with the project's deterministic search-ID helper. The new test currently loads only `evidence.tsv` and `field_evidence.tsv`; please extend it to validate `searches.tsv`, `populations.tsv`, and `aliases.tsv` as well. This is why CI is green despite the contract failure.

2. **All genotype-count locators reference the wrong table.** The CC/CT/TT counts are in Table 3 of Enattah et al. 2007, not Table 2. This affects `record_locator`, the field-evidence locators, the audit, and the test comment. Since `source_record_id` incorporates `record_locator`, correcting `table:2` to `table:3` also requires regenerating all 12 record IDs and updating their child field-evidence rows.

3. **The population radii cannot be stored as valid registry geography while they remain proposals.** `populations.tsv` supplies radii such as 120, 200, 250, and 450 km, while its provenance and the audit explicitly say these are proposals requiring registry review. `uncertainty_radius_km` has no fallback or provisional default under the project contract. Please either provide exact, immutable, location-specific provenance plus a reviewed derivation for each radius, or remove these candidates from the schema-valid P0 fixture and retain them only as unresolved audit material. The `ancestral` location classification likewise needs evidence.

4. **The citation text contains an incorrect author.** It says `Enattah NS, Trivedi M, et al.` throughout, but the second author is Aimee Trudeau. Please correct the citation text and its field-evidence rows using the PMID metadata.

5. **Please verify the extraction-method classification.** `structured_table` is reserved for deterministic import from machine-readable content. The PR describes the values as transcribed, identifies an agent as extractor, and includes no deterministic importer. If these are agent-produced records that have not been checked by a human extractor, the immutable origin should be `automated_proposal` even though verification remains `pending`. If a deterministic structured import was used, please document and test that path.

Two additional items need resolution:

- The test currently pins `reuse_status=restricted` from a generic article copyright notice. Our adopted policy is to treat extracted factual data as reusable unless terms specifically restrict the proposed factual-data reuse. If no such restriction was found, use `no_restriction_found` and record exactly where the terms check was performed; otherwise cite the specific restriction.
- Please connect this PR to a dedicated, triaged issue. #149 is closed and described LCT scientific curation as separately reviewable follow-up work; this PR currently has no linked issue, labels, milestone, or project item.
