## What this changes, and why

Two Atlas browser tests on `main` failed intermittently in CI (#430). Neither was a test race. Each was hiding a real product bug.

**1. "genomeOS Dark" wasn't set as the wordmark** (`site.spec.ts`, "visible project names use the wordmark typography")

- The basemap picker printed catalog labels in a plain `<strong>`. "genomeOS Dark" is the default basemap, so the plain text showed in four places: the trigger, the detail title, the "genomeOS" group heading and the option. The dataset info tip also printed a plain "genomeOS".
- The test caught it only when React had mounted the controls before the scan, which is why it passed in some runs and failed in others.
- **Fix:**
  - A new `BrandText.tsx` wraps each "genomeOS" in catalog text in `<span class="brand-name">`. The picker uses it everywhere, and aria-labels keep plain text.
  - The provider-colour rule is scoped to `> div > span`, so the title's wordmark keeps the title colour.
  - The audit now waits for `data-atlas-ready` before scanning.

**2. The phone legend strip slid up 4 px after the Atlas said it was ready** (`atlas-mobile.spec.ts`, "the legend strip keeps its row … during a cold reveal", `Received 4`)

- Per-frame recording on all three phone profiles found the cause. `ContextOverlay` added the "Natural Earth (public domain)" credit only after the deferred Natural Earth fetch and parse, 1.5–2.2 s after `data-atlas-ready`. That wrapped the credit text to two lines (30.69 → 34.69 px), so `--atlas-credit-height` grew by 4 px and the docked strip moved.
- **Fix:**
  - The credit is added when the overlay is constructed, before the first frame. It is removed only if the load falls back before the context is parsed, so it stays only where it did before.
  - The test now records the legend row in the frame `data-atlas-ready` flips, via a MutationObserver init script. A late credit therefore fails every run instead of some.

No retries were added, no timeout was raised and no assertion was loosened.

## What I verified, and what I did not

**Verified:**
- Both root causes, with failing-node ancestor paths and a per-frame timeline of the credit block, the CSS variable and the legend.
- The new tests fail on the unfixed product and pass on the fix.
- An independent reviewer re-ran the stress suites and approved.

**Not verified / known trade-offs (reviewer's minor findings):**
- The Natural Earth credit now shows from scene construction, about 1–2 s before the borders are drawn.
- If the Natural Earth fetch itself fails (offline, 404), the credit is removed about 1 s after ready. On phones that moves the strip down 4 px on that failure path. No e2e test covers the overlay fallback. Reserving the credit block's height would remove the shift on both paths, so that is a possible follow-up.
- The new picker e2e test pins exactly 4 wordmarks. Adding a second "genomeOS" basemap will need that count updated.
- Run vitest and `npm run build:e2e` one after the other, not at the same time: some vitest test that runs a build writes into `dist/`.
