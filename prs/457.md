## Body

## Summary

This fixes the intermittent mobile e2e failure "the Stadia credit lightbox closes from its own close button" at its product cause. The same cause also affects real users who prefer reduced motion. It is not related to GA4.

Closes #455.

## Cause

The explorer's reduced-motion block shortens every transition with `transition-duration: 0.01ms !important` on `.atlas-explorer *`. `transition-property` defaults to `all`, so that rule turns every style change on every explorer element into a CSS transition. That includes elements that declare no transition at all.

One of those changes is the scene's `z-index` lift from 0 to 5 when Cesium's credit lightbox opens (#408), which raises the lightbox above the z-index 4 controls. As a transition, the lift completes only on a later animation frame. Until then:
- the map catalog trigger in the top slot sits above the lightbox's close button;
- a reduced-motion user tapping ✕ in that window opens the catalog instead of closing the lightbox.

After the Atlas reports ready, the main thread is still busy with chunk-worker messages and Cesium promise work. On CI's software GL that holds frames off for seconds, past the test's 5 s poll.

**Evidence:**
- On the real page, after the attribute changes, `getComputedStyle(scene).zIndex` stays `"0"` and `scene.getAnimations()` shows a running `z-index` CSSTransition. It reads `5` only on the second animation frame. Without reduced motion it reads `5` at once.
- In the failing window, `elementFromPoint` at the close button's centre returns `.atlas-map-catalog__trigger`.
- CI history shows the test flaking on 31 of the last 60 `pages` runs, on all three phone sizes, starting from #423 (2026-10-10). That is before #429 (GA4), which refutes the cookie-banner hypothesis.

## Fix

Inside the reduced-motion block:

```css
:where(.atlas-explorer *), :where(.atlas-explorer *)::before, :where(.atlas-explorer *)::after {
  transition-property: none;
}
```

- Elements that declare no transition no longer get one.
- Every transition the explorer CSS declares names its properties in the shorthand, so those still apply, shortened to 0.01 ms. The `transitionend` the legend popover waits for still fires. That is why the fix doesn't set the duration to 0 instead.
