## Body

## Summary

Closes #225. The sibling defect of #160, found while reviewing it: `afnd_carriers.py` read one
sample size in three different forms, so the rules depending on it could disagree.

```
duplicated(subset=[... "n_indiv"])          raw float
n_individuals = rows["n_indiv"].round()     rounds
stable_source_record_id(..., int(n))        truncates
```

## Reproduced before fixing

#225 was filed from a line-level reading of `main` and explicitly said the collision was
inferred, not observed. It is observed now. Both tests were watched failing on the pre-fix tree.

**A fractional sample size was silently rounded.** One row claiming `n=100.5` was retained and
reported as 100 individuals, with no refusal recorded:

```
retained rows : 1
refusals      : {}
carriers      : 95 of n_individuals 100
```

**And two rows collided onto one identity.** For `carrier_fraction=0.95` with `n=100` and
`n=100.5` — the two differ as floats so the duplicate check keeps both, `int()` then collapses
them, and `unique=True` rejects the pair:

```
pandera.errors.SchemaErrors: series 'source_record_id' contains duplicate values:
0    afnd-carriers:55b5ad60c15e367a3a3fcb6a537932b8...
1    afnd-carriers:55b5ad60c15e367a3a3fcb6a537932b8...
```

That is #154's failure mode in a second adapter. Worth noting the rounding here is **worse**
than #160's truncation: `.round()` moves the invented denominator in either direction, so the
reported count depends only on the fractional part.

## The fix

Ports #160's pattern rather than inventing a second one, so the two adapters now fail the same
way for the same reason.

1. **A fractional sample size is refused, not rounded.** On the raw parsed float, before any
   cast, and before the duplicate check so the row is reported for its actual defect rather than
   as a duplicate.
2. **One canonical `n_individuals` Int64 column**, built once the safety checks pass, and the
   only form read by the duplicate check, the carrier-count reconstruction, and the identity.

`.round()` on the sample size goes away. The rounding of `carrier_fraction * n_individuals`
stays, because *that* reconstruction is genuinely fractional — a percentage of a whole cohort.

## No published identity moves

`str(np.int64(200))` is `"200"`, exactly what `str(int(200.0))` produced, so integral inputs
hash identically. Verified directly:

```
pre-fix  int(200.0)      -> afnd-carriers:bdc5659f...
post-fix np.int64(200)   -> afnd-carriers:bdc5659f...
IDENTICAL: True
```

**Nothing in the suite pinned a carrier id before this** — the existing test only asserted
`.startswith("afnd-carriers:")`. So a future change to how the sample size is carried could have
silently re-minted every `afnd-carriers` record and broken any citation of one, with no test
noticing. The new digest test closes that gap, and it is a real tripwire rather than a
tautology: I confirmed it fails when the identity input form is perturbed to `float(n)`, and
passes again when restored.

## `afnd_cytokines.py` is still not affected

Re-confirmed. It emits exactly one record per `groupby(["locus", "population"])`, so its
narrower key is unique by construction. These three are the only callers of the helper, so the
family is now consistent.

## What a reviewer should check

Whether refusing a fractional sample size outright is right for KIR presence rows, or whether
AFND ever legitimately publishes a non-integral `n` there that we would want to keep. #160 chose
