## Step 2 — the layer the parity run consumes, and the live layer

The input Step 1 could not reach is fetched by this repository's own tool rather than reconstructed:
`scripts/fetch_map_hbs.py --out <path>` writes the `Explorer:HbS_Data` WFS response
(`outputFormat=csv`, no credentials).

- Fetch windows 2026-10-07T22:08:31Z-22:08:33Z and 22:14:06Z-22:14:07Z. Both responses 402,028 bytes,
  1,287 data rows.
- **The response is not byte-stable, and the reason is one column.** GeoServer's `FID` is a
  per-request feature id (`...-6220`, `...-6728`, `...-6764` across three requests). With `FID`
  removed every request is identical: data-column SHA-256
  `3d6a4f6040c0806dbb4331745918999a220c56afa83d7befd7ca54e48c0702f1`, reproduced on all three.
  Whole-response SHA-256 varies per request and identifies nothing; a later check compares the
  data-column hash with the byte count and the row count.
- Second layer: the committed artifact the P1 path holds,
  `website/public/data/atlas/hbs-rs334.observations.json` (`map-2026-08`), 1,071 records, every id
  present in the live layer. The live layer has grown by 216 ids (1,071 to 1,287), so the comparison
  runs twice: against the immutable artifact, and against the live layer.

**Result: no collision in either layer.**

- Study identity: 0 occurrences of the identifiers in the committed artifact (1,071 records) and in
  the live layer (1,287 rows), searched over every field.
- All 41 Sudan rows in the live layer are also in the committed artifact and none is this study; they
  resolve to ten other studies — Foy 1964 (13), Vella 1966 (7), Omer 1972 (7), Lauder & Ibrahim 1970
  (3), Roberts & Lehmann 1955 (3), Saha & Patgunarajah 1981 (3), Vella 1965, Saha 1981, Samuel 1981,
  Bayoumi 1985, Nasr 2008.
- Count identity, in the layer's own units. The counts are derived, and the derivation is pinned to
  the committed artifact rather than chosen: **an = 2 x (AA + AS + SS)** with a blank `hbaa`
  recovered as `sample_size - hbas - hbss`, and **ac = hbas + 2 x hbss** with a blank `hbss` read as
  zero. That reproduces the payload's `an` and `ac` exactly on **1,071 of 1,071** records, 0
  mismatches. Deriving `an` as `2 x sample_size` is wrong for 207 of them, which is the error an
  earlier draft of this section made and which the re-check caught.
- Under that rule the comparison covers **1,185 of 1,287 live rows** (102 are not derivable). No row
  carries either pair, 448/121 or 492/98. Nearest rows, named so the refusal is checkable: at an 492,
  id 1193 Schiliro 1986 (Italy) has ac 5 and id 879 (Burkina Faso) ac 19; ac 98 belongs to id 406
  (Kenya, an 916), id 994 (Gambia, an 994) and id 1034 (India, an 1018); ac 121 belongs to id 1075
  (Belgium, an 19,150). No row has a `sample_size` of 224 at all.
- **Homonym control:** the single population-label hit is survey id 12, Adamson 1951, *Nigeria*,
  "Haematological and biochemical findings in Hausa males", present in both layers. Hausa is an
  ethnicity across Nigeria, Niger and Sudan, so a label-only match would have reported a Nigerian
  1951 survey as a duplicate of this row. The match is refused.
