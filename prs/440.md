## What this changes, and why

The site's brand audit (`site.spec.ts`, "visible project names use the wordmark typography") requires every visible "genomeOS" to be set in the Raleway wordmark (`.brand-name`). The Atlas basemap picker breaks that rule in two places:
- its closed trigger, visible on `/app/` at load, shows the default basemap **"genomeOS Dark"** in a plain `<strong>`;
- inside the picker, the "genomeOS" category heading and the gallery and detail labels are plain text too.

The audit reads the page straight after `goto`, so it fails only when the picker has rendered by then. It passed on `main`'s last run, but failed on all 3 attempts in canderson50/genomeOS#4 (`pages / e2e (shard 1/4)`), a PR that changes nothing on `/app/`. Details are in [that PR's comment](https://github.com/canderson50/genomeOS/pull/4#issuecomment-6114581269).

`withWordmark(text)` wraps each "genomeOS" in a catalog label in `<span class="brand-name">`, the markup `ExplorerHeading`, `ExplorerControls` and `AtlasDataCredit` already use. It's applied to the trigger's basemap and terrain labels, the detail label, the category heading and the gallery buttons. Accessible names (`aria-label`) and the catalog data are unchanged.
