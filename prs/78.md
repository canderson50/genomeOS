Pushed an update adding three things:

**"Check the issues before you start — open *and* closed"** — the tracker is the project's record of what was done and decided, not just a queue. Closed-as-*completed* means the work exists (read it, don't redo it, and its approach is probably the house pattern); closed-as-*not planned* means it was considered and rejected, so reopening needs an argument in the issue rather than a PR. And if a task has no issue at all, that is itself a signal — either a genuine gap worth filing, or out of scope.

**"Filing work"** — bugs and feature requests go in as issues, and features get triaged before implementation. The rationale matters for an agent: priority here is derived from the dependency graph, so an unrequested feature PR displaces critical-path work *even when the idea is good*. Points at the deferred P6–P12 list so scope gets checked first.

**The PR requirement is now explicit and unconditional** — every change, including docs and config, goes through a pull request. Also documents that the close *reason* drives the board automation (`completed` → Done, `not planned` → Not planned, reopened → In progress), so issues need closing with the right reason for the board to stay truthful.

`AGENTS.md` is now 180 lines. The equivalent guidance for human contributors went into the README's Contributing section on #77.
