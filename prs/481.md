## TL;DR

This adds the two cost and access controls the owner decided on in #480. It is code, tests and docs only. **Nothing is deployed yet, so the owner's 150% decision is not in force.** This session's permission policy blocked the IAM changes, and the publisher's role needs the owner's approval first. The exact commands for the owner are below.

1. **Budget kill switch.** At 150% of the $200 monthly budget, a Cloud Run function removes public access from the data-store bucket (`genomeos-atlas-data`). The bucket stays private until the owner turns access back on. The web bucket keeps serving and is refused by name.
2. **Upload-only publisher.** A new service account, `data-store-publisher`, can create new objects and read what is there, but cannot overwrite or delete anything. Routine publishing impersonates it, and the runbook in `docs/data-store.md` now does this.

**An adversarial review found seven problems. All seven are confirmed, and code and doc fixes are in `8f4c860` and `8d582b3`** (details under *Review response*). In short: the switch now acts only on its own budget's messages; a misconfigured switch is loud on every message; its role is now exactly the two calls it makes; both scripts report who else can act as their accounts; and the docs no longer overclaim.

**Three decisions for the owner:**

1. **Approve the publisher's read role, `dataStoreReader`** (exactly `storage.objects.get` and `storage.objects.list`). Earlier this was `dataStoreLister`, list only. `roles/storage.objectCreator` alone cannot upload with `gcloud storage cp`: before each upload to a new key, cp lists the key as a prefix (traced below). The added `get` means publishing still works after the switch removes the public grant. The alternative is objectCreator only, with direct JSON-API uploads replacing `gcloud storage cp` in `publish_data_store.py`.
2. **Decide on the default compute account's `roles/editor`.** It can act as both new accounts, create keys for them, redeploy the function and publish to the topic. Function builds also run as it. See `docs/cost-controls.md` → *Project-wide access*. Options: remove Editor and pass a dedicated `--build-service-account`, or accept it.
3. **Set up the failure alert** (a console step, recipe in `docs/cost-controls.md` → *Alerting on failures*). Nothing alerts on a failure yet.

**Stacked on #474.** The base is `data/store-on-gcs`, because the publish script, the data-store runbook and the committed bucket constant exist only there. When #474 merges and its branch is deleted, GitHub retargets this PR to `main`. If #474 is squash-merged, rebase this branch with `git rebase --onto origin/main 33bd3ca`.

## What this changes, and why

The public data store has no cap on egress. Before this PR, routine uploads also ran as the project Owner.

- **`deploy/budget-kill-switch/`.** `kill_switch.py` is pure and has no Google imports. It first checks its own settings: with no `TARGET_BUCKET`, with the web bucket as target, or with no `BUDGET_ID`, it refuses every message (CRITICAL), below the threshold too. It acts only on messages whose `budgetId` attribute equals `BUDGET_ID`; anything else is logged as `malformed`. It parses `costAmount` and `budgetAmount` as exact `Decimal`s. `alertThresholdExceeded` is logged but never trusted. It trips at `cost >= 1.5 × budget`. On a trip, it strips every `allUsers` and `allAuthenticatedUsers` member from every binding and keeps every other member and condition. It writes the policy back against the etag it read and retries on a conflict. It is idempotent, never touches objects, and writes one structured JSON log line with a `decision` and a `severity`. Malformed messages and I/O failures are logged and acknowledged, never raised. `main.py` is the thin `functions-framework` wrapper. `requirements.txt` pins `functions-framework==3.10.2` and `google-cloud-storage==3.15.1`.
- **`scripts/provision_budget_kill_switch.py`.** Idempotent, with `--dry-run`. It enables only the missing APIs and creates the custom role `budgetKillSwitch` with exactly `storage.buckets.getIamPolicy` and `setIamPolicy`, the only two calls `main.py` makes (a test ties them together). It creates the service account `budget-kill-switch` and binds the role on the data-store bucket only. It refuses an extra role on the bucket or any project-wide role. It reports who else can act as the account. It creates the topic `budget-notifications`. It finds the project's budget *before* deploying. It deploys the function: gen2, python312, `TARGET_BUCKET` set to the committed bucket, `BUDGET_ID` set to the budget's id (read at run time, never committed), internal-only ingress, max 1 instance, no `--retry`. It redeploys only on source-digest or setting drift, `BUDGET_ID` included. The function runs and is triggered as the same account, which gets `run.invoker` on its own service. Finally it attaches the topic to the budget and verifies that the amount, thresholds, filter, default recipients and channels are unchanged. A budget that already sends elsewhere is refused.
- **`scripts/provision_data_store_publisher.py`.** It creates `data-store-publisher` with objectCreator and `dataStoreReader` on the bucket only. It grants the maintainer `--account` `iam.serviceAccountTokenCreator` on that one account. `--account` now accepts `group:`, `user:` and `serviceAccount:` prefixes; before, a group was granted as a `user:`. It never creates a key.
- **`scripts/gcp_identity.py`.** The shared idempotent steps: APIs, service account, custom role, policy member. `check_project_iam` refuses a project-wide role for the account, as before. It also reads every project-wide role's permissions and reports each principal that can act as the account or mint credentials for it (`actAs`, `serviceAccountKeys.create`, `getAccessToken`, `signBlob`, `signJwt`, `implicitDelegation`). Owners and Google-managed service agents get a `note:`, anyone else a `warning:`, and neither is fatal.
- **`scripts/atlas_web_gcloud.py`.** gcloud's `NOT_FOUND:` status, which IAM and Pub/Sub print, now counts as absent. Before, a missing service account was a hard error.
- **Tests.** `tests/fake_gcloud_platform.py` is a new half of the fake gcloud, now also describing predefined roles. `fake_gcloud.py` hands unknown commands to it, with exact flag sets, and it honours `.gcloudignore`. The fake also logs the impersonation variable. New suites: `test_budget_kill_switch.py`, `test_provision_budget_kill_switch.py` and `test_provision_data_store_publisher.py`. New cases in `test_publish_data_store.py` (every call carries the impersonated identity) and `test_atlas_web_gcloud.py`.
- **Docs.** `docs/cost-controls.md` is new. It covers: the budget; the thresholds; who gets the emails; what the switch does and does not cap; the project-wide access the owner has to decide on; alerting, and its gaps; the exact re-enable runbook; testing, with cleanup; and the weekly spend email through a BigQuery billing export and a scheduled Looker Studio delivery. `docs/data-store.md` gets the impersonated publish runbook. `AGENTS.md` and `CONTRIBUTING.md` link to the new doc.
