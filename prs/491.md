## Body

## What this does, in plain words

Every artifact published from now on carries a copy of the exact observation table its fit was
trained on, saved next to the surface and pinned by its sha256 in the artifact's manifest. A
surface can only be checked against the rows it was fitted to, and an input that lives anywhere
else can be lost.

That is what happened in #45. The 2026-09-16 HbS parity run recorded the sha256 of its 994 input
surveys, but no copy of the rows survived. A month later they had to be rebuilt from a fresh MAP
export, and the hash was the only proof the rebuild matched. With this change a run's input is
published with its output, under the same immutable release, so it cannot go missing again.

This is step 1 of "inputs travel with outputs".

## How it works

- **The fit keeps its input.** `fit_surface` keeps the schema-validated frame it fitted on
  (`SurfaceFit.observations`), and `save_fit` writes it into the cache as fit format 3. Formats 1
  and 2 still load, with `observations=None` instead of a guessed table, so an older fit is
  recognised and refused later. `save_fit` refuses a fit that has no table.
- **Publishing writes that frame, not a reload.** `publish_artifacts.py` writes
  `observations.parquet` beside `cells.parquet` (`genomeos/surfaces/fit_input.py`). It holds exactly
  the rows the fit consumed, in their order, as integer counts and never frequencies, under the
  strict frozen contract for the artifact's `measurement`. The bytes are deterministic in the
  locked environment. An
  `allele_frequency` artifact uses `contract/observations.schema.json` (`ac` out of `an`). A
  `carrier_frequency` (KIR) artifact is published as what it is,
  `contract/carrier_observations.schema.json` (`carriers` out of `n_individuals`, #133).
  `as_binomial` is a pure rename, so the rows are still exactly the fit's.
- **The manifest pins it.** `manifest.json` records the file's `sha256`, `bytes`, `row_count`
  (equal to `n_observations`), `measurement`, `columns` and the contract with its
  `schema_sha256`. It is written last, and an overwrite drops the old manifest first.

### Layout

```
data/store/artifacts/<variant>__<model>__<data>/
  cells.parquet          the citable per-cell surface (inferred)
  observations.parquet   the exact observation table its fit consumed (measured, #45)
  manifest.json          what was published, under what assumptions, with the input's hash; written last
```

Observations and surfaces stay in separate files with separate provenance. Nothing is inferred on
the serving path.

### The hard-error rule

Nothing is skipped and nothing is exempt by default.

- `publish_artifacts.py` checks every fit's input before writing the first directory, so a refusal
  never leaves a run half published. It refuses:
  - a fit cached before format 3, because what it consumed is unknown (refit it);
  - flags that supply rows other than the fit's own;
  - a fit with an observation footprint, because it also consumed support points that the table
    does not describe.
- `build_data_release.py` refuses an artifact that has no `observations.parquet`, or whose
  recorded hash, size, row count, columns or measurement do not match the file and the artifact.
  It also checks the file itself:
  - its counts must be its measurement's own columns, with an integer type;
  - it may carry no other measurement's counts and no column named like a frequency;
  - its `schema_sha256` must be listed in `CONTRACT_REVISIONS` (`genomeos/publication/artifact_inputs.py`).
- A released artifact directory may not gain a file. A released artifact is cited and immutable.

## Released artifacts with no preserved input, and why

The 61 artifacts released on 2026-10-17 were published before this rule existed. Because a
released artifact cannot change, they cannot gain the file. Each one is named, with its reason, in
`RELEASED_WITHOUT_INPUT` in `scripts/build_data_release.py`:

| Artifacts | Count | Why there is no input |
|---|---:|---|
| HbS `chr11-5227002-T-A` v1–v3 (`map-2026-08`) | 3 | Their fits read MAP HbS survey rows (the manifest records 1,071), and the data store does not hold that export. The 994 rows under `validation/hbs-piel-parity-2026-09-16/` belong to the 2026-09-16 parity run, not to these artifacts. |
| G6PD deficiency v1, v3 (`map-2026-08`) | 2 | Their fits read MAP G6PD survey rows from a raw MAP export the data store does not hold. |
| HLA (40) and cytokine (8) loci v2, v3 (`afnd-2026-08`) | 48 | Their fits read allele counts from the AFND frequency harvest, a raw harvest the data store does not hold. |
| KIR genes v2, v3 (`afnd-2026-08`) | 8 | Their fits read KIR carrier counts from the same AFND harvest. |

The table is kept from growing or hiding anything:

- A released artifact missing from the table fails the build.
- An entry that no earlier release holds is refused, so the table can never admit a new artifact.
- An entry that an earlier release holds *with* its input is refused, so a later release can
  never quietly drop an input.

`docs/data-store.md` gains the new file in the layout and durability table, plus a section on the
rule.

## Review follow-ups

Eight fixes from two rounds of review, each with a test:

- **The release gate refuses a column outside the input's contract**, a non-integer `bytes` and a non-hex `sha256`, so a surface's `post_mean` in the observation table no longer passes (`b2632bb3`).
- **A format-3 fit cache still loads after a contract revision**: `load_fit` requires only a non-empty table with integer `ac` and `an`, while `save_fit` and `serialize_observations` keep the strict check (`a16d8f83`).
- **The Atlas export refuses reloaded rows that differ from the artifact's pinned input**, in the new pure module `genomeos/publication/web_inputs.py`, and its served manifest drops `observations.path` (`9864376d`).
- **`observations.parquet` is tagged with its data source alone** (`map` or `afnd`, never `worldpop`) in design §5 and `docs/data-store.md` (`06546a7a`).
- **The release gate refuses an empty input**, and its docstring now says it checks the record and the parquet footer, not row values, which `serialize_observations` and `read_observations` check (`13100178`).
- **An input's columns are checked against the contract revision its record cites**: `REVISION_COLUMNS` maps each `CONTRACT_REVISIONS` digest to its columns, replacing the per-measurement `INPUT_COLUMNS`, so a column-changing revision cannot fail inputs released before it (`71063163`).
- **A format-3 cache whose `ac` is a float is refused by a test**, which covers `load_fit`'s dtype check: removing it used to pass every test (`6051b1cc`).
- **`publish_artifacts.py` says a cache was written under an earlier contract revision** and must be refit or migrated, instead of blaming the row flags, when its table's columns differ from the current contract (`3513f1f3`).

## Left for follow-ups

- Backfill the 61 `RELEASED_WITHOUT_INPUT` artifacts. Recover each input (refit inputs and the raw
  MAP/AFND harvests, data store phase 2) and publish it under a new key, as a `validation/` record
  or as a refit under a new `model_version`. Never add a file to a released directory. Drop an
  entry from the table only when its artifact is superseded.
- Make the P4 catalog builder (`genomeos/artifacts/build.py`, `VariantEntry.observations`) read
  each artifact's own `observations.parquet` instead of reloading the source files through
  adapters. `export_atlas_web.py` now checks its reloaded rows against that table (see Review
  follow-ups), but still reloads them, because only the adapters join each row to its citation
  and study label.
- Wire the input record into the planned refit pipeline. Its `inputs_hash` and `served.json` could
  cite the observations sha256, and the qc "Inputs" checks can read the artifact's table directly.
- File an issue for the nullable `Float64` truncation in `OBSERVATIONS_SCHEMA`. This PR's
  `serialize_observations` already refuses a fractional count in any float dtype, but the schema
  itself still truncates a pandas `Float64` count.
- Decide whether publishing should refuse fits that used footprint support until the support is
  also recorded.
- On the database question: every input is now a fixed-contract parquet at a fixed key in the
  public bucket, so it can be queried in place without copying, for example as a BigQuery
  external/BigLake table, or with DuckDB over HTTPS.
