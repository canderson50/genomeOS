## What this changes, and why

After #412, CI pytest ran on 4 xdist workers but still took 22–40 min. It also hit an intermittent SIGABRT in `test_build_scripts.py::test_build_observations_promotes_and_retains_literature`. Both had real causes:

1. **The SIGABRT: a pyarrow buffer released during interpreter shutdown.**
   - **Cause.** `write_observations` called `DataFrame.to_parquet(partition_cols=[...])`, which goes through Arrow's async dataset writer. That writer can release the last NumPy-backed buffer on an Arrow worker thread *after* the call returns. When the script then exits under CPU load:
     1. that thread asks for the GIL during interpreter shutdown;
     2. CPython 3.12 calls `pthread_exit`;
     3. glibc force-unwinds the thread through a noexcept destructor;
     4. the result is `std::terminate`: "terminate called without an active exception", exit -6.
   - **Evidence.** The abort was reproduced on Linux (CPython 3.12.15, glibc 2.36, CI's library versions) and captured in a core-dump backtrace. macOS cannot abort this way.
   - **Fix.** Write each `chrom` partition synchronously with `pq.write_table`, using one schema inferred from the whole frame. Directory names, schemas and reads (DuckDB partition pruning and `read_observations`) are identical. Only the file name changes, from `<uuid>-0.parquet` to `part-0.parquet`. `to_parquet(..., use_threads=False)` does *not* fix it: 30/30 aborts in the reproducer.
   - **Linux under stress:** old code 3/600 aborts; fixed code 0/900. Deterministic reproducer: old 50/50, fixed 0/50.
   - **Regression test.** A new test refuses `write_dataset`, and it fails on the old code. A layout test pins the on-disk shape.
2. **The 893 s test: OpenBLAS oversubscription.**
   - **Cause.** JAX's CPU Cholesky and triangular solves call scipy's OpenBLAS on Linux. Its thread pool spin-waits on each of the many tiny calls in an inducing-point fit. Four workers each running a full pool on a 4-vCPU runner thrash. That made `test_surface_fit.py::test_the_inducing_approximation_fits_and_predicts[h3]` take 893 s on CI, and `test_surface_fit.py` set the whole job's critical path.
   - **Fix.** Cap BLAS/OpenMP at one thread per worker in the CI Test step only, using the repo's existing `NUMERICAL_THREAD_CAPS` set. In local OpenBLAS measurements under 4-way contention, capped runs took about 76 s against more than 1,470 s uncapped.
3. **One shared cross-validation fixture.** Two crossval tests ran the identical seeded 3-fold run; they now share one module-scoped fixture.
4. **Slowest-test report.** `--durations=40` stays in CI so regressions are visible.

No scientific parameter changed: draws, tune, `n_inducing`, folds and seeds are all as before.
