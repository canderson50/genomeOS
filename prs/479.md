## TL;DR

**What it does:** Adds the design for an automated refit pipeline. This PR is the design only; no code yet. When reviewed data for a dataset merges, the pipeline:
1. refits the affected surfaces on free GitHub-hosted runners;
2. computes QC statistics;
3. builds a report with **old-vs-new maps**;
4. asks the code owner who approved the triggering PR to review it.

**Only that person's approval publishes.** The exact bytes they reviewed go to the public data store, then the Atlas and the API serve them.

**Why it matters:** Today every step from refit to upload is manual: version labels are typed by hand, diagnostics are thrown away, there is no old-vs-new comparison, and uploads are run by hand. The owner asked for "as automated as possible, while still ensuring quality checks", with "the final upload … up to them after reviewing the report".

**Status:** Design for the owner's approval. After approval, the next step is an implementation plan. Build order:
- **Phase 0:** merge #474 and #475, and publish the AFND and WorldPop inputs (#472).
- **Phase 1:** local refit and report.
- **Phase 2:** CI refit to a review PR, piloted on HLA-A\*02:01.
- **Phase 3:** automated promotion and the API reading the new release.
- **Phase 4:** rs334.

## Decided by the owner

- Automated QC statistics, a new-vs-old map report, and a notification to whoever approved the trigger PR. The final upload happens only after they review.
- Candidates may be visible in a public PR before approval. Nothing reaches a bucket, the Atlas or the API before approval.
- Pilot on an AFND allele first, then rs334.
