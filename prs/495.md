## What this changes, and why

[#198](https://github.com/genomeOS/genomeOS/issues/198) found that a freshly fitted `SurfaceFit` and its clean-process reload disagreed in every latent and surface value (~5e-8). Its [follow-up comment](https://github.com/genomeOS/genomeOS/issues/198#issuecomment-5606556750) identified the mechanism: live JAX float64 posterior arrays came back as float32 on reload. `save_fit` has materialized them as NumPy since [#203](https://github.com/genomeOS/genomeOS/pull/203) (`b30244f`).

What was still missing is the issue's acceptance: *"define/test the cache replay guarantee… Test fresh/reloaded and repeated/reordered calls separately."* The only clean-process test on main covers `predict_new_cohort_parameters`. The surface round-trip test runs in one process, which #198 showed cannot see the drift.

`tests/test_surface_fit_replay.py` adds three tests, one guarantee each, with bitwise equality and no tolerance:
1. **Fresh versus reloaded:** `predict_draws`, `predict` and `predict_observation` from a fresh fit equal those from a clean-process reload. The subprocess runs from the repository root, so it imports the tree under test.
2. **Dtypes survive:** every posterior variable has the same dtype after the clean reload as live (float64 for the continuous parameters).
3. **Repeated and reordered calls** on one object give identical draws.

**Scientific contract**
1. *Claim:* a persisted fit predicts bit for bit what the fresh fit did, in the pinned environment, so figures and rollups made from a cache are the fit's numbers.
2. *Output and acceptance evidence:* the three tests pass on `main` and fail on the commit before #203. See the table below.
3. *Component:* tests only. No change to `save_fit`, `load_fit`, the cache format or any model.
4. *Assumptions and consumers:* the guarantee is for the pinned `requirements.lock` environment. Historical caches written before #203 are not repaired and still differ, as the issue says they should stay; published artifacts are unaffected. Consumers are anything that loads a cached fit (`plot_surface.py`, `publish_artifacts.py`, national rollups).

**The tests discriminate.** The same test file, run on the commit before #203 (`33aa2e1`) and on `main` (`e1706b4`):

| Test | Before #203 | `main` |
|---|---|---|
| fresh vs clean reload, bitwise | **fails**: 6,400/6,400 latent values differ, max 5.35e-8 | passes |
| dtypes after clean reload | **fails**: float32 instead of float64 | passes |
| repeated/reordered calls | passes | passes |

That matches #198's record: 6,400/6,400 differing, max 5.5e-8, repeated calls already identical.

**#198's own two-process reproduction on `main`:** latent 0/6,400 differ, surface 0/18, survey 0/16; reloaded posteriors are NumPy float64. Environment: Python 3.12.3, Linux x86_64, PyMC 6.3.2, PyTensor 3.3.2, JAX/jaxlib 0.11.2, NumPyro 0.22.0, NumPy 2.4.6 (`scripts/env_report.py`). The issue's original record was macOS arm64 with older versions.
