## Body

## TL;DR

Some source files literally contain words such as “Unknown.” This PR keeps those words exactly as the source wrote them and shows a warning so a human can decide what they mean. A required field that is null, empty, or only spaces still stops the build.

## Why this is needed

Text that looks like missing data is not always safe to delete or reject automatically. In the downloaded AFND population table, `Unknown` occurs 534 times in `urban_rural` and 16 times in `ethnic_origin`; `Not Known` occurs 1,443 times in `family`. Those are real source values in controlled-vocabulary columns. They do not prove that the metadata is complete, but they do prove that the literal text must remain available for review.

No committed input currently contains the exact phrase `not reported` in a field changed by this PR. That phrase and the other spellings are defensive checks for future imports.

| Input to required free text | Behavior after this PR |
|---|---|
| null, `""`, `" "`, or `"\t"` | validation fails |
| `NA`, `N/A`, `unknown`, `none`, `null`, `-`, `tbd`, or `not reported` | value is preserved and validation emits a human-review warning |
| `NAT2`, `Nancy`, `not_reported`, or ordinary source text | value is preserved without this warning |

Matching is case-insensitive and applies to the complete trimmed value, so a real identifier that merely contains one of these strings is unaffected.

## Implementation

Required free-text fields now use two registered Pandera checks:

- `non_blank_text` is blocking and requires at least one non-whitespace character.
- `meaningful_text` is advisory. It emits `SchemaWarning` for a placeholder-like literal and keeps the original value.

The pair is exported as `REVIEWABLE_TEXT`. The checks are registered so the frozen JSON contracts record both behaviors, including `raise_warning: true`; the schema diff is the reviewable public contract.

The literature-evidence validator previously performed a second blanket rejection after its schema warning. That duplicate rejection is removed, and optional search decision text now uses the same warning policy. Exact identifiers, stable source locators, structured states, recomputable derivations, count bounds, and field-evidence consistency remain hard validation rules.

`population_aliases.label` remains a verbatim source field with the same preserve-and-warn behavior. The synthetic `NA` alias test demonstrates that behavior; it is not evidence that HGDP has a real population named `NA`.

## Design

Implements design §12 and the publication-evidence safeguards: preserve source evidence, reject absent required content, and expose ambiguous text for human review instead of silently converting it into missingness or silently treating it as trustworthy metadata.
