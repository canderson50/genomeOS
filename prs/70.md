## Body

Closes the board setup.

**The automation exists because the built-in workflow can't do it.** GitHub's "Item closed" project workflow sets one Status value, so it cannot tell an issue closed as *completed* from one closed as *not planned*. This reads `state_reason` and routes to `Done` / `Not planned`, and routes reopens to `In progress`.

It reads the project item off the issue's own `projectItems` connection rather than paginating the project — simpler and no page-size ceiling.

**Repository variables are already set** (`PROJECT_ID`, `STATUS_FIELD_ID`, and the three option ids). Two things I can't do for you:

1. `gh secret set PROJECT_TOKEN -R bschilder/genomeOS` — a PAT with `project` scope. The ambient `GITHUB_TOKEN` cannot write to user-owned Projects v2, and I'm not going to write a personal token into your repo secrets on your behalf. The workflow no-ops safely until this exists.
2. **Board sort:** *Group by* `Status`, *Sort by* `Priority` ascending. Projects v2 view configuration isn't writable through the API, so it's a one-time UI step.

`docs/board-conventions.md` documents the label families, the priority semantics (derived from the dependency graph — "what breaks if this is late", not "what would be nice"), and why milestones map to release boundaries instead of to P0–P5.
