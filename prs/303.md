## TL;DR

We publish a diagnostic picture that argues a particular modelling shortcut is wrong. The only test
guarding it checked that a picture file appeared and was bigger than 10 kB.

That would still pass if the two maps were swapped, if latitude and longitude were exchanged so the
map showed nowhere real, or if a colour scale ran backwards so the eye read the figure inside out.
All three produce a perfectly valid image and a different argument.

This replaces the file-size check with seven assertions about what each panel actually draws. I then
broke the code five different ways to confirm the tests notice.

The published figure is unchanged, byte for byte.

---

## Why a size check is not a test

Review figures in this project are held to the same invariants as the product. Measured observations
and inferred model geometry must never read as one layer. Absent data must be visible rather than
blank. A colour ramp must read low-to-high without its legend, because a reversed ramp inverts a
map's meaning for anyone who only glances at it.

None of that was enforced. It was verified once, by a person looking at the image, which does not
survive the next edit.

## What is asserted now

| Assertion | The error it catches |
|---|---|
| Each map panel is bound to the quantity it claims to show | The two panels swapped — same cells, same region, opposite story |
| Every scatter plots longitude against latitude | A coordinate swap, which still draws a map, just not of anywhere real |
| The mechanism panel plots error against distance, not the reverse | An axis swap that inverts the panel's entire claim |
| The distance ramp reads low-to-high | A reversed ramp, so near reads as far |
| The error ramp keeps its dark-is-worse convention | The same, in the opposite direction, which is deliberate here |
| Measured sites stay visually separable from model locations | Two layers collapsing into one, which the design forbids |
| The false-support overlay marks exactly the cells crossing the threshold | The figure's headline count drifting from the computed one |

## Verified by mutation, not by reading

A test that has never failed has not been shown to work. Each mutation was applied to the production
code, the suite run, and the code restored:

| Mutation | Result |
|---|---|
| Swap the two panel arrays | fails `..._bound_to_the_quantity_it_claims_to_show` |
| Swap latitude and longitude in a scatter | fails `..._plots_longitude_against_latitude` |
| Reverse the distance colormap | fails `..._reads_low_to_high_without_its_legend` |
| Swap the mechanism panel's axes | fails `..._plots_error_against_distance_not_the_reverse` |
| Make the two point layers identical | fails `..._stay_visually_separable...` |

Each fails exactly one test and no others, and the suite is green once restored.

## The one production change

`render` built the figure, saved it and closed it. A closed figure can only be checked by looking at
the picture, so it is split: `build_figure` returns the figure and the values it was drawn from, and
a thin `render` saves it. That split is what makes any of the above assertable.

**The split is behaviour-preserving and I checked rather than assumed.** Regenerating
`docs/figures/prior_normalization.png` from the committed command produces a byte-identical file,
sha256 `b2b00b93…`.

## A small correction while here

A comment described the reference marker as sitting at the regional centre. It sits at a fixed
interior point of 5 N, 20 E; the centroid would be 5 N, 24 E. Any fixed interior point makes the
same argument, so the marker stays put and the comment now says what is true — moving it would mean
regenerating a published figure to shift a marker four degrees east.
