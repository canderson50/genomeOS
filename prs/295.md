## Body

## TL;DR

Some of the data genomeOS wants to use is free for research but not for commercial use. Until now
our only option was to refuse it outright, which cost us real evidence for no good reason. This
change lets us publish that data on one condition: every piece of it is labelled, so that if
genomeOS ever grows a commercial side, one command tells us exactly what has to come out.

```bash
python scripts/check_commercial_use.py --list
```

**No restricted data is added here.** This is the labelling machinery and the rules around it.

---

## What this changes, and why

Reviewing #207 I told the contributor to drop AlphaGenome's `top_attributions`, because DeepMind
defines the AVI Score Feature Breakdown as separate from the AVI Score and licenses it for
non-commercial use only. That was the only thing the repository could express at the time: a
blanket refusal.

The ruling is that non-commercial data **may** be included, provided it is marked clearly enough in
the code and in issues and pull requests that a future commercial component can extract all of it at
once. This builds that.

### The restrictions are field-level, not source-level

This is the design decision everything else follows from:

| Source | Permissive part | Restricted part |
|---|---|---|
| AlphaGenome | AVI Score (explicit commercial carve-out) | AVI Score Feature Breakdown |
| gnomAD | the CC0 callset | bundled SpliceAI annotations (CC BY-NC) |

A licence tag on a whole source would be wrong in both directions. It would over-claim the
restricted half or condemn the permissive half — and a commercial build wants to drop one
AlphaGenome field while keeping the score it is entitled to use.

### What a contributor writes

Each external resource in the publish allowlist carries a `commercial_use` block. Two fields always
(`finding`, `restricted_fields`), and three more whenever a check was actually performed
(`checked_at`, `terms_url`, `recorded_in`). The findings are the same vocabulary the literature
reuse checks already use, so a source's terms read the same wherever they are recorded.

### The tripwire

`KNOWN_NON_COMMERCIAL_FIELDS` in `scripts/export_atlas_web.py` refuses a payload carrying a
known-restricted field unless the declaration names it. This is what the blanket refusal became:
**restricted data may ship marked, and may never ship unmarked.** Deleting the refusal outright
would have let the breakdown re-enter the payload silently, which is the failure the original gate
existed to prevent.

### `not_checked` stays publishable, deliberately

Refusing it would leave a contributor choosing between abandoning the data and inventing a licence
finding to make the build pass. Inventing a reuse check is exactly what the publication-evidence
safeguards in `AGENTS.md` forbid. Unchecked sources are reported by the gate as unresolved instead —
for an extraction, "we never read these terms" is as actionable as "we know this is restricted."

This is not hypothetical: it is why gnomAD and dbSNP are marked `not_checked` here rather than
transcribed from memory. Issue #3 records gnomAD as CC0, but with no date, and I am not in a
position to be the verifier of a check I did not perform. #294 tracks resolving both.

### For humans, not only the build

- a `NON-COMMERCIAL:` comment at every code site, so `grep -rn "NON-COMMERCIAL:"` finds them all
- a new `licence:non-commercial` label
- a line in the pull-request template asking whether a data PR adds non-commercial data
- `docs/non-commercial-data.md` as the register, and a rewritten AlphaGenome audit note

## What I verified, and what I did not

**Verified.** Every gate above, run locally. The regenerated `catalog.json` is byte-identical to the
committed one apart from the added marking — checked by parsing both, stripping `commercial_use`,
and comparing. The browser typecheck caught three TypeScript fixtures missing the new required
field, which is the contract doing its job.

**Not verified: whether publishing the AlphaGenome feature breakdown is something we should actually
do.** This PR makes it *possible and traceable*; it does not do it. The acquisition-path question in
#246 — whether the committed AVI value came from the permissive download or a read of the Atlas
interface — is unresolved and is the real gate on adding the breakdown, not the licence.

**Not verified: the gnomAD and dbSNP commercial terms.** Deliberately. See above and #294.

**Not verified by me: the licence reading itself.** The AlphaGenome terms quoted in
`docs/audits/alphagenome-avi-licensing.md` were read on 2026-09-10 and I have relied on that record
rather than re-reading them. An expert or a lawyer should confirm that "genomeOS publishes the
breakdown as a non-commercial open atlas" is within the grant before any payload carries it.
