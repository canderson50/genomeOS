## What this changes, and why

`genomeos.surfaces.persistence` owns `save_fit` and `load_fit`, but it could not be imported on its own (#199):

```
$ PYTHONPATH=. python -c 'from genomeos.surfaces.persistence import load_fit'
ImportError: cannot import name 'FIT_FORMAT' from partially initialized module
'genomeos.surfaces.persistence' (most likely due to a circular import)
```

**Why it failed:**
- `persistence.py` imported `genomeos.surfaces.fit` at module level, to get `SurfaceFit` and `FitConfig`.
- `fit.py`'s last lines re-export from `persistence`.
- So importing `persistence` first started `fit`, which asked `persistence` for `FIT_FORMAT` before it existed.
- The supported seam, `from genomeos.surfaces.fit import load_fit`, only worked because it happened to import in the other order.

**The fix, confined to `genomeos/surfaces/persistence.py`:**
- `FitConfig` is imported from `genomeos.surfaces.config`, where it is defined. `fit.FitConfig` is the same object.
- `SurfaceFit` is imported under `TYPE_CHECKING` for the annotations.
- `load_fit` also checks and builds a `SurfaceFit` at runtime, so it imports the class inside the function. By the time it is called, both modules are fully initialised.

Nothing else changes: no model, prior, convergence criterion, source data, serving behaviour, cache format (`FIT_FORMAT` stays 2), or re-export. `fit.load_fit`, `fit.save_fit` and `fit.FIT_FORMAT` are still the same objects as the `persistence` ones. Loading is unchanged: trusted-owner caches only, and no new pickle path.
