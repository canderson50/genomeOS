## Body

## What this changes, and why

One line of dependency policy: `jax` and `jaxlib` are now bounded in the `surfaces` extra, the same way `pymc`, `arviz` and `numpyro` already are, and for the same stated reason. Seven added lines in `pyproject.toml`, nothing else.

**The failure it fixes.** `tests/test_surface_fit.py::test_the_inducing_approximation_fits_and_predicts[kmeans]` fails in CI on every branch opened since 2026-10-19:

```
genomeos.surfaces.fit.ConvergenceError: sampler did not converge
(r_hat 1.224 > 1.05; effective sample size 13 < 200)
```

The last green run on main (2026-10-18, PR #489) resolved **jax 0.11.2**. Every failing run since resolves **jax 0.12.0** or **0.12.0.1**, with `numpyro 0.22.0`, `pymc 6.3.2` and `arviz 1.3.0` identical across both. The same failure reports the **same `r_hat 1.224` and the same effective sample size of 13** on four unrelated PRs, which is not what a race or a timeout looks like, and no re-run clears it.

**Why a bound rather than a test change.** `pyproject.toml` already says the upper bounds are deliberate rather than defensive, and gives the reason: an unbounded surface dependency is how two contributors end up disagreeing about what the code does while both being right about their own environment. That is what happened here, through the one dependency in the extra that had no bound.

**Compatibility.** `numpyro 0.22.0` requires only `jax>=0.7.0` and `jaxlib>=0.7.0`, so the bound resolves cleanly. `jaxlib` is bounded alongside `jax` so the resolver cannot half-upgrade the pair.

**What this unblocks.** Four open PRs were red on this one test, including [#498](https://github.com/genomeOS/genomeOS/pull/498). The diagnosis with the full run table is [#499](https://github.com/genomeOS/genomeOS/issues/499).

**What this does not claim.** It does not explain *what changed* in JAX 0.12, and it does not make the kmeans variant converge on 0.12. Pinning restores the last known-good environment; understanding the change is a separate piece of work that #499 describes and that this PR deliberately leaves open.

## What the CI run on this branch showed

The job went from failing on `test_the_inducing_approximation_fits_and_predicts[kmeans]` to passing it, and then failing a different test:

```
1 failed, 7196 passed, 52 skipped, 4 warnings in 701.59s (0:11:41)
FAILED tests/test_surface_fit.py::test_new_observation_parameters_survive_save_load_exactly - AssertionError
```

This branch resolved **jax 0.11.2 and jaxlib 0.11.2**, the same pair that was green on main in [PR #489](https://github.com/genomeOS/genomeOS/pull/489). So the pin does what it claims for the kmeans variant, and this second failure is not explained by the version: on the same jax version the whole suite passed on 2026-10-18, and in this run it did not.

Two differences are visible and neither is proven. The run took 11m41s against 24m55s for the green run, which suggests a different worker distribution under `pytest-xdist`, and the failing test asserts exact equality after a pickle round trip, which is the kind of assertion that can depend on which tests share a worker. I cannot re-run the job (no admin rights on the repository), so I cannot say whether it is intermittent.

That changes what this PR is. It is still the correct dependency policy, and it does remove the kmeans failure that has been red on every branch since 2026-10-19. It is not a promise of a green suite, and the second failure needs its own look.
