## What this changes, and why

Every PR waited about an hour in CI. Two serial steps dominated (measured on #408):

- Pages `validate`, 'Run browser and accessibility contracts': **58.7 min**. That is 252 Playwright tests on 1 worker.
- CI `test`, 'Test': **49.0 min**. That is about 6,500 pytest tests in one process with coverage.

This PR parallelises both without changing what is tested.

- **Playwright runs as a 4-shard matrix job, `e2e (shard N/4)`.**
  - It runs alongside `validate`, and `build`/deploy now need `validate` and all four shards. Sharding is test-level (`--fully-parallel --shard=N/4`), with 1 worker per shard as before, `fail-fast: false`, and traces uploaded per shard on failure.
  - Project-only describes are now tagged and filtered at collection instead of skipped at runtime, so the shards are balanced: 65/65/65/65, which together are exactly the 260 tests that ran before.
- **pytest runs with `pytest-xdist -n auto --dist loadfile`.**
  - `pytest-xdist==3.8.0` (and `execnet==2.1.2`) is the only change to `requirements.lock`.
  - Results and coverage are identical to the serial run, so the coverage badge check is unaffected.
  - One test flaked only under parallel load: a 50 ms subprocess timeout raced interpreter start-up. It now has 1 s of headroom, and its assertion is unchanged.
- **Local opt-in parallelism.** `PLAYWRIGHT_WORKERS` (default 1) and `PLAYWRIGHT_PORT` (default 4322) let local runs parallelise and avoid port clashes. CI defaults are unchanged.
- **Guard test.** `website/tests/pages-workflow.test.ts` fails if the e2e job's setup drifts from `validate`'s, if the shard list doesn't match the total, or if `build` stops needing every shard.
