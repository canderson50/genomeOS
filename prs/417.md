## Body

## What this changes, and why

On genome-os.org, a single transient failure while a Cesium web worker imports a module showed Cesium's raw dialog. It read: "An error occurred while rendering. Rendering has stopped. TypeError: Failed to fetch dynamically imported module …/cesium/Workers/createPolygonGeometry.js". The globe then stayed dead until a manual reload.

### Root cause

- The app never handled render-loop errors, so Cesium's defaults applied: it showed its panel and stopped the loop permanently.
- Cesium's geometry workers are module-level: they are created once per page and keep a failed import. An in-place retry therefore cannot recover; only a reload does.
- Reproduced 100% by aborting only the first request for `createPolygonGeometry.js`.

### Fix

- **Render loop.** The Viewer now runs with `showRenderLoopErrors: false` and `useDefaultRenderLoop: false`. A small owned loop (`scene/render-loop.ts`) runs `viewer.resize(); viewer.render();` each animation frame inside one try/catch. That catch also receives Cesium's `scene.renderError`, so every frame error, inside or outside Cesium's guarded passes, is reported once, logged, and stops rendering.
- **Recovery.** The explorer shows its existing failure panel (role=alert): "The globe stopped rendering. A network or graphics error caused this. Retry reloads the explorer with your current view. No scientific data was changed." Retry reloads the page; state lives in the URL. WebGL failures keep their in-place retry and the Browser requirements link.
- **Readiness flag.** `data-atlas-ready` reads `true` only when no scene failure is showing.
- **Reduced motion.** The reduced-motion preference is now read before the first scene build. Previously, users with OS reduce-motion got the globe built twice on load, including the 3 MB Natural Earth file downloaded twice.
- **Spec.** Cesium globe design §12 gains a "Render loop throws" row.

The custom loop preserves Cesium's behaviour, verified in Cesium's source by the re-review. `Scene.render` still decides whether to draw (`requestRenderMode`), so idle frames don't redraw. The clock still ticks, resize behaves as before, and there are no double loops across retries.
