## What this is

A design document only. **No implementation**, no schema, no code. Written after a brainstorm on 2026-09-10 so the decisions are captured while fresh, and posted for review before any plan is written.

## Why

Review of #207 surfaced that the four AFND cytokine loci are genuinely single-nucleotide changes but carry composite identifiers like `cyt:il-6-174-c`, so they cannot hold coordinate-keyed external annotations. The corpus holds **60 such loci and publishes 4**, so this is not a one-off.

## Decisions taken, and what each rules out

| Decision | Alternative rejected |
|---|---|
| Normalized identity sits **alongside** the existing `variant_id` | Replacing it would re-mint 4 published artifact identities and every cytokine `source_record_id` — for convenience, not correctness |
| Lives in a **reviewed registry keyed by `variant_id`**, mirroring P0 | Columns on `OBSERVATIONS_SCHEMA` would be a frozen-contract change every adapter must satisfy, repeating one mapping across ~89,000 rows |
| Resolution is **tooling plus agentic review**, PR as the review gate | Fully automated resolution; or blocking on manual entry |

## Two things worth your attention

**A check I proposed and you rejected, correctly.** I suggested validating a mapping by comparing AFND's allele frequency to a reference population's. Beyond varying by population and dataset, it has **no discriminating power near 0.5**, because a strand flip returns roughly the same number — blindest at exactly the alleles most likely to be mislabelled. The spec records this as rejected with the reason, so it does not get re-proposed. The evidence that settles the naming step is a citation, not a statistic.

**A flaw in my own central check, found in self-review.** The round-trip test — complement the printed alleles under the recorded strand, and they must equal reference and alternate — **cannot detect a strand error for palindromic alleles**, because complementing `A/T` or `G/C` returns the same set. `IL-6 -174 G>C` is such a case, so this is not hypothetical for the very first batch. Palindromic rows now require separate `strand_evidence` and fail the build without it.

## Your addition, which changed the schema

Recording the cases where the tools find nothing. An unresolvable locus becomes an `unresolved` row with its reason and what was attempted, not an absent one. That stops the same dead end being re-investigated, keeps coverage honest across three distinct states rather than one undifferentiated absence, and makes the pattern of what fails visible. Expected to be the common path for the obscure loci.

## Dependency

Blocked on #242 for whether an agent-resolved row may be agent-verified. Rows land as `pending` until that is decided, so **the verification policy, not this spec, determines when the cytokines actually become eligible**. Worth knowing before this looks like it unblocks #207.

My review of #207 asked for a coordinate-shape check in the exporter. This design replaces that with a registry lookup — one source of truth instead of a regex duplicated in Python and TypeScript. If this is approved I will update that review so the contributor does not build the weaker version.
