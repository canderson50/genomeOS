## Body

## TL;DR

Pull requests that change only website code, docs prose, docs figures or the contributor guides no longer run the 17–50 minute Python `test` job. Anything the Python job actually reads still runs it. The rule comes from a trace of every file the full pytest suite and the gate scripts open. Over the last 40 merged PRs, 13 would have skipped, saving 27 `test` runs (660 runner-minutes, median 24 min each). None of those 13 touched a file the job reads, and all 27 of their `test` runs had passed. Two checks that read every tracked file now run on every PR in a new cheap job, so website PRs keep that coverage. Pushes to `main` are unfiltered.

## What this changes, and why

The `test` job ran on every PR. Docs-only PRs #424, #401 and #403 each ran it for 24–52 minutes, and so did every website-only PR. Skipping it is only safe for paths nothing in the job reads, and "website/**" is not such a path. Python tests compare byte-identical fixture copies under `website/tests/fixtures/atlas/`. They read the catalog and the borders binary under `website/public/data/atlas/`, and `check_commercial_use.py` reads `website/src/atlas/public-artifacts.json`.

Only `.github/workflows/ci.yml` changes, in three parts:

**1. A `changes` job** diffs the PR's merge commit against its base (`git diff --name-only --no-renames HEAD^1 HEAD`, no third-party action). Without rename detection, a file moved out of a read path counts on both sides. The `test` job is skipped only when every changed path meets both conditions below.

- **It matches no must-run pattern.** Each of these was found to be read by the job:

  | Pattern | Read by |
  |---|---|
  | `*.py` `*.pyi` `*.ipynb` `*pyproject.toml` `*ruff.toml` (anywhere) | `ruff check .` lints every Python file and reads every ruff config, even under `website/` |
  | `website/public/data/atlas/*` | `check_commercial_use.py`, `test_check_commercial_use`, `test_encode_natural_earth_borders`, `test_export_atlas_web` |
  | `website/public/_static/coverage.svg` | the "Coverage badge is current" step |
  | `website/src/atlas/public-artifacts.json` | `check_commercial_use.py`, `test_check_commercial_use`, `test_export_atlas_web` |
  | `website/tests/fixtures/atlas/*` | `test_atlas_web_fixtures`, `test_build_atlas_parity_subset`, `test_build_atlas_e2e_fixture` (139 files traced) |
  | `docs/literature-evidence-curation.md` | `test_literature_evidence_schema` |

- **It matches a skippable pattern.** Nothing in the job reads these except the two whole-tree scans below:

  | Pattern | Why it is in |
  |---|---|
  | `website/*` | read only through the carve-outs above |
  | `docs/*.md`, `docs/*.png` | prose and figures. Data files under `docs/` stay out, because tests read three of them: a TSV, a JSON and a JSON.gz. |
  | `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`, `.github/PULL_REQUEST_TEMPLATE.md` | not read |
  | `.github/workflows/pages.yml`, `.github/workflows/project-status.yml` | not read. `pages.yml` validates itself. |

- **Everything else runs, by default.** That includes `README.md`, which the coverage-badge step rewrites (it needs exactly one badge) and the container build copies. It also includes `LICENSE` (pyproject `license-files`), `.gitignore` (ruff honours it), `.env.example`, `Dockerfile`, `data/`, `contract/`, `deploy/`, `demo/`, `reference/`, `requirements.lock`, `docker.yml`, `ci.yml`, and any new file under `.github/`, such as a composite action. `docker.yml` is unread, but I kept it in the run set because it is coupled to this workflow through `workflow_run`.

**2. A `tracked-files` job** runs on every event. Two checks in the Python job read every tracked file, so any PR can fail them, website and docs PRs included:

- `scripts/check_private_files.py`. Its own comments cite a `website/src/components/home/` false positive from #454.
- `test_web_layout.py::test_no_concrete_bucket_url_is_tracked`, which runs `git grep` over the tree for a hard-coded bucket URL.

They need only the standard library and pytest. pytest is installed with `--constraint requirements.lock`, which pins exactly pytest 8.4.2, iniconfig 2.3.0, packaging 26.3, pluggy 1.6.0 and Pygments 2.21.0. The bucket test runs with `--noconftest`, because `tests/conftest.py` imports SQLAlchemy and the test does not use it. The test job still runs both checks, unchanged.

**3. The `test` job** gets `needs: changes` and `if: ${{ !cancelled() && needs.changes.outputs.python != 'false' }}`:

- **It fails safe.** If `changes` fails or answers anything but `false`, the tests run.
- **A skip still reports a status**, which a required check counts as passing. A workflow-level `paths:` filter would instead leave a required check waiting forever.
- **Pushes to `main` always answer `run`.** The coverage badge and `docker.yml`, which fires on `workflow_run` of `ci` on `main`, depend on that run.

Actions are pinned like the rest of `ci.yml`: `actions/checkout@v4`, `actions/setup-python@v5`.

## What I verified, and what I did not

**Verified:**
- the rule against a full-suite file trace;
- the backtest over 40 merged PRs, plus the 3 motivating PRs;
- the empirical history of those PRs' `test` runs;
- the classifier against real git merge commits;
- actionlint with shellcheck;
- the gates above.

**Not verified locally:**
- **The suite on macOS is not CI's environment.** It has 2 failures, both native-tool version checks: `test_native_reference_tbi_oracle` and `test_live_native_full_and_sparse_controls`, which expect bcftools/htslib 1.23.1 where this machine has 1.21. They touch no path in this change. The local run also needed scratch package metadata for `genomeos`, because the shared venv does not install it. CI is the reference run.
- **The bash version differs.** The classifier was exercised under macOS bash 3.2, and runners use bash 5. The script avoids bash-4-only features (`mapfile`, `;&`). This PR's own CI runs it under bash 5.
- **The skip path has not run in CI.** This PR changes `ci.yml`, so its own CI must answer "run". The first website- or docs-only PR after merge is the first real skip.

**Residual risk:** the must-run list is hand-maintained. A new Python test that reads a new file under `website/` or a `docs/*.md` file must be added to `read_by_python`, and nothing enforces that yet. A follow-up could add a guard test that pins the list against the readers in `tests/` and `scripts/`, like the gap #439(b) notes for `pages.yml`. That is for the owner to decide.
