## What this does

It publishes the exact input of the 2026-09-16 HbS parity run, golden test 1, so anyone can download
it without credentials. The input is the 994 MAP surveys (385 cohorts, 11,359,130 alleles). It goes in
data-store release **2026-10-18**, under `validation/hbs-piel-parity-2026-09-16/`. canderson50 asked for
this on #45: their GPU pods see only the public repo, so a private copy is no use to them.

## What we found

- **There was never a curated CSV.** The run predates the spatial-support contract (2026-09-22,
  `4686030`) by a week. It used MAP's raw public export, filtered to the Piel 2013 subset, with radii
  derived from MAP's area class. `data/curated/map_hbs_surveys.csv` was only ever an illustrative path.
- **The run's own files are rebuilt byte for byte.** No copy survived, so both files were regenerated
  from a fresh MAP export with the `6c1b051` adapter and the locked pandas, pyarrow and numpy:
  - the parquet, `466034e2…`: the frozen "observation parquet" in the parity doc;
  - the TSV, `820d725f…`: the B1G benchmark baseline.

  `b1g_comparison.py` pins both. The rebuild was proven three times in fresh Linux containers, on
  aarch64 and amd64, each from a separate MAP export. All 994 rows also match the published v3 Atlas
  observations field for field.
- **Several columns are adapter constants, not evidence.** `radius_km` is an equal-area area-class
  radius, which the current contract refuses. The dates are 0 on every row. `sampling_design` and
  `disease_ascertainment_excluded` are source-level assertions. The research doc and the README in
  the bucket both say so. The files reproduce the 16 Sept run; they are not a contract-valid curated
  input.
- **The doc's `8694b1bc…` digest is not reproduced.** Its recipe was never recorded, and the doc now
  says so.

## ⚠️ Merge order: publish first

uploaded, every `python scripts/fetch_data.py` on `main` fails. The owner uploads from this branch's
worktree, which holds the local files: about 220 KB of new objects plus the manifest copy, while the
245 earlier keys are skipped. Then run the anonymous `fetch_data.py --verify-remote`, and only then
merge.
