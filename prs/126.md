## Body

Follow-up to #125, which merged before these corrections were pushed. Main currently carries a bound and a lock pin that are both wrong, and the second is worse than the first because a committed lock looks authoritative.

## 1. The bound was the accident, not the venv

#125 claimed a local venv had drifted to `fastapi 0.141.1` out of a declared `>=0.115,<0.120`. **That was backwards.**

`git log -L` on the line shows it was `>=0.115,<1` originally — the deliberate choice, and the right shape for a library that has stayed on 0.x for years. **#107 narrowed it to `<0.120`** while adding an unrelated Atlas read preview, with no mention of fastapi in its commit message or PR body.

So 0.141.x was legal under the project's actual intent. Nothing drifted. Restored, with the history in the comment so it is not silently narrowed again. Verified on **both** ends: the API tests pass on 0.119.1 and on 0.141.1.

## 2. `--upgrade`, not `--refresh`, is what moves a pin

#125 documented `--refresh` as the fix for a lock that pinned an older version than the index offered. That guidance is wrong, and it passed review because one experiment happened to work for the wrong reason.

Writing to an **existing** `--output-file` makes uv treat the pins already in it as *preferences*, holding versions steady to minimise churn — the same behaviour `pip-compile` has. So after restoring the wider bound:

```
uv pip compile ... --output-file requirements.lock        -> fastapi==0.119.1   (held by the old pin)
uv pip compile ... --refresh --output-file ...            -> fastapi==0.119.1   (index cache was not the problem)
uv pip compile ... --upgrade --output-file ...            -> fastapi==0.141.1   (correct)
echo 'fastapi<1' | uv pip compile -                       -> fastapi==0.141.1   (no output file, no preference)
```

`--refresh` busts uv's persistent *index* cache, which is a real but different failure mode. Here the stale value came from the output file. AGENTS.md now names `--upgrade`, explains the preference behaviour, and keeps the `--refresh` note as the separate thing it is.

## Why this matters more than a version number

A committed lock is read as authoritative. Main's currently pins `fastapi==0.119.1`, so anyone following the documented reproduction gets a version **we do not test against locally** — the exact divergence #125 set out to eliminate, reintroduced by the PR that was fixing it.
