## What this changes, and why

The privacy gate inspected **which files were tracked, not what they said about someone's machine**, so it passed a tracked file containing a hardcoded personal home directory. Verified empirically on #188's head rather than inferred: the gate reported `private-file check passed (619 tracked files)`, exit 0, with this line present.

```python
PAYLOAD_DIR = Path("C:/Users/Bola/.hermes/genomeos/hbb-rs334/payloads")
```

Two costs, and the second is the one that surprises people.

**Privacy.** A contributor's username and machine layout, committed to a public repo permanently. Not a credential, so not urgent, but exactly the class of thing this gate exists to keep out.

**Portability, silently.** `Path("C:/Users/x")` is **not absolute on POSIX** — pathlib treats `C:` as an ordinary relative segment. A `mkdir(parents=True)` on it builds a junk `./C:/Users/x` tree inside the working copy, unignored and stageable, with no error. A gate that caught the string would have caught this for free.

## Three things the tests forced

I wrote the tests first, and each of these came from a failure rather than from foresight. Worth listing because two of them contradict what I originally specified.

**`%USERPROFILE%` is not reported, and my own issue was wrong to ask for it.** It is the portable Windows spelling of a home directory, exactly analogous to `$HOME`, which we obviously allow. Flagging it would penalise the correct form. `$HOME`, `~` and `%USERPROFILE%` are all fine; a path pinned to one person is not.

**Separators may be doubled.** A Python source literal writes `"C:\\Users\\x"`, so the pattern takes `[\\/]+`. The match is reported **verbatim**, doubles included, because that is the string a reviewer greps for.

**The repo had to be fixed to pass its own gate.** `docs/superpowers/plans/2026-09-06-cesium-globe-explorer.md` recorded ten verification commands as `/Users/bschilder/code/genomeOS/.venv/bin/python`. Now `.venv/bin/python`, which is both portable and correct — an absolute interpreter path in a plan document only ever worked on one machine. This is why the change is two parts rather than one, and it is the strongest evidence the check earns its place: the gap was not hypothetical, main was already carrying it.

## Design

`personal_paths()` is a **pure function over text**, so a case can be added without a throwaway git repository, and it reports **line numbers** — a filename alone is not actionable in a 300-line file. The failure message says what to do instead rather than only what is wrong.

`PLACEHOLDER_USERS` is what keeps it usable. `runner` is GitHub Actions; `vscode`, `ubuntu`, `node` and `app` are devcontainer and base-image conventions; `<user>`, `youruser` and `username` are documentation. **A gate that fires on those gets deleted rather than satisfied**, so the comment directs contributors to add to the set rather than remove the check. The scanner and its own tests are exempt, since they must contain the shapes they detect.
