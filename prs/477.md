## TL;DR

**What it does:** The project-board workflow now reads `PROJECT_TOKEN` from a new `project-board` environment that only `main` can use. Until now it read the token as a repository secret.

**Why it matters:** Any workflow pushed to *any* branch by someone with write access could read a repository secret. This one was a classic personal access token with the `repo` scope, so it was enough to push code as its owner. After this change, a workflow on another branch can't see it.

**Status:** Safe to merge before the new token exists. Until the environment holds its own `PROJECT_TOKEN`, the jobs fall back to the repository secret, so the board keeps working throughout.

## Rollout

1. ✅ Created the `project-board` environment. Deployment branches: `main` only.
2. Merge this PR.
3. The owner creates a fine-grained token: resource owner **genomeOS**, organisation permission **Projects: Read and write**, repository `genomeOS/genomeOS` with **Issues: Read**, nothing else. Then store it: `gh secret set PROJECT_TOKEN --env project-board -R genomeOS/genomeOS`.
4. Open and close a test issue to confirm the board updates. Then delete the repository-level secret (`gh secret delete PROJECT_TOKEN -R genomeOS/genomeOS`) and revoke the old classic token.

Issue events always run on the default branch, so they satisfy the environment's `main`-only rule.
