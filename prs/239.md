## What this changes, and why

Two consecutive literature-corpus PRs, from two different contributors, reimplemented
`scripts/fetch_pubmed_manifest.py` — which is already named as step 1 of the curation workflow.
#188 wrote its own capture with wall-clock timestamps that re-mint `search_id` on every run, no
payload validation, a hardcoded personal path, and screening fused into capture. #156 shipped no
builder at all (#237). I then reviewed #188 **twice against the wrong baseline** before finding the
script myself.

Three independent readers missing the same paragraph is a discoverability failure, not a contributor
failure. So this changes the **route** to the rules, not the rules. `AGENTS.md` and the design spec
were accurate throughout and are not rewritten.

## What is added

**Two entry points that did not exist.** There was no `CONTRIBUTING.md`, no PR template, and no
issue templates; `.github/` held only `workflows/`. GitHub surfaces `CONTRIBUTING.md` and the
template exactly where `AGENTS.md` is never seen — which matters because both contributors here
work from forks and never see repo-local convention unless something points at it.

- **`CONTRIBUTING.md`** routes and nothing else: which doc for which workstream, check open *and*
  closed issues, the gate list, and a data-submission section stating the stricter bar and why
  (a wrong number is harder to detect than a broken build, and can be cited before anyone notices).
- **`.github/PULL_REQUEST_TEMPLATE.md`** carries the mandatory gates as a checklist that asks for
  **output rather than a tick**, plus a data/evidence block. #188's blocking lint failure would have
  been caught by the contributor rather than by CI.

**Three changes to the curation doc.**

- Discovery is now binding, with what the existing script already gets right spelled out: a required
  `--executed-at`, network I/O confined to one function so a committed payload replays, and payload
  validation including the `count`-vs-`idlist` check that catches a truncated or paginated response
  before it becomes a short, confident-looking manifest.
- **Committing the raw payload is now stated.** It was documented nowhere, even though
  `docs/audits/lct-rs4988235-pilot.json` already models the practice by recording its exact
  `command`.
- A subsection on **why discovery and screening are separate manifest versions**. Fusing them is
  what made #188's coverage counts ambiguous: with no fixed snapshot, "candidates found" and "papers
  excluded" are counted against nothing.
- The **coverage-totals-must-reconcile** rule moved out of §8 of the 748-line spec into the doc a
  curator actually reads, with the two failure modes actually seen: counting unique papers and
  manifest rows in one sentence, and reporting a shrinking refusal count as progress when that is
  equally consistent with having invented the missing values.

**One environment note in `AGENTS.md`.** The `.venv` is an editable install pinned to the main
checkout, so running it from a worktree can import the wrong source tree with no error. This
invalidated one "all gates pass" report today. The note includes the one-line check that settles it.

**README** now routes to `CONTRIBUTING.md` and `AGENTS.md` before writing code, and the
documentation table gains the curation guide, which was absent — a data submitter could not have
found it from the README.
