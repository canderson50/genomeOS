## TL;DR

This project caps how long a single code file may get, so that a person or an agent can read one
without loading the whole repository. A change I merged earlier today pushed the Atlas export script
past that cap — and every check stayed green, because the cap was only ever looking at one of the
two directories that hold real code.

So this does two things: moves the oversized part into its own file, and points the cap at the
directory it was ignoring.

It was #287's stricter version of the same check that caught this. Credit where due.

---

## What happened

The commercial-use marking merged in #295 took `scripts/export_atlas_web.py` from roughly 770 to
**870 logical lines**, against a hard cap of 800. Nothing failed, because the budget scanned
`genomeos/` only.

That is the actual defect. A budget that does not cover a tree is not a budget for that tree, and
`scripts/` is not a folder of thin entry points — the exporter alone enforces publication policy and
is one of the largest files in the repository.

## The fix

**The marking moves to `genomeos/publication/commercial_use.py`**, taking the exporter to 771 lines.

That module is the better home independent of size. Two consumers need the same vocabulary: the
exporter, which refuses to publish an undeclared restriction, and the check script, which turns
declarations into an extraction plan. A policy both of them enforce should not be reachable only by
importing a command-line script — which is literally what the check script was doing, reaching into
`scripts/export_atlas_web.py` for its constants.

**The budget now scans `scripts/` as well.** Nothing there is over the cap once the exporter is
split, so this passes today. 176 modules are checked where 120 were before.

| | Before | After |
|---|---|---|
| Exporter, logical lines | 870 | 771 |
| Modules checked | 120 | 176 |
| Largest file under `scripts/` after the exporter | — | 555 |

## One small thing

`check_module_size.py` gains an explicit argument list, matching `check_commercial_use.py`. A `main`
that reads the process arguments directly cannot be called from a test, because the test runner owns
those arguments — so the gate's own test could not run the gate. Same defect, same fix, now in both.
