## First: `main` is currently broken, and this fixes it

`as_binomial` was added to `afnd_carriers` while wiring `--layer kir`, but never staged — commit
`21b7708` added `plot_surface.py` and not the module it calls. So #143 merged a `main` where
**`plot_surface.py` calls `afnd_carriers.as_binomial` twice and the function does not exist**.

CI passed because **no test imports the plotting scripts**. `--layer kir` would fail at runtime
with `AttributeError` and nothing in the suite would notice. That is a real gap: `scripts/` is
entirely untested, and this is the second time today a script-level fault reached `main` (the
first being the colour-scale bug in #144, caught only by looking at a figure).

### The store now holds exactly one artifact per variant, at its latest version

```
30 artifact dirs, 30 distinct variants
variants present at more than one version: 0
```

- **20 HLA** — had v1, refit as v2, the v1 copy dropped as a duplicate.
- **8 cytokine and KIR** — new; no v1 existed.
- **2 MAP** (HbS, G6PD) — still `__v1__map-2026-08`, because **no v2 exists to supersede them**.
  They are not duplicates and are untouched.

§5's immutability guarantee is about a cited map never changing underneath anyone. Publishing as
`v2` rather than overwriting `v1` preserves that: the version number stays truthful about what
changed, and the superseded copy is simply not retained in a private store where no citation to it
can exist.

**One thing worth recording about how the older copies were selected.** The deletion was scoped by
*data_version* (`__v1__afnd-2026-08`), not by model_version. Those two rules happen to coincide
here, but only because the MAP artifacts sit on a different data_version — a blanket `*__v1__*`
would have destroyed HbS and G6PD, which back our only published validation results. The robust
rule for "keep the latest per variant" is to group by variant and drop older versions **within**
each group, never to filter on a version string.

## `measurement` on the manifest

**Required, no default.** An artifact of carrier frequencies over individuals and one of allele
frequencies over chromosomes are indistinguishable by inspection, and a consumer averaging across
both is wrong in a way nothing downstream can detect (#133).

```json
{ "variant_id": "kir:2dl1",     "measurement": "carrier_frequency" }
{ "variant_id": "hla:a-02-01",  "measurement": "allele_frequency"  }
```

An unknown value raises. `publish_artifacts.py` gains `--cytokines` and `--kir`.

`sync_store` gains `store/screen_v2`, kept separate from `store/screen` because the two were
fitted on different corpora and a fit is only interpretable against the data that produced it.
