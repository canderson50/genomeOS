## TL;DR

This adds a resumable three-step runner so the five expensive HbS held-out tests can run independently on separate GPUs without mixing inputs, changing seeds, or silently replacing failures. It records enough evidence to audit every model choice and resource cost. This PR contains code and synthetic tests only; it publishes no real HbS results and changes no production behavior.

This advances #331. It does not close the issue: the frozen real-data run and comparison with the existing non-spatial and current spatial models remain pending.

## Problem and resulting behavior

The fitted B1G model in #366 has five independent outer geographic folds, and each fold performs the fixed nine-candidate inner selection before one final held-out fit. A single long process would lose completed work when a GPU pod is interrupted and would prevent safe fold-level parallelism.

`scripts/benchmark_b1g.py` now supports three explicit modes:

1. `--initialize` freezes input hashes, configuration, ordered splits, seeds, code hashes, package versions, and the scientific qualification in a checkpoint header.
2. `--fold-index N` computes exactly one outer fold and atomically writes one immutable, integrity-hashed shard.
3. `--finalize --out ...` refuses incomplete campaigns, reloads all five shards under the frozen identity, and writes the ordinary benchmark tables plus a manifest and inventory.

Each shard retains the outer status, selected configuration, sampler diagnostics, predictions, all nine candidate scores, every inner-fold seed/status/diagnostic/failure, elapsed seconds, peak RSS, device, and query chunk size. Failed or infeasible outer folds are preserved, including legitimate failures that occur before inner-grid planning begins. Unexpected checkpoint files, partial candidate grids, bad convergence evidence, changed inputs, changed splits, and shard overwrites are refused.

## Scientific scope

- Implements design §§4–8 and §12 for offline B1G evidence preservation.
- Does not alter the registered B1G model, fixed candidate grid, nested selection metric, folds, priors, likelihood, or promotion gates.
- Enables outer-fold infrastructure parallelism only; the scientific unit remains one complete untouched outer holdout.
- Adds no environmental covariates, serving path, production artifact, or real-data result.
