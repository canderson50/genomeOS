## Body

Users can now ask the Atlas to discover, explain and display published maps through a private assistant panel. Gemini proposes a bounded operation; the server supplies grounded text from recorded metadata and validates exact publication identities before returning a map action. The browser rejects stale or unavailable actions and reports application only after the renderer acknowledges the view.

Advances #433. This is a preview stacked on #432; its comparison link uses that branch's independent map panels. It does not close #282 or #54.

## Boundaries and behavior

- Separate FastAPI application with no database imports, SQLAlchemy sessions, schema initialization or writes. GET serves admitted metadata; POST returns a read result/proposed display operation. No mutation, ingestion, arbitrary SQL/URL/code, burden, trait-correlation or pleiotropy tools.
- Server admission matches the reviewed publication allowlist, pinned dataset revision and exact artifact/model/data identities. Browser admission also matches observation/surface hashes. Support remains visible on every assistant action; comparison preserves separate measurement meanings and versions.
- Gemini 3.8 Flash uses Google Cloud ADC on the server. One bounded structured selection per turn; model prose is never returned. The model may misclassify intent, but can only select admitted views or recorded explanations. No general-purpose output channel exists.
- Every browser profile receives a random 256-bit anonymous identity in a signed, host-only HttpOnly/Secure/SameSite cookie. Chat POSTs require that cookie, a matching session-bound CSRF proof and an allowed Origin; forged/expired cookies and another browser's proof fail before Gemini. Signing keys are explicit shared runtime secrets, not defaults. No session table or shared conversation store exists.
- Conversation history is browser memory per tab only; at most four previous user questions reach the provider. Request size, time, output tokens, concurrency and per-process request budgets are bounded. Session changes clear stale local conversations; late cancelled responses cannot append. Budgets include six requests/minute per verified browser session and 12 per IP, plus the global cap. Cancel, undo, clear and versioned share links are included.
- Validated responses are atomic rather than streaming unvalidated model text. Named camera presets currently cover the world and West Africa; other regions need manual navigation.

Implements Atlas design §§4–5, 11, 13 and the bounded existing-artifact subset of §16. No new scientific artifact, fitting, ingestion or scientific claim is introduced. #54's general P4 surface/burden class policy remains separate; those tools are not exposed by this application and must not be added before that policy lands. Expert review should check measurement/denominator semantics, provenance and refusal wording, and whether the publication admission boundary is sufficient for this preview. Engineering/security review should also check cookie signing/domain separation, CSRF/Origin checks, expiry, shared signing-key deployment and browser-context isolation.

## Outstanding qualification; not deployed

The read-only GCP check found `aiplatform.googleapis.com` absent from the existing project's enabled services; repository-local ADC is also absent. Live model access, intent/refusal evaluations, quota/billing and retention remain unverified. Hosted activation needs a strong shared `ATLAS_CHAT_SESSION_SECRET`, a same-site HTTPS frontend/API deployment, anonymous gateway rate limiting/bot protection and billing caps and a dedicated model-invocation identity without database/storage-write grants. Browser sessions are anonymous browser-profile credentials, not person/account authentication; tabs share the profile ID but keep separate conversations. Cookies and CSRF are checked server-side, and a stolen cookie remains a bearer credential. Process-local budgets still need distributed gateway controls. The website honestly disables the assistant when its backend URL is unconfigured.

`Dockerfile.chat` is provided with an allowlisted build context. Its build was attempted inside and outside the sandbox but Docker denied daemon access; the image remains unverified. No cloud configuration was changed and nothing was deployed.
