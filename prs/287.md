## Body

## TL;DR

This draft takes small, preselected sections of a human genetic reference dataset and produces four tables showing how often each genetic variant appears in each population. Every planned section was processed and checked, no individual-level source data are published, and the work is now divided among six smaller pull requests (#346–#351) to make review manageable.

---

The global AF campaign lacked a reviewed path from the frozen #254 byte plan to broader, traceable reference-panel count inputs. This PR now completes that path: the software gates were independently reviewed, the controller acquired the exact generation-bound ranges for all 66 prespecified windows, and offline preparation produced four immutable technical/paper × called/quality development tracks.

The completed run retained 22/22 chromosome sources and 109/109 planned VCF ranges. Sixty-five windows contained records and `chr16-s2` was retained as an explicit no-record result; none was replaced or refused. The pipeline preserved 32,415 PASS biallelic SNPs across 80 literal populations. Each track has 2,593,200 rows, including explicit `AN=0` rows. Native bcftools cohort totals match all 32,415 variants in each cohort stage, for 64,830 variant-level AC/AN matches. Both deep terminal validators independently replayed and rehashed the retained artifacts.

The row-level acquisition, genotype, native-token, participant-linked, and count artifacts remain private and untracked. The committed research note reports only aggregate evidence and immutable manifest hashes. This is reference-panel development data: population labels describe origins rather than verified present-day residence, the 32,415 variants are not independent loci, and the result establishes no model gain, calibration, P1 eligibility, publication eligibility, or public surface. No MAP, environmental, or publisher-branded covariate enters the preparation. A map would imply geography this task has not qualified, so no geographic figure is included.

This implements Atlas §§4–8 and 12. It closes the bounded preparation issue and advances the larger benchmark-first program without closing it.

Validation:

- independent exact-source review: passed before retrieval;
- independent real-evidence audit: passed after acquisition and preparation; acquisition manifest `14b61409...6a307`, preparation manifest `78543a6f...5221`;
- current branch: 253 focused reference tests pass, including seven later mutation tests for native disagreement, exact window accounting, and completeness; full CI will rerun on the evidence commit.

Expert review should focus on the boundary between independently native-validated cohort-wide called AC/AN and replay-validated population/quality counts, the retained dependency limits, and the decision to keep resident geography and model admission outside this issue.

## TL;DR

This is careful, substantial work, and the machinery it builds is genuinely well designed. I am
asking for changes for two reasons.

First, the headline safety claim is not actually tested. The pull request says it "checks native
extraction and called allele counts independently". I deleted that comparison from the code and
**every one of the 246 focused tests still passed**. The check is real and works; nothing proves it
keeps working. The same is true of the "all 66 windows accounted for" guarantee and of the flag that
decides whether an acquisition counts as complete.

Second, at 17,042 lines across 47 files, no human can honestly review this as one unit. The commits
already describe four or five separable pieces. Splitting them is the difference between this being
reviewed and being waved through.

Nothing here is a design flaw. It is a test-coverage gap sitting under the claims that matter most.

---

## How these were found

By mutation, not by reading. For each finding below I broke the production code and ran the focused
suite. A check that nothing notices when you delete it is a check that will quietly stop working
after the next refactor.

### 1. The independent allele-count check has no test with power — critical

Replacing the comparison in `scripts/prepare_reference_window_counts.py:407-408`

```python
if native_totals[stage] != expected_total:
    raise ValueError("native_mismatch")
```

with `if False:` leaves all 246 focused reference tests passing. The equivalent comparison in the
deep replay path at `scripts/reference_count_replay.py:289-304` is equally uncovered. No test
anywhere supplies an allele count that disagrees.

The mechanism itself is genuinely independent — bcftools computing tags over the extracted binary
against a Python count over the raw text, two implementations over the same bytes. That is the right
design. But in the end-to-end tests the native totals are monkeypatched
(`tests/test_reference_window_clis.py:1011`) and the fake is hard-coded to
`AC = len(samples), AN = 2 * len(samples)` while the fake token stream emits `0/1:30:20:10,10` for
every sample. The fake was constructed to agree with the thing it is supposed to be able to
contradict. The one live-tooling test ends in an expected refusal, so it never compares a real count
either.

Worth saying that the per-call **token** comparison is properly tested — mutating
`genomeos/validation/reference_genotypes.py:499` fails three tests, and the malformed fixture
exercises a real normalization discrepancy where an out-of-range genotype quality becomes missing.
So the independence machinery demonstrably works at call level. Only the totals level is unverified.

**What would fix it:** one test where the native count disagrees with the Python count and the
window is refused. The malformed fixture already proves a real discrepancy is reachable, so this can
be driven by real tooling rather than a fake.

### 2. The 66-window accounting is unenforced by tests — high

The invariant is real and structural: both `genomeos/validation/reference_acquisition_types.py:345-348`
and `reference_preparation_types.py:370-375` require the window identifiers to equal the full
expected set exactly. I neutralised **both** and the artifact, CLI and preparation suites all still
passed. The only coverage is a happy-path length assertion. Nothing tests that a manifest with a
missing, duplicated or reordered window is refused.

### 3. `complete` is load-bearing and untested — high

`reference_acquisition_types.py:365` is the only place completeness is verified. It is never
recomputed, and because it is a plain boolean rather than a constrained literal the codec does not
catch it either. Meanwhile `scripts/reference_window_artifacts.py:704` gates the entire preparation
phase on it and both command-line tools use it as their exit status. I removed the check and no test
failed. A regression there lets a refused acquisition report success and admit preparation.

### 4. Two published evidence columns are tautologies — medium

`native_ac_an_matches` is set to the variant count and then required to equal the variant count, and
is emitted as a column in the native-controls ledger. `native_interpreted_calls` is the sample count
times the variant count. Neither is wrong — any genuine mismatch refuses the window earlier, so the
equality is necessarily true — but a reader of that ledger will take them for independently counted
verification quantities. Either derive them from something that could disagree, or rename them so
they do not read as evidence.

### 5. The only real-tooling test never runs in CI, and hard-fails off it — medium

The workflow never installs the genomics command-line tools, so the live test is always skipped.
That accounts for the skips noted in the description. The sharper problem is that the skip guard
asks only whether the tool exists, while the test then asserts an exact version string — so a
contributor with any other version gets a hard failure rather than a skip. Either install the tool
in CI or fold the version into the skip condition.

### 6. Internal faults are reported as bad user input — medium

Both command-line entry points wrap everything in a broad handler that prints a single
`error:invalid_input`, exits 2, and discards the message and traceback. Since every schema violation
in this stack raises the same exception type, a genuine invariant breach, a disk error and an
ordinary coding bug are indistinguishable to the operator. The process does fail loudly, so the
hard-errors invariant holds — but nobody can diagnose it.

### 7. The module-size budget is met at the cap, not at the target — medium

The gate passes, and I ran it. But `scripts/reference_window_io.py` sits at exactly 800 logical
lines against a gate that fails above 800, with `reference_window_artifacts.py` at 798 and
`prepare_reference_window_counts.py` at 756. The stated target is 500. Three modules one line under
a cap is a signal about decomposition, not a pass.

Minor, for completeness: the repository-local gcloud wrapper reads an executable path from the
environment, which is correctly locked down inside the acquisition tool but is live for anyone
running the wrapper directly. One record-reading path skips the symlink-component check the rest of
the module applies. A byte-exact table is parsed with a reader that applies quoting semantics,
mitigated by a later byte-for-byte comparison. Three production assertions vanish under optimised
Python, though each is already guaranteed by an adjacent check.

## What came back clean

This deserves saying, because it is most of the code and it is good:

- **No refusal override exists.** No force, skip, allow or ignore flag on either tool. Refusal state
  is derived structurally rather than set.
- **No command injection.** Every subprocess call passes a list with no shell, and every tool path is
  resolved to a real absolute file, so no argument can be mistaken for a flag.
- **Reads are bounded throughout** — output drained in pieces to disk under a hard cap, compressed
  block reads capped, manifests capped.
- **No temp-file collisions.** Both tools refuse a pre-existing output directory and create it
  exclusively, so concurrent runs cannot share a tree, and the scratch database is removed in a
  `finally`.
- **Science modules are pure.** No network or subprocess imports anywhere in the new validation
  modules; all input and output lives in `scripts/`.
- **No invented metadata.** Every defaulted lookup found is on a sparse tally where zero is
  semantically correct, never on a required field.
- **Transport and framing checks are genuinely tested** — mutating the end-of-file marker check and
  the sparse-extent comparison each fails real tests.
- **Issue linkage is honest.** The body says "advances" with no closing keyword, matching the claim
  that neither issue is closed.

## What was not reviewed

Stated plainly, because at this size a claim of completeness would be false. The 411-line spec and

## Two things the work turned up

**The comparison exists twice, and that matters for how you test it.** Once on the preparation path,
once in the deep replay that confirms a refusal reproduces. Perturbing only the first gives
`refused count failure is not reproduced` — a *different* error, which would have looked like a
passing test while proving nothing about the comparison. Both are patched in the test, so one case
covers both sites. Anyone adding a third copy should know this.

**A disagreement is a refusal, not an exception.** I first wrote the test expecting a raise. The
real contract is better: status `refused`, `complete` false, and the window carrying reason
`native_mismatch`. The test asserts the reason reaches the ledger rather than merely that something
failed.

**There is a control test, deliberately.** The same fixture, the same run, nothing perturbed, must
succeed. Without it a refusal caused by anything unrelated would look exactly like the check
working — which is a milder version of how the original gap survived.

## Why the gap survived, for the record

The end-to-end tests replace the native counter with a stand-in whose totals are derived from the
same fake genotype stream they are compared against. The two could never disagree. A fake cannot
falsify a comparison it was built from.

That is worth remembering beyond this branch: whenever a test substitutes one side of an
independence check, the check stops being independent inside that test.
