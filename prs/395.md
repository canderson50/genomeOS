## Body

## TL;DR

The exact GPU scorer was making every query in a batch do as much work as the longest query beside it. This groups similarly sized queries before scoring and restores the original order afterward. The scientific answers are unchanged, while the controlled campaign-shaped A100 benchmark fell from 315.41 seconds to 105.93 seconds (2.98× faster; 66.4% less time). One registered end-to-end activity task completed in 692.83 seconds instead of roughly 23 minutes.

Closes #394.

## Problem and resulting behavior

Exact beta-binomial CDF scoring uses a tensor whose support dimension is the longest finite tail in the current row batch. The previous fixed input order often mixed very short and very long tails, so short queries were padded to the longest query's work.

The scorer now:

1. computes each query's shorter exact-tail length on the host;
2. sorts queries by that length, with denominator as a deterministic tie-breaker;
3. runs the unchanged bounded 8-row × 256-draw × 2,048-support plan; and
4. scatters results back into the caller's original query order.

The public `CountPredictive` and `ActivityCountPredictive` interfaces, float64 finite-support algorithm, normalization, failure behavior, and memory planner are unchanged. This implements Atlas design §§7–8.

## Measured evidence

The deterministic before/after profile reused byte-identical generated inputs (`b9ccb0d8…db73da96`) on the same A100:

- warm campaign-shaped complete diagnostics: 315.409 s → 105.932 s;
- cold optimized run: 106.893 s;
- speedup: 2.98×, or 66.4% lower wall time;
- exact count quantiles, coverage flags, and seeded samples;
- every numeric diagnostic within `rtol=1e-9`, `atol=1e-11`; maximum PIT difference `1.11e-16`;
- exact million-scale CDF retained the prior `3.95e-11` absolute CPU/GPU discrepancy;
- sampled device-wide high-water increase: 849,346,560 bytes on an 85.1 GB device; the existing live-work planner remains capped at 512 MiB and adaptive to free memory.

An initial attempt to raise the row cap from 8 to 32 was stopped after 28 minutes without producing an artifact. Mixed tail lengths caused larger padded tensors and made the real task slower. The submitted scheduler addresses that measured cause without increasing the live batch limits.

The optimized public campaign adapter also completed registered activity/null task `f22b3e21…b9645476` on its first attempt with zero divergences in 692.83 seconds. The downloaded evidence archive and result artifact passed their SHA-256 and schema/identity checks.
