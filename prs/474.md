## TL;DR

genomeOS's data moves out of git and into a **public Google Cloud Storage data store**. Anyone can download it over plain HTTPS with no credentials, and every file is checked against a sha256 recorded in git.

- **What leaves git:** the 61 surface-artifact directories (254 MB) and the validation outputs (4 MB) are no longer tracked. History is **not** rewritten.
- **What stays:** git keeps a small manifest per data release, `data/releases/2026-10-17.json`. The hand-curated inputs reviewed by diff also stay in git, and are published to the store as well.
- **Fetching:** `python scripts/fetch_data.py` fetches and verifies files from the committed public URL `https://storage.googleapis.com/genomeos-atlas-data/`. The scripts that read `data/store` resolve their inputs through it.
- **Not published:** trained models exist only as pickles, so they are not published (#471).

## What this changes, and why

**Owner decisions applied after the first draft** (data store design §3, marked "Owner decision"):

1. **The public URL is committed.**
   - `DATA_STORE_BASE_URL` and `DATA_STORE_BUCKET` live in `genomeos/publication/data_release.py`, and the URL is `fetch_data.py`'s default.
   - A `GENOMEOS_DATA_BASE_URL`, `GENOMEOS_DATA_BUCKET` or `--bucket`/`--base-url` naming anything else is refused; only a loopback mirror is admitted, for tests. The committed value is the truth.
   - `docs/repo-gcloud-auth.md` is amended: public read-only bucket URLs and names may be committed; project ids and numbers, accounts and credentials still may not.
   - `tests/test_web_layout.py::test_no_concrete_bucket_url_is_tracked` keeps its name and location, and exempts **exactly** the committed URL form. A `gs://`, virtual-hosted, JSON-API or console form of the same bucket still fails, as does any other bucket, and tests pin this. I did not exempt the web-data URL, because this PR does not commit it.
2. **Version control in GCS.** Object versioning is on and soft delete is 30 days. Both are a backstop to the immutable release paths and no-overwrite uploads, which are unchanged.
3. **Not listable.** `allUsers` holds `roles/storage.legacyObjectReader` instead of `objectViewer`. Provisioning grants the reader role first and only then removes a listing role. `fetch_data` and `--verify-remote` take every key from the manifest and never list.
4. **Future automation.** The spec and docs present the maintainer upload as the current mechanism and the base for CI automation: refit on data change, upload through GitHub→GCP Workload Identity Federation. That automation is not built here.

The original scope follows.

The owner's decisions:

- "all data, including surfaces, belong on GCP."
- "the data (raw data, harmonized data, surfaces, trained models) should be available to everyone, that's the point of genomeOS Atlas."

`data/` was 259 MB tracked on `main`, and every clone paid for it. The repository is public, so mirroring the data to a public bucket exposes nothing new.

- **`genomeos/publication/data_release.py`** (pure; no I/O, no network). It defines the manifest schema, immutable release-versioned keys (`releases/<release>/<path>`, with earlier keys reused for identical bytes), a closed media-type table, refusal of pickles, and source and terms references. Every violation is a hard error.
- **`scripts/build_data_release.py`** hashes the include roots under `data/`. It maps each path to its sources with a reviewed table; a path no rule claims is refused. It copies terms verbatim from the records that hold them (the CPIC and curated `SOURCE.json`, #117 for AFND) and writes `not_checked` where the repository records nothing. It refuses pickles and object-dtype `.npy`, refuses a released artifact whose bytes changed, and never replaces a written release.
- **`scripts/fetch_data.py`** is for readers and needs no credentials.
  - It uses the standard library only, and fetches over public HTTPS into the git-ignored `data/`.
  - Downloads stream through `data/.fetch-partial/`. The byte count and sha256 are checked before an atomic rename, and any mismatch is a loud failure.
  - A local file that differs from the manifest is never overwritten.
  - Modes: `--list`, `--verify-local`, and `--verify-remote` (GET and hash everything, write nothing).
  - Other scripts call `require_local()`.
- **`scripts/publish_data_store.py`** is the maintainer's upload, and runs through `gcloud_repo.py`. It checks every local file first, then settles every key's identity (metadata sha256 and size) before the first upload. Absent keys are uploaded with `--if-generation-match=0`. Identical ones are skipped, and any other existing object is a hard error. A 412 response gets the same comparison. After each upload it verifies size, md5 and metadata. The manifest copy goes last. Nothing is ever deleted.
- **`scripts/provision_data_store_bucket.py`** sets up a dedicated bucket, separate from the web-data bucket:
  - us-east1, uniform access, `allUsers` objectViewer, no versioning, open GET/HEAD CORS;
  - the label `genomeos-purpose=data-store`;
  - it reuses the web provisioner's org-policy check, refuses any bucket it did not label, and is idempotent.
- **Store readers:**
  - `build_atlas_catalog.py` resolves its `--source` through the store.
  - `sync_store.py push-atlas-release` resolves each artifact directory the same way.
  - `publish_artifacts.py` refuses any directory a committed release already holds, even with `--overwrite`. Immutability can no longer depend on the local tree being complete.
  - `store_inventory.py`: docstring update only.
  - `plot_registry_refusal.py` and `screen_alleles.py` touch only pickled fits, so they are not applicable.
- **Untracking:** `git rm -r --cached data/store/artifacts data/validation` (229 files), `.gitignore` updated, and `!data/releases/` added.
- **Docs:** AGENTS.md, README, CONTRIBUTING, `docs/data-store.md` and `docs/hf-dataset-card.md` now point at the data store and give `git clone --filter=blob:none` advice. Research notes that linked into `data/validation/` now name the files and the fetch command.

**Overlap with the web-format-version branch.** That branch is the other agent's (publication/, export and encode scripts, `website/src/atlas`). This PR adds only a **new** file in `genomeos/publication/`, `data_release.py`. It does not edit `export_atlas_web.py`; that script's `--store` is documented as "fetch first".
