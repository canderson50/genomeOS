## Body

## Summary

After the map appears, the Atlas now loads the rest in a fixed order:
1. the Natural Earth borders;
2. the exact (f64) cell values for the displayed dataset;
3. the starfield.

Each step starts when the one before settles. On phones the borders and exact values arrive much sooner, because they no longer share the link with each other or with the 870 kB sky box.

The PR also fixes a GPU stall that main already has (see below).

Closes #443.

## What changed

- **`website/src/atlas/load-order.ts` (new),** a small, pure sequencer:
  - The borders start at surface-visible, as before, and settle at their last byte.
  - The detail tier settles when it is decoded.
  - The starfield waits for both, and for `ready`.
  - A failure, or a stall of 15 s (the provider's own stall window, where any body chunk counts as progress), releases the next step, so nothing can block.
  - A later dataset switch starts its detail tier at once.
- **`context-overlay.ts`:** the borders fetch streams its body, reports each chunk as progress, and calls `onFetched` at the last byte.
- **`useArtifactPipeline.ts`:**
  - detail requests queue behind the borders;
  - a turn that joins a request already in flight hears its chunks;
  - a tier that is already attached marks `values-ready` at surface-visible, without waiting.
- **Spec:** §B.2 and §B.6.9 are amended with a dated note.

## The desktop long frame, and a stall that main already has

The first measurement of this branch failed the desktop budget. The longest frames were 598 and 673 ms, against a 200 ms budget. Traces showed the cause was on main too:

1. **The trigger.** At the cold commit, `setSurfaceHeights` re-applied the same heights object the first chunk had applied. That re-placed all 1,071 HbS sampling rings at identical positions. On the next render, Cesium rewrote their 14.8 MB position buffer one ring at a time: 1,071 `bufferSubData` calls.
2. **The stall.** In many loads, the GPU process (ANGLE Metal) then spent 650–850 ms on that work. No frame could start until it finished.
3. **Why main hid it.** On main the stall lands while Cesium uploads the sky box, so the harness charged it to Cesium. A probe that records every long frame found 624–685 ms frames on main in 4 of 6 runs.
4. **Why this branch failed.** With the new order the sky box waits, so Atlas work landed inside the stall and the harness charged it to the Atlas.

**The fix (98f5e91).** `setSurfaceHeights` now ignores a heights object identical to the current one. Heights are immutable, so nothing visible changes. Two regression tests pin it.

**The evidence is an intervention, not just correlation.** With this one check removed, the branch has long frames in 10 of 12 runs. With it, none of 12 do. Main plus the check alone shows no stall.
