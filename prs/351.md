## TL;DR

This connects the reviewed download and counting steps to produce four tables showing how often each variant appears by population, using two participant groups and two quality settings, with independent checks of every result. It publishes only population summaries, never individual genotypes, and depends on the five smaller prerequisite pull requests (#346–#350).

---

The reference-window campaign had a reviewed acquisition and count-preparation implementation, but PR #287 combined every layer into one 17k-line review. This final stacked slice composes the verified acquisition evidence into four immutable technical/paper × called/quality count tracks, retains independent native controls, and publishes the aggregate-only execution report. It advances #255 and #189; it does not close either issue on its own because the preceding stacked PRs must also merge.

This PR is stacked on #350. The full stack is #346 → #347 → #348 → #349 → #350 → this PR.

### What changed

- adds the offline acquisition and preparation CLIs with revision, source-hash, executable, library, plugin, and SDK identity gates;
- streams each retained record once and counts the nested 4,117-sample technical and 4,094-sample paper cohorts together, then compares each result against independently generated native totals and tokens;
- emits exact window/QC/native ledgers and four manifest-last count tables while refusing incomplete or contradictory evidence;
- decomposes the former oversized artifact and preparation modules into responsibility-specific modules, all within the repository size budget;
- expands campaign provenance from the historical 32-file execution surface to the current 38-file reviewed implementation surface;
- adds mutation-powered tests for native-count disagreement, missing/duplicated/reordered 66-window manifests, and contradictory completeness flags;
- rejects coherently rehashed geography substitutions by replaying each count row against the retained cohort and parent genotype evidence;
- carries the normative design/plan updates and the aggregate-only historical run report. No private participant, genotype, per-variant count, credential, or real generated artifact is tracked.

Design implemented: reference-window acquisition design §§5–7; Atlas §§4–8 and §12.
