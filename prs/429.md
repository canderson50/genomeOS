## Body

## Summary

Adds Google Analytics 4 to genome-os.org. Analytics is **opt-out by default outside Europe** and **opt-in in the EEA, the UK and Switzerland**, and the site honours **Global Privacy Control**. Wherever analytics is off in the browser (an undecided visitor in a European time zone, a Decline, a switch turned off, or GPC), the page doesn't load gtag.js at all, so nothing reaches Google. Every page has a small, collapsed **cookie settings icon**, and the footer has a **Cookie settings** link that opens the same panel. The Atlas sends three usage events, and a new **/privacy/** page explains all of this.

> **Before merge, the owner must untick one GA setting:** "Page changes based on browser history events" (owner step 2). While it is on, every pan or zoom in the Atlas sends Google a page view whose URL holds the camera's latitude and longitude.

Only the production Pages build loads analytics, from the repository variable `GA_MEASUREMENT_ID`. Local dev, the validate and e2e jobs, the `/genomeOS/` fallback, pull requests and forks load nothing. Without the variable, `dist/` contains no `gtag`, no `googletagmanager` and none of the cookie-control code.

## Consent design

An inline head snippet on every page (site layout, all docs pages, `/app/`, `/app/polygon/`, 404) does this, in order. There is no static `<script src>` for gtag.js; the snippet adds it only in step 4.

1. Sets up `window.dataLayer` and `gtag`.
2. Calls `gtag('consent','default', …)` twice:
   - for EEA (EU-27 + IS, LI, NO), GB and CH, plus the EU territory Google geolocates separately (GP, MQ, GF, RE, YT, MF, AX) and JE, GG, IM, GI: `analytics_storage`, `ad_storage`, `ad_user_data` and `ad_personalization` all **denied**, with `wait_for_update: 500`;
   - everywhere else: `analytics_storage` **granted** and all ad signals **denied**.
3. Sends at most one `gtag('consent','update', {analytics_storage})`, using the first rule that applies (the same rule as `resolveConsent` in `src/lib/consent.ts`):

   | Visitor | analytics_storage | gtag.js | Cookie control on load |
   |---|---|---|---|
   | Has a stored choice (`localStorage['genomeos-analytics-consent']`) | the choice | loads only if granted | collapsed |
   | Browser sends Global Privacy Control, no stored choice | denied | not loaded | collapsed; the panel says GPC turned it off |
   | Opt-in time zone, no stored choice | denied (opt-in) | **not loaded until Accept** | **opens as an Accept/Decline prompt**, once per visit, without taking focus |
   | Anyone else | granted (opt-out default stands, no update) | loads | collapsed |

4. Unless step 3 left analytics denied: calls `gtag('config', ID, { page_location: origin + pathname, send_page_view: true, allow_google_signals: false, allow_ad_personalization_signals: false })`, then adds gtag.js. The query string and fragment are never sent (they hold an Atlas camera position or a selected cell), and `page_referrer` is also stripped of its query. Where analytics is denied, a later `gtag('consent','update',{analytics_storage:'granted'})` (Accept, or the switch turned on) runs step 4 then, with the grant ahead of the config.

**Basic consent mode where analytics is denied in the browser.** With gtag.js loaded under a denied default, Google's advanced consent mode still sends cookieless `page_view` pings (`gcs=G100`, with the page URL, user agent, screen size, language and referrer) to google-analytics.com and www.google.com. I confirmed this with the real container under `Europe/Berlin` in headless Chromium, with every collect request aborted. With this change the same run makes **no request to googletagmanager.com or any collect endpoint before Accept**. After Accept it loads gtag.js once and sends one path-only `page_view` with `gcs=G101`, and the `_ga` cookies appear. Until gtag.js is loading, and after analytics is turned off on a page, the head's `gtag` drops `event` calls instead of queueing them, so no Atlas event is held back and sent after a later Accept.

**Choices** are stored in `localStorage` and never in a cookie. They are applied before `config` on every page load. Turning analytics off also expires any `_ga` and `_ga_<container>` cookies.

Lifting it to 72 px, as first suggested, would have put it on the camera control.

It is crowded at desktop widths: the pill's right end sits right under the legend's info button at 1100–1200 px, and widening the pill covered the legend's Color button at 1440.

**Choices I made where the issue was silent:**

- **Basic consent mode wherever analytics is denied in the browser** (see above). The owner asked for opt-in in the UK and Europe "just to be safe". Google's advanced mode sends cookieless pings before Accept, and its basic mode is described as "no data is sent before a user consents". So an undecided visitor in an opt-in time zone, a Decline, a switch turned off and GPC all mean **no gtag.js**. The cost is that GA's modelling gets no pings from them. The one remaining advanced-mode case is a visitor whom Google places in the EEA/UK/CH by IP but whose browser reports a time zone elsewhere (VPN, traveller): there gtag.js loads, Google's region default keeps it cookieless, and it sends pings until they choose. `/privacy/` says so.
- **Opt-in time zones also apply `denied` in the browser.** The issue's IP region default only covers visitors Google places in the EEA/UK/CH. This rule means that what the panel shows is always what gtag was told: a visitor shown the opt-in prompt is never already tracked. Over-inclusion (a non-European in a European zone) only means asking first. Under-inclusion is still covered by Google's IP region default.
- **The opt-in lists go beyond the EEA, UK and CH, "just to be safe".** Google geolocates the EU's outermost regions and Åland as countries of their own, so the 30 EEA codes missed a visitor in Réunion or Guadeloupe, who got `_ga` cookies without a prompt. Both lists now include them: the codes GP, MQ, GF, RE, YT, MF and AX, and the zones America/Guadeloupe, America/Martinique, America/Cayenne, Indian/Reunion, Indian/Mayotte and America/Marigot (Europe/Mariehamn was already listed). They also include Jersey, Guernsey, the Isle of Man and Gibraltar (JE, GG, IM, GI and their `Europe/*` zones), whose laws follow the GDPR. Each new zone reports under its own name in Chromium and in Node's ICU 76.
- **The panel can show "On" where Google has analytics off.** For the VPN/traveller case above, Google's region default is denied, but the browser sees a non-European zone, so the switch shows **On** and no prompt opens. A first click "turns off" something already off. The error is on the conservative side (Google sets no cookie). The fix would be a geo-IP lookup, which this static site doesn't have.
- **GPC wins over the opt-in prompt.** A European browser that sends GPC is treated as opted out and isn't prompted. It can still opt in from the icon.
- **"First visit" means first page per browser session.** Closing the prompt without choosing sets a `sessionStorage` flag (`genomeos-analytics-prompt-dismissed`, not a cookie), so the prompt doesn't reopen on every page. A new visit asks again.
- **The control renders only in builds that load analytics.** With no GA there are no cookies to set. The `/privacy/` page is published in every build.
- **Known limits:**
  - On short landscape phones (≤ 34rem tall), the Atlas hides its docked credit strips above peek, and the docked icon hides with them. It is back at peek.
  - In a European time zone on desktop `/app/`, the first-visit Accept/Decline prompt opens above the bottom-left icon and covers part of the controls dock and the legend until it is answered or dismissed. A press on the covered part lands on the prompt, so it doesn't dismiss it. This happens once per visit, so I left it; no test pins it.

## Atlas events

`src/lib/analytics.ts` exposes `trackEvent`, which is a no-op without gtag (and is constant-folded away in builds without an ID), never throws, and drops an identical event repeated within 1 s. It is called from `useAtlasAnalytics` in Part B's `AtlasExplorer`:

- `atlas_dataset_open` `{dataset_id}`: when the requested dataset changes, including the initial one once. Only catalog ids count.
- `atlas_view_change` `{view: globe|map|perspective}`: on a view switch. The opening view doesn't count.
- `atlas_inspector_open` `{inspector: surface|observation}`: when an inspector opens or changes kind.

Events carry no coordinates and nothing about the visitor.

## Privacy page

`/privacy/` uses the site layout, and "genomeOS" there is the wordmark span. It covers:

- GA4 and its `_ga` and `_ga_<container>` cookies, each lasting up to two years (Google's cookie table): set only after opt-in in the EEA/UK/CH (their overseas regions, Åland, the Channel Islands, the Isle of Man and Gibraltar included), where the site doesn't load GA at all until Accept; set by default elsewhere unless the visitor opts out or sends GPC. With analytics off, pages don't load GA. It also describes the VPN/traveller case that gets cookieless pings.
- What is collected: pages (path only), referrer, approximate location from IP (GA4 does not log or store IP addresses), device and browser, and the three Atlas events. Visit-level data is kept for **two months** (see owner step 4), and only aggregate reports after that.
- What isn't: no ads, Google signals off, no personal details.
- How to change the choice: the icon in a bottom corner (in the Atlas, under the map controls on a wide screen and at the end of the data credits on a phone), or the Cookie settings link at the foot of the site and docs pages. `/app/` hides the site footer, so the link isn't there.
- Google's privacy policy.
- A build without analytics (the `/genomeOS/` fallback, local dev) opens with "This copy of genomeOS loads no analytics and sets no cookies. The rest of this page describes genome-os.org, which does."

Footers on the site and the docs gain **Privacy** and **Cookie settings**.

## Owner steps

1. ~~Create the GA4 property and send the Measurement ID~~: done on 2026-10-10. Per the issue, the repository variable `GA_MEASUREMENT_ID` is already set, and `pages.yml` passes it **only** to the production "Build production site" step as `PUBLIC_GA_MEASUREMENT_ID`. A malformed value fails the build.
2. **Required before merge.** In GA Admin, go to **Data streams → genome-os.org → Enhanced measurement (gear) → Page views → Show advanced settings** and **untick "Page changes based on browser history events"**.
   - **Why:** the live container has this on (`vtp_enableHistoryEvents: true`). gtag.js then wraps `history.pushState`/`replaceState` and listens for `popstate`, `hashchange` and back-forward-cache restores, and sends a `page_view` with the **full URL** whenever it changes. The Atlas calls `history.replaceState` on every camera settle, so every pan or zoom sends an extra page view whose `dl` holds the camera's `lat`/`lon` and whose `dr` holds the previous position. I reproduced this with the real container in headless Chromium, with every collect request aborted. That contradicts `/privacy/` ("by path only, never the query", "we never send what you look at on the map") and inflates page-view counts.
   - **Why not in code:** no gtag config parameter overrides this container setting. I considered having the Atlas call the native `History.prototype.replaceState` to get past gtag's wrapper. It would still leave the `popstate`/`hashchange` path (the `/app/` skip link) and the bfcache restore path, both of which send the current URL. It would also leave gtag's "previous URL" stale. So the setting is the fix.
3. **Defence in depth, same data stream:** **Redact data → URL query parameters**: enable it and list `lat`, `lon`, `height`, `heading`, `pitch` and `cell`. This keeps any page view that does carry the Atlas query from reaching Google with a position.
4. Also in GA Admin:
   - **Data collection:** leave **Google signals off**. The container already disallows it in every region, matching `allow_google_signals: false`. Also turn **User-provided data collection off**: the container has automatic detection of emails, phone numbers and addresses on, and `/privacy/` says "No names, accounts or other personal details".
   - **Data retention:** keep event data retention at **2 months**, the GA4 default, which `/privacy/` states. A longer period needs `/privacy/` updated too.
   - **Custom definitions:** add event-scoped custom dimensions `dataset_id`, `view` and `inspector` so the Atlas events can be broken down in reports.
5. **Verify after deploy:**
   - **No coordinates:** on https://genome-os.org/app/, open DevTools → Network, filter `collect`, then pan and zoom the globe. No new `page_view` should appear, and no request should carry `lat=`.
   - **Realtime:** open https://genome-os.org from a non-EU browser. Reports → Realtime should show the page view within a minute. In DevTools → Network, the `…/g/collect` hits should carry `gcs=G101` (analytics granted, ads denied), and Application → Cookies should show `_ga` and `_ga_<container>`.
   - **DebugView:** connect the site in Tag Assistant (tagassistant.google.com). Admin → DebugView then lists `page_view` and, on `/app/`, `atlas_dataset_open`, `atlas_view_change` and `atlas_inspector_open` with their parameter. Tag Assistant's Consent tab shows the defaults and the update.
   - **Opt-in path:** set the browser's time zone to Europe/Berlin (DevTools → Sensors → Location). The icon opens as the Accept/Decline prompt. The Network panel should show **no** `googletagmanager.com` or `collect` request and no `_ga` cookie until **Accept**. Then gtag.js loads, a `page_view` with `gcs=G101` follows, and the cookies appear.
   - **GPC:** in a GPC browser (Firefox with GPC on, Brave or DuckDuckGo), no `googletagmanager.com` request until the switch is turned on.
