## Body

## Scientific objective

Count-predictive scores must be valid log probabilities, and exact discrete quantile endpoints must respect the distribution's support. These are benchmark-composition invariants, not evidence of allele-frequency accuracy.

## Reproduction

Independent final review of `feat/global-af-modeling` at `8da0398` reproduced:

```python
import numpy as np
from genomeos.validation.predictive import CountPredictive

CountPredictive(np.array([[1e-16]]), concentration=np.array([[1e6]])).log_prob([0], [1])
# [1.043968467229206e-09], but the analytic Bernoulli result is log1p(-1e-16)

CountPredictive(np.array([[0.1]])).quantiles([100], [1.0])
# [[42]], but the true upper support endpoint is 100
```

The positive log probability passes through `predictive_diagnostics`; `summarize_benchmark` correctly refuses it. Beta-function subtraction loses precision. Quantile binary search accepts a CDF rounded to one before the actual endpoint. Current diagnostic levels stop at 0.975, but the public quantile interface accepts 1.

## Engineering contract and acceptance

- Stabilize accepted evaluations or explicitly refuse numerical failure at the scoring boundary. Do not clip probabilities or relax the reporter.
- Handle 100% quantiles from exact mixture support, including all-zero degenerate mixtures.
- Add analytical and scorer-to-reporter regressions, observed failing before the fix.
- Run focused tests, smoke, complete CI checks, and relevant GPU verification if the executed scoring path changes. Preserve prior hardware reports under their original revisions.
