## Body

## Problem

`scripts/build_registry.py` takes `--hgdp`, `--afnd` and `--wbbc-regions`, but has no way to add reviewed **literature** populations and their P0 aliases. So the literature promotion path can't be run from the command line:

- `scripts/build_observations.py --literature-evidence ... --literature-field-evidence ...` refuses any promotable literature row whose population label has no reviewed `literature` P0 alias. For example, the fixture row fails with `UnmappedPopulationError ... population label absent from an exact literature P0 alias: 'Sami'`.
- A registry built by the CLI can never carry those aliases, so the end-to-end rebuild in AGENTS.md had to drop the two literature flags (#424).

Literature promotion is currently exercised only in-process, by `tests/test_build_scripts.py`.

## Why it matters

#151 (HBB rs334 publication round trip, critical) needs reviewed `literature` P0 aliases for the Salih 2010 population labels before those rows can be promoted (see #403). Without a CLI route, that step can't be reproduced from the documented commands.

## Acceptance

- `build_registry.py` accepts reviewed literature populations and aliases from a curated input, validated as strictly as the other registry sources: no defaults for `uncertainty_radius_km`, and a hard error on any label without a coordinate.
- The AGENTS.md rebuild can include `--literature-evidence` / `--literature-field-evidence` again and promotes the fixture row.
- A test covers the CLI route.
