## Body

On the pinned A100 CUDA qualification run, frozen E1 stopped at `refusal.first.2403.add`: the expected ValueError did not occur for the noncanonical ScaledPair (-0.0,+0.0,0).

The retained NumPy 0-D input has uint64 bits 9223372036854775808, but CuPy 14.2.0 `asarray` transfers that 0-D array as positive zero (bits 0). The core therefore correctly accepts the altered input. A one-element NumPy upload followed by device `reshape(())` preserves the negative-zero bits and the unchanged core raises ValueError.

This violates exact input identity for the CUDA arithmetic qualification harness. Repair scalar H2D materialization while preserving shape, dtype, bit pattern, immutable original evidence, and every refusal expectation. Add focused transfer regressions, independently review the successor, then rerun the unchanged E1 gates under a new version.

Actual environment: CPython 3.12.3, NumPy 2.4.6, CuPy 14.2.0, A100 SXM 80GB, CUDA runtime API 12090. Original overall run failed: 1 stage attempted, 0 completed, 4 unstarted. No numerical/scientific acceptance claimed.
