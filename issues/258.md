## Body

## TL;DR

One of our tests fails for a reason that has nothing to do with what it is testing. It happens only when a developer works in a separate copy of the repository, which we do routinely. The test looks alarming — it reports that our data formats have drifted, which would be serious — but nothing is actually wrong. It cost two people time this week, and one of them misdiagnosed it. A one-line change fixes it.

---

## What

`tests/test_contract_frozen.py::test_frozen_contract_matches_the_live_schemas` shells out:

```python
subprocess.run([sys.executable, "scripts/freeze_contract.py", "--check"], cwd=REPO, ...)
```

Running a *script* puts the script's directory on `sys.path`, not the cwd. So the subprocess resolves `genomeos` through the editable install rather than through `REPO`. When those are the same tree this is invisible. When they are not — anyone developing in a **git worktree**, which this project does routinely — the subprocess imports a different checkout, and the test fails with a `ModuleNotFoundError` for any module that exists only on the branch under test.

Observed while building `feat/variant-normalization-registry`: the test failed for the whole branch, passed on `main`, and passed with `PYTHONPATH=.`. Nothing was wrong with the contract. CI is unaffected, because it installs editable into the checkout it is testing.

## Why it is worth fixing rather than tolerating

It costs real time in exactly the situation where people are least sure of themselves. Two separate agents hit it on this branch; one misdiagnosed it as pre-existing, and the failure looks alarming — a frozen-contract test failing reads as schema drift, which is a serious thing in this repo.

It is also a symptom of a trap that is now documented in `AGENTS.md` ("Verifying a branch in a git worktree needs care"). This test is the first place it bites automatically.

## Fix

Pass the repository explicitly, so the subprocess imports the tree under test:

```python
env = {**os.environ, "PYTHONPATH": str(REPO)}
result = subprocess.run([...], cwd=REPO, env=env, capture_output=True, text=True)
```

## Acceptance evidence

- The test passes in a git worktree whose branch adds a new module, without setting `PYTHONPATH` by hand.
- It still passes in a normal checkout and in CI.
- It still **fails** when the contract genuinely drifts — verify by editing a schema without regenerating.
