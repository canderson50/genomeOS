## Body

## Scientific objective

Complete exact posterior-predictive beta-binomial diagnostics for admitted million-scale count data quickly enough that the five-fold global AF benchmark is operational rather than dominated by GPU kernel-dispatch overhead. The A100 benchmark under #189 spends tens of minutes per fold after sampling while GPU utilization remains around 40% and one host CPU core stays saturated. #316 removes irrelevant full-support probes, but measured fold time remains about 18 minutes because `CuPyCDF` dispatches exact tail work in nested batches of only 4 query rows × 128 draws × 1,024 support values.

This is source-neutral numerical infrastructure. It neither prioritizes the current HbS development dataset nor changes any source, model, or promotion gate.

## Measurable output and acceptance evidence

- Establish an immutable before/after profile on the same named GPU, source revision, workload parameters, and pinned numerical environment using `scripts/profile_count_scoring.py` or a benchmark extension that faithfully represents multi-query beta-binomial quantiles.
- Reduce wall time and host dispatch overhead on the measured A100 workload without reducing posterior draws, requested quantiles, float64 arithmetic, or exact finite-tail semantics.
- CPU/CuPy CDFs, quantile endpoints, coverage, PIT, and interval widths retain their existing parity tolerances across row, draw, and support chunk boundaries.
- Peak temporary memory remains explicitly bounded. Chunk selection must refuse or reduce its plan when the device cannot safely provide the required memory; it may not rely on the 80 GB A100 alone.
- The five-fold current-GP benchmark completes with the same frozen inputs and scientific configuration, and the artifact records the implementation commit.
- Focused tests, full pytest, smoke, Ruff, contract, module-size, privacy, and actual-device GPU tests pass.

## Engineering component and public interface

Change the offline GPU numerical backend in `genomeos.validation.predictive_cupy.CuPyCDF` and, if needed, the existing immutable profiler artifacts. Keep `CountPredictive`, `cdf_backend="cupy"`, returned arrays, and failure semantics unchanged. Prefer fewer, larger vectorized device operations or a validated recurrence/scan over additional Python loops.

## Assumptions, refusal conditions, and downstream consumers

- Exact count-law semantics and float64 validation remain fixed. Sampling-based intervals, normal approximations, reduced draws, or silent CPU fallback are ineligible shortcuts.
- Device-memory planning must leave a documented safety margin and fail loudly if it cannot satisfy the bound.
- Performance claims require measured artifacts; utilization screenshots or synthetic microexamples alone are insufficient.
- `predictive_diagnostics`, B0/B0H/current-GP comparisons, and the broader WP1 model ladder are downstream consumers.

## Expert review

A numerical/GPU reviewer should check temporary-array accounting, synchronization in the timing harness, parity at chunk boundaries, and whether the benchmark exercises the same query shape and support lengths as the real five-fold workload.
