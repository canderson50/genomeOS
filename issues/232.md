## Body

## What happened

Independent final review of the B0H codec reproduced a pre-existing constructor
validation defect in `SelectedSbcQuantities`. At
`genomeos/validation/heterogeneity_sbc_quantity_types.py:431`, comparison-bearing
ranks look up point slots before the failed-control consistency check at line435.
Failed controls omit slots5–8. A locally valid complete mode1 dependence rank
inserted into a failed-control record therefore raises `KeyError('5')` instead
of the intended validation `ValueError`.

The same error occurs through the public constructor without the codec. The
scientific constructor source is unchanged from `df0b71d`; the literal fixtures
below are available on `feat/global-af-b0h-codec` at `b2f7700`.

## Reproduction

With the repository's locked test environment:

```bash
PYTHONPATH=.:tests python - <<'PY'
from dataclasses import replace
from heterogeneity_codec_fixtures import selected, control_failures

complete = selected()
failed = selected(failure=control_failures()[0])
try:
    replace(failed, ranks=failed.ranks[:11] + (complete.ranks[11],) + failed.ranks[12:])
except Exception as exc:
    print(type(exc).__name__, repr(str(exc)))
PY
```

Observed: `KeyError '5'`. Expected: deterministic `ValueError` rejecting a
non-control-failed rank when its control failed, before attempting slot lookup.
The reviewer also reproduced this with canonical codec metadata for the same
invalid state; the codec correctly propagates the unexpected constructor error
under its explicit exception policy.

## Impact and bounded fix

Invalid evidence still refuses; no evidence is admitted, repaired or silently
mutated. This violates the normal public validation-error interface, not the
scientific failed-control rule. Move the existing consistency rejection before
the slot access and add a direct constructor regression plus a codec integration
regression. Do not broadly swallow `KeyError`, duplicate scientific validation
in the codec, loosen failed-control dominance or change rank/control semantics.

This is separate from the representation-only codec change and advances the
validation robustness work under #211/#189. Acceptance: the exact invalid state
raises the declared validation exception, valid failed-control states remain
unchanged, and focused quantity/codec tests plus mandatory smoke pass.
