## Body

The repository moved from `bschilder/genomeOS` to `genomeOS/genomeOS` on 2026-10-10. Old GitHub links redirect, but three things don't:

1. **Container publishing will fail.** `.github/workflows/docker.yml` pushes to `ghcr.io/bschilder/genomeos`. The transfer unlinked that package from the repository (`repository: null`), so the org repo's `GITHUB_TOKEN` can't push there. The next push to main fails the container workflow. Fix: publish to `ghcr.io/genomeos/genomeos` and update the README and deployment docs' `docker pull` lines. The old image stays pullable at its old address.
2. **The Pages fallback host changed.** `website/scripts/build-fallback.mjs` builds for `https://bschilder.github.io`, which now 404s for this repo. The fallback host is `https://genomeos.github.io` (it redirects to genome-os.org while the custom domain is set). The Part C bucket CORS list needs the same change before provisioning (tracked in #406's lane).
3. **Site links** (header GitHub link, docs edit links, Discussions and Issues links on the home page) should point at the new home rather than rely on a redirect.

**Settings for the owner (not code):** "Enforce HTTPS" on GitHub Pages was off after the transfer: `http://genome-os.org` serves without redirecting, though the certificate is approved. At GoDaddy, `www` still CNAMEs to `bschilder.github.io` (works today), and domain verification is the user-level `_github-pages-challenge-bschilder` record. The org should verify the domain too.

**Out of scope here:** the ~180 documentation links that only redirect (a follow-up sweep once the in-flight PRs land, to avoid conflicts); the project board, which stays at users/bschilder/projects/8; Hugging Face `bschilder/genomeos-data`; and `bschilder/cugen`.

**Done when** the container workflow publishes to the org namespace on main, the fallback build and its link check use `genomeos.github.io`, and the site's GitHub links point at `genomeOS/genomeOS`.
