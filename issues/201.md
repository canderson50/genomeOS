## Observed dependency defect during #195 preflight

Pinned local CuGen `03df1688abf52d295bd85d47f1aca6130440b553` (0.1.7), Python3.12.13,
NumPy2.4.6, Pandas3.0.5, CPU-only process. `cugen.ld.ld_matrix(..., backend="numpy")`
returns correct synthetic LD but emits `ResourceWarning: unclosed file` when warnings are
made observable. Source `ld.py` opens `reader = read_cugen(...)` and neither closes it nor
uses its context manager; `io.py` provides `close`/`__enter__`/`__exit__`.

Observed on the hand-auditable #195 fixture: seven variants, four manually selected training
samples; explicit annotation, `stats=("r","r2")`, pairwise missingness, ALT orientation,
`min_obs=2`, no MAF/r2/window filter, `output=None`, `precision="fp32"`, `max_pairs=21`.
It produced all six valid pairs with exact co-observed counts/identities, maximum absolute R
error1.554362449862623e-08 and R2 error3.448202612332807e-09. The remaining11 insufficient-
observation and4 zero-variance pairs were absent as expected. Independent byte decode also
matched the input genotype calls/gidx. This was NOT GPU subsetting or a GPU LD test.

Minimal reproduction structure:

```python
import warnings
import numpy as np
from cugen.write import write_cugen
from cugen.ld import ld_matrix

# Use a new temporary file; all values are synthetic.
write_cugen(path, np.array([[0, 0], [1, 2], [2, 1]], dtype=np.uint8),
            gidx=[30, 10], encoding=0)
with warnings.catch_warnings(record=True) as seen:
    warnings.simplefilter("always")
    result = ld_matrix(path, backend="numpy", stats=("r", "r2"),
                       precision="fp32", output=None, verbose=False)
    resource_warnings = [str(w.message) for w in seen
                         if issubclass(w.category, ResourceWarning)]
```

Expected: the public API explicitly releases its reader on success, early return, and
exception. Observed: file finalization generates the warning. This does **not** establish a
persistent file-descriptor leak or incorrect LD, and no such claim is made. The first pilot
remains isolated and bounded, but must retain warning/resource evidence.

Scope: track a minimal upstream reader-lifetime fix or documented dependency resolution as
part of CuGen integration; do not edit the external checkout or replace CuGen as a side effect
of the observation-interface PR. Add tests for successful, empty-result and failure exits,
checking actual closure, not just warning suppression. Recheck exact numerical behavior and
the public API after the upstream change. No production surface/model behavior changes here.

The separate six Pandas4Warnings in this diagnostic concern the deprecated `copy=` keyword;
they are not evidence of the reader defect and should not be conflated with it.
