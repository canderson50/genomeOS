## Body

Today the GitHub Pages artifact ships all 609 MB of `website/public/data/atlas`, with `max-age=600` and no immutable caching. Of that, 598 MB is per-artifact surface JSON committed to `main`.

**Scope:** Part C of the design spec `docs/superpowers/specs/2026-10-07-atlas-mobile-fast-load-gcs-design.md` (§C.1–C.4):
- **Bucket:** a public bucket in `us-east1`. Objects use content-addressed keys under `atlas/web/` with `Cache-Control: public, max-age=31536000, immutable`, and are stored with gzip transport encoding. Metadata records the decoded sha256 and size.
- **Scripts:** `provision_atlas_web_bucket.py` (`--mode edge|cloud-cdn`) and `publish_atlas_web.py`, which refuses to overwrite an existing object, skips identical ones, and is run through `scripts/gcloud_repo.py`.
- **Site wiring:** a `PUBLIC_ATLAS_DATA_BASE_URL` build variable, from a repository variable with no project id in git. Two data bases: Natural Earth, places and `external/` stay in the Pages bundle.
- **Deploy gate:** checks status, gzip, Cache-Control, CORS and the decoded sha256/bytes metadata.
- **Tests:** a cross-origin e2e fixture origin.
- **Repo cleanup:** the 90 per-artifact files are removed from `main`. History is not rewritten.

The `edge` CDN mode is provisioned. The `cloud-cdn` mode (load balancer plus a managed certificate on `data.genome-os.org`) is scripted only. It needs a DNS A record at the registrar, which is a human step, and it has a recurring cost.

Relation to #33: this bucket serves only encoded site data. It does not replace #33's private artifact staging and pinning.
