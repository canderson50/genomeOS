## Body

## Scientific objective

Evaluate the declared beta-binomial observation model on the complete measured-count ledger used by the global AF benchmark. The current predictive scorer refuses any interior beta-binomial observation with `AN > 65,536`, although the fitted likelihood admits the project's supported count domain. That implementation limit blocks all five folds of the 994-row HbS development benchmark because 18 measured rows exceed it.

This issue advances #189. It does not promote the HbS source, make MAP a preferred publisher, or turn development evidence into sealed validation.

## Measurable output and acceptance evidence

- `CountPredictive.log_prob` evaluates interior beta-binomial counts throughout the declared `0 <= AC <= AN <= 2**31 - 1` domain with work and temporary memory bounded independently of `AN`.
- Per-draw and integrated mixture log masses match an independent high-precision oracle across small counts, million-scale denominators, boundary-heavy means, both allele orientations, and the admitted concentration domain. Tolerances must be justified from measured error rather than widened to make tests pass.
- Small-support normalization, complement symmetry, exact `AN=1` identities, impossible outcomes, and near-one mixture handling remain covered.
- Tests reject any support-sized allocation, recurrence, or loop whose work scales with `AN` in the log-mass path.
- The current-GP benchmark preflight accepts all 994 measured HbS rows without dropping or changing any count. Fit/CDF/quantile failures remain explicit and are outside this issue unless the new scorer exposes a separate defect.
- Focused tests, full pytest, smoke, Ruff, contract, module-size, and privacy gates pass.

## Engineering component and public interface

Change the offline predictive-scoring implementation behind `genomeos.validation.predictive.CountPredictive.log_prob` and `predictive_diagnostics`. Keep the public API and count-distribution semantics unchanged. Reuse the bounded rising-factorial method already independently exercised by the fitted beta-binomial likelihood where its numerical contract is adequate; do not couple validation code to private PyTensor graph internals.

## Assumptions, refusal conditions, and downstream consumers

- Beta-binomial remains the declared default likelihood. Do not silently substitute binomial scoring or drop high-denominator rows.
- Exact here means evaluation of the normalized finite discrete count law to a validated float64 error bound; an unvalidated asymptotic, normal approximation, or plug-in mean is ineligible.
- Means at exactly 0 or 1 retain their existing degenerate semantics. Invalid counts, nonfinite parameters, unsupported concentrations, or arithmetic outside the validated numerical domain must still fail loudly.
- `CountPredictive` diagnostics, the held-out evaluator in PR #313, WP1 benchmark reports, and subsequent model comparisons are the downstream consumers.

## Expert review

A numerical/statistical reviewer should check the rising-factorial derivation, error envelope at parameter extremes, normalization and complement evidence, and whether the accepted float64 tolerance is strong enough for model ranking by integrated log score.
