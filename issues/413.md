## Body

After #412, CI's pytest step runs on 4 xdist workers (`created: 4/4 workers`) but still took **39.6 min**: `6484 passed, 37 skipped in 0:39:35`. It was 49 min serial. Locally the same suite drops from 34.7 to 10.1 min with `-n 4 --dist loadfile`, so something on the runners does not parallelise.

Two hypotheses:
1. One slow test file dominates, because `loadfile` keeps a file on one worker.
2. Thread oversubscription: JAX, BLAS and numba each start their own thread pools inside each of the 4 workers on a 4-vCPU runner.

The CI log has no per-test lines, because the repo's addopts suppress `-v`. Step 1 is a diagnostic run with `--durations=40`; the fix follows from its data.
