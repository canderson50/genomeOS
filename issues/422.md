## Body

Add privacy-respecting analytics to genome-os.org, so we can see which pages and Atlas datasets people actually use.

**Owner decisions (2026-10-10)**
- **Cookieless**, so no consent banner: GoatCounter, which is open source, EU-based and free for non-profit use. Google Analytics was considered and set aside: it sets cookies, which would need a consent banner for EU/UK visitors.
- **Atlas events:** record a few key interactions, carrying only public dataset names and nothing about the visitor:
  - which dataset/allele is opened;
  - view switches (globe / map / perspective);
  - which inspector is opened.

**Design**
- The site code comes from a repository variable (`GOATCOUNTER_CODE` → build env `PUBLIC_GOATCOUNTER_CODE`), passed only to the production Pages build. Local dev, tests, the `/genomeOS/` fallback build and forks load no analytics.
- Use GoatCounter's versioned `count.js` with subresource integrity, on every page including docs and `/app/`. Count the path only, never the query string, so `/app/?entity=…` doesn't splinter.
- A small `analytics` helper (a no-op when GoatCounter is absent) sends Atlas events as GoatCounter events, e.g. `atlas/dataset/hbs-rs334`, `atlas/view/map`, `atlas/inspector/surface`.
- A short **Privacy** page, linked from the footer, saying what is collected (aggregate page views, referrer, country, browser/screen size, Atlas dataset/view events) and what isn't (no cookies, no personal data, no cross-site tracking).

**Done when**
- The production build includes the GoatCounter script with SRI, and every other build includes none.
- Atlas events fire once per user action, and tests cover both.
- The privacy page is live and linked.
- Events show up in the GoatCounter dashboard after deploy.

## Options considered (2026-10-10)

genome-os.org had no analytics, privacy page or content-security policy before this. The owner first asked for Google Analytics; the choice below came out of two questions: consent, then which cookieless service.

| Option | Cookies / banner | Atlas events | Cost | Why it wasn't chosen / was |
|---|---|---|---|---|
| **GA4 + consent banner** (Consent Mode v2) | Cookies after consent; needs a banner | Yes, with properties | Free | Most detail, but a banner on every first visit, and GA collects more than we need. |
| **GA4, no banner** | Cookies without asking | Yes | Free | Not compliant for EU/UK visitors (GDPR/ePrivacy require consent for analytics cookies), and the site serves international contributors. |
| **Cloudflare Web Analytics** | None | **No custom events** | Free | Can't record which Atlas datasets or views are used. |
| **Umami Cloud** | None | Yes, with properties | Free to 100k events/month, then paid | A good alternative, with a nicer dashboard and event properties. Usage caps. |
| **Plausible** | None | Yes, with properties | ~$9/month, or self-host | The best-known option, but paid. |
| **GoatCounter** ✅ | **None, so no banner** | Yes (events as paths, e.g. `atlas/dataset/hbs-rs334`) | Free for non-profit / small sites | **Chosen:** cookieless, open source, EU-based, free, and supports the events we need. Simpler dashboard than Umami or Plausible. |

**What GoatCounter collects:** aggregate page views, referrer, country (from IP, which is not stored), browser and screen size. No cookies, no persistent identifiers, no cross-site tracking. The privacy page will say this in plain words.

**Atlas events planned:**
- `atlas/dataset/<entity-id>` when a dataset or allele is opened, including the initial one;
- `atlas/view/<globe|map|perspective>` on a view switch;
- `atlas/inspector/<surface|observation>` when an inspector opens.

Each fires once per user action. They carry only public dataset names, never coordinates the visitor clicked or anything about the visitor.

## Decision changed (2026-10-10): Google Analytics 4 instead of GoatCounter

The owner reversed the cookieless choice and picked **GA4**, with the consent banner **shown only to EU/UK visitors**. GoatCounter is dropped, and the `GOATCOUNTER_CODE` repository variable is deleted. The options table above still stands as the record of what was weighed. GA4 is the "most detail" option, and its consent handling is below.

**Consent design**
- **Legal default from Google Consent Mode v2, per region.**
  - EEA countries, the UK and Switzerland: `analytics_storage`, `ad_storage`, `ad_user_data` and `ad_personalization` default to **denied**.
  - Everywhere else: `analytics_storage` defaults to **granted** and all ad signals to **denied**. We don't use ads.
  - Google applies the region default from the visitor's IP, so EU/UK visitors are never tracked with cookies unless they accept. Until then GA receives only cookieless pings, which it uses to model totals.
- **Banner display** is decided in the browser from the time zone (EEA/UK/Swiss `Europe/*` zones and the matching Atlantic zones), with no network lookup. A misclassified European still gets the denied default, so the fallback is safe. A non-European in a European zone sees a harmless banner.
- **The banner:** small and unobtrusive, with **Accept** and **Decline**. The choice is stored in `localStorage` (never in a cookie). Accept switches `analytics_storage` to granted. A **Cookie settings** link in the footer reopens it.
- IP anonymisation is built into GA4. Google signals and ads personalisation are off. Data retention is set in GA admin (owner).

**Measurement:** the site loads `gtag.js` only when the build sets `PUBLIC_GA_MEASUREMENT_ID`, and the production Pages build reads it from the repository variable `GA_MEASUREMENT_ID`, which the owner will supply. Local dev, tests, the fallback build and forks load nothing. Page views count the path only, never the query string.

**Atlas events (GA4):** each carries public identifiers only, nothing about the visitor:
- `atlas_dataset_open` {`dataset_id`}
- `atlas_view_change` {`view`: globe | map | perspective}
- `atlas_inspector_open` {`inspector`: surface | observation}

**Privacy page:** says that GA4 is used, which cookies it sets (`_ga`, `_ga_<id>`) and only after consent where required, what is collected, the regions where consent is asked, and how to change the choice.

**Owner steps:**
1. Create the GA4 property with a web stream for https://genome-os.org and send the Measurement ID (`G-…`).
2. In GA admin: turn off Google signals, set data retention, and check that the region consent settings match the above.

### bschilder, 2026-10-10T16:15:43Z (https://github.com/genomeOS/genomeOS/issues/422#issuecomment-6099576558)

## Consent model refined (owner, 2026-10-10)

This supersedes the banner-only design in the comment above.

- **Outside the EEA, UK and Switzerland: opt-out.**
  - Analytics cookies are on by default (ad signals are always off).
  - We honour **Global Privacy Control**: a browser that sends GPC is treated as opted out unless the visitor later makes an explicit choice. California, Colorado, Connecticut and other states require honouring universal opt-out signals.
- **EEA, UK and Switzerland: opt-in.**
  - Consent Mode's region default is *denied*, and Google applies it by IP.
  - Visitors in those time zones see the cookie control open as a short Accept/Decline prompt on their first visit.
- **An always-available cookie control** sits on every page for everyone: a very small collapsed icon in a corner. It expands to an on/off switch for analytics cookies, with a link to the privacy page. It never covers the Atlas controls, legend, credits or phone sheet. A **Cookie settings** link in the footer opens the same panel.
- **Choices** are stored in `localStorage`, never in a cookie, and applied on every page load. The privacy page describes the regional model.
