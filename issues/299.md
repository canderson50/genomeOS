## Body

## TL;DR

The reference-window acquisition work in #287 has a safety check that compares two independent
counts of the same genetic data, so that a disagreement refuses the window rather than publishing a
wrong number. The check works. Nothing tests it — I deleted the comparison and all 246 focused tests
still passed.

Filing this separately from the pull request so it survives if that work gets split up, because it
is the single most important gap found in the review.

---

## The three untested guarantees

Each was confirmed by breaking the production code and watching the tests stay green.

**1. The independent allele-count comparison.** Replacing the mismatch check in the count-preparation
script with an unconditional pass leaves every focused test passing. The deep replay path has the
same comparison and the same lack of coverage. No test anywhere feeds a count that disagrees.

The reason the gap survived is worth recording: in the end-to-end tests the native totals are
monkeypatched, and the fake is hard-coded to produce exactly the totals implied by the fake genotype
stream. The stand-in was built to agree with the thing it is meant to be capable of contradicting.
That is the general failure mode — a fake cannot falsify a comparison it was derived from.

**2. The complete-window-set requirement.** Two separate type-level checks require the window
identifiers to match the full expected set exactly. Neutralising both leaves the artifact, CLI and
preparation suites passing. The only coverage is a happy-path count. Nothing tests that a missing,
duplicated or reordered window is refused.

**3. The completeness flag.** One check verifies it, it is never recomputed, and it is a plain
boolean so decoding does not catch it either. It gates the entire preparation phase and both
command-line exit statuses. Removing the check fails no test. A regression lets a refused
acquisition report success.

## What to add

- A test where the two counts genuinely disagree and the window is refused. This should be driven by
  real tooling rather than a fake, because a fake reproduces the original problem. The malformed
  fixture already in the branch proves a real discrepancy is reachable, since an out-of-range
  genotype quality normalizes to missing.
- Negative tests for the window set: one missing, one duplicated, one reordered.
- A negative test for the completeness flag, or make it a constrained literal so decoding catches it.

## Related

The only test that exercises real genomics tooling never runs in CI, because the workflow does not
install it. That is why this gap was invisible: the checks that need real tools to falsify them are
exactly the ones no automated run ever reaches. Installing the tooling in CI would be the structural
fix. Note also that the skip guard only asks whether the tool exists while the test asserts an exact
version, so a contributor with a different version gets a hard failure rather than a skip.

## Two things the work turned up

**The comparison exists twice, and that matters for how you test it.** Once on the preparation path,
once in the deep replay that confirms a refusal reproduces. Perturbing only the first gives
`refused count failure is not reproduced` — a *different* error, which would have looked like a
passing test while proving nothing about the comparison. Both are patched in the test, so one case
covers both sites. Anyone adding a third copy should know this.

**A disagreement is a refusal, not an exception.** I first wrote the test expecting a raise. The
real contract is better: status `refused`, `complete` false, and the window carrying reason
`native_mismatch`. The test asserts the reason reaches the ledger rather than merely that something
failed.

**There is a control test, deliberately.** The same fixture, the same run, nothing perturbed, must
succeed. Without it a refusal caused by anything unrelated would look exactly like the check
working — which is a milder version of how the original gap survived.

## Why the gap survived, for the record

The end-to-end tests replace the native counter with a stand-in whose totals are derived from the
same fake genotype stream they are compared against. The two could never disagree. A fake cannot
falsify a comparison it was built from.

That is worth remembering beyond this branch: whenever a test substitutes one side of an
independence check, the check stops being independent inside that test.
