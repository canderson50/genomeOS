## Body

## Problem

The Part C reviews (#406, PR #437) parked several test-hardening gaps. None affects the deploy or the published data, because the live deploy gate checks every object. Each one would let a future regression through silently.

## Items

- [ ] **(a) Publisher branches without tests.** `scripts/publish_atlas_web.py` has two:
  - the decoded-bytes identity check in `require_identical`;
  - the post-upload `contentType`, `contentDisposition` and `cacheControl` checks in `verify_upload`.
- [ ] **(b) Unpinned path filters.** No test pins the `.github/workflows/pages.yml` path filters, including `deploy/atlas-web-cors.json`, `scripts/check_atlas_web_data.py` and `requirements.lock`.
- [ ] **(c) Vacuous step-order check.** In `website/tests/atlas-data-base-config.test.ts`, the check that the refusal step runs before the build looks the step up by name. If the step is renamed, `indexOf` returns -1 and the check passes vacuously. Assert that the index is ≥ 0.
- [ ] **(d) No-op setup step.** `actions/setup-python` in the `pages.yml` e2e job no longer does anything, because no Python step remains. Drop it, along with the matching `pages-workflow.test.ts` expectation.
- [ ] **(e) Fixture loose ends.** `website/tests/atlas-browser-fixture.ts` has an unchecked second `page.request.get`, and its `E2E_ARTIFACT_DATA_BASE` export is unused.
- [ ] **(f) Error handling in the performance harness:**
  - `website/playwright.performance.config.ts` fails with a raw ENOENT when `dist/` is missing.
  - `tests/support/atlas-data-target.ts` silently ignores `ATLAS_DATA_DIR` on a bucket build.
- [ ] **(g) Missing docs warning.** The Local development docs page doesn't warn that bucket-mode runs must keep `PLAYWRIGHT_PORT` within 4321–4323, the CORS-allowed local ports.
- [ ] **(h) Script defaults not pinned.** No test pins the defaults of `scripts/build_atlas_parity_subset.py` and `scripts/plot_surface_codec_parity.py` (`data/atlas-web`). Add a `main([])` defaults test like the e2e fixture builder's.

## Acceptance

Each item has a test that fails without its fix, or the item is removed with a stated reason.
