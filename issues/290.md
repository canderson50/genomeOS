## Body

## Problem

WP3 requires reproducible acquisition and out-of-region tests for environmental covariates, but the current campaign has no first-class assessment of the Google Earth Engine catalog. Catalog presence is not a reason to ingest a dataset. One feature family currently merits a bounded test, while other assets remain unscheduled unless they pass the same utility screen:

- `GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL`: global annual 10 m, 64-dimensional learned representations for 2017–2024, currently `DATASET_VERSION=1.1`, generated with AlphaEarth Foundations model v2.1, CC BY 4.0.
- Other environmental or accessibility assets, including products published by the Malaria Atlas Project, are examples encountered during catalog review. They are not a work queue. A named asset advances only if it has a plausible role, useful temporal support, and a reasonable prospect of adding information beyond simpler sources.

The Earth Engine catalog is an access layer, not one homogeneous license or scientific source. Every admitted asset therefore needs its own frozen identity, provenance, temporal semantics, extraction rule, and terms record.

This advances #189 WP3. It does not close #189.

## Scientific contract

### 1. Objective / claim

Determine whether Earth Engine environmental features add geographically transferable information for present-day resident allele-frequency prediction after genomic structure and simple geography are already represented.

The primary claims to test are:

1. learned Satellite Embedding features improve count prediction and calibration outside buffered training regions;
2. a candidate Earth Engine family earns extraction and benchmark cost only when it supplies information that is not already available from simpler, better-timed covariates;
3. any apparent gain is not reproduced by missingness indicators, coordinates alone, a structured negative control, or a location-fingerprint failure.

There is no default biological claim for MAP environmental or accessibility products. MAP friction/accessibility layers are modern general-purpose travel models, despite the publisher name. At most they may diagnose recruitment/sampling structure or support a separately pre-registered modern-connectivity mechanism. They are not measured migration networks, historical gene flow or malaria exposure. This source-neutral gate supersedes the older research inventory's blanket description of MAP malaria layers as a “high-priority mechanistic pilot”; that wording must not be used to schedule work.

Recent imagery may describe present-day habitat or sampling context. It must not be interpreted as historical selection, ancestry, or migration without separate evidence.

### 2. Measurable outputs and acceptance evidence

Produce a versioned candidate registry and frozen benchmark results containing:

- exact Earth Engine asset ID, publisher, dataset/model/processing version properties when present, retrieval date, CRS, nominal and empirically observed scale, band names/units, valid and available time, support, missingness, upstream dependencies, license/attribution, and content hashes for exported artifacts;
- footprint-aware summaries over each reviewed population location and `uncertainty_radius_km`, never an undocumented point lookup when a footprint is known;
- explicit temporal matching to the observation date interval, or a named fixed summary whose scientific meaning is pre-registered; no nearest-year/default substitution;
- unchanged splits comparing baseline, coordinates-only, added feature family, missingness-only, and structured negative control;
- incremental performance after genomic structure using held-out binomial log score, calibration/coverage, local contrasts, refusal rate, and buffered leave-region-out results;
- learning curves and stability across loci/regions, with rejected features recorded rather than silently dropped;
- a location-fingerprint audit for Satellite Embedding features, including performance as geographic buffers widen;
- for any environmental asset that passes initial triage, a comparison against its simpler/upstream alternative and a named mechanism;
- all dimensionality reduction or feature selection fit only inside each training fold.

Admission requires reproducible extraction plus improvement on the pre-registered out-of-region target without degrading calibration, rare/localized-allele behavior, or refusal semantics. In-region fit alone is insufficient.

### 3. Engineering component / public interface

Add an offline, source-neutral covariate extraction boundary that emits immutable tabular artifacts consumed by the existing pure fitters. The serving path continues to read precomputed surfaces and performs no Earth Engine calls or fitting.

The first implementation slice should remain small:

1. registry records and an inspection command for exact asset metadata;
2. fixture-scale extraction for one Satellite Embedding year;
3. vectorized/batched footprint reduction rather than population × band nested request loops;
4. deterministic manifests and local cache/export receipts;
5. frozen WP3 benchmark integration.

No MAP asset is scheduled merely because it exists in the catalog. Only a named asset with a unique-information argument, valid time interpretation, and simpler comparator may enter the registry or extraction path. The MAP name or a malaria-associated target locus is not enough to trigger work.

The 64 Satellite Embedding bands form one vector and must remain jointly identified. Any fold-local compression emits its fitted transform and explained-variance diagnostics as part of the benchmark artifact.

### 4. Assumptions, refusal conditions, downstream consumers

Assumptions:

- genomeOS is currently planned as an entirely noncommercial project;
- CC BY-NC-SA inputs are therefore eligible for evaluation and possible use now, subject to attribution, share-alike, and asset-specific terms;
- license metadata still records commercial compatibility independently so a future commercial component can exclude or replace incompatible assets;
- a legal/reuse review is still required before distributing derived artifacts because model outputs and dataset adaptations may be treated differently.

Refuse extraction/admission when an asset lacks an exact versionable identity, stable terms, required time coverage, a documented unit/scale, a valid value at a required footprint, or a reproducible export receipt. Also refuse when catalog labels and band metadata disagree on scale or units until the discrepancy is resolved from the asset itself.

Downstream consumers are the offline B1–B4 and N0–N2 benchmark candidates. Raw imagery/embeddings are never served as allele-frequency observations and never visually merged with measured observations.

## Candidate ordering

1. **Satellite Embedding V1 Annual** — the only Earth Engine family currently prioritized for a bounded test; CC BY 4.0; test all 64 dimensions jointly with strong regularization and fold-local compression.
2. **Simple interpretable baselines** — climate, terrain, and land-cover summaries with appropriate time support. These are the comparators an opaque or derived feature family must beat; prefer the simplest qualified source.
3. **MAP-published environmental/accessibility assets** — no planned ingestion by default. EVI/LST/TCB/TCW appear largely substitutable with simpler climate or land-cover sources. Modern friction/accessibility surfaces are poor default predictors for historical population genetics and carry substantial location-fingerprint risk. Reconsider one only for a named sampling-bias or modern-connectivity question with a pre-registered comparator. Malaria prevalence or transmission products would require a separate, target-specific selection hypothesis and source-overlap audit; the publisher name alone supplies neither.
4. **European crop maps** — regional hypothesis/control only, not a global default; qualify the exact 2018/2022 asset and license before use.

- [ ] Extraction is fixture-tested, deterministic, vectorized/batched, and produces immutable manifests.
- [ ] Satellite Embedding completes the frozen baseline/add-family/missingness/control comparison.

### bschilder, 2026-09-17T21:56:35Z (https://github.com/genomeOS/genomeOS/issues/290#issuecomment-5721769545)

Corrected design preflight for the next extraction slice:

- One calendar year is a tiled `ImageCollection`, not one global image. The catalog says each source image covers approximately 163,840 m × 163,840 m and is generated in its local UTM projection. Therefore `.filterDate(...).filterBounds(...).first()` is valid only for a point-like catalog demo; it is not a complete footprint extractor.
- The bounded first fixture should select one exact source image by immutable image identity and include several reviewed footprints wholly contained in that image. One server-side `Image.reduceRegions` call can then reduce the complete fixture `FeatureCollection`; it is not necessary to issue population × band requests.
- A single-input reducer is replicated across image bands. Combining mean, standard deviation, and count with `sharedInputs=true` computes all requested summaries in one pass over the pixels.
- The resulting `FeatureCollection` can be submitted as one `Export.table.toCloudStorage` batch task. The receipt must retain the task/operation ID, exact selectors, destination prefix, task state, exported object identity, size, and content hash.
- The implementation must set scale and CRS explicitly and must retain `tileScale`/`maxPixelsPerRegion` in the manifest. It must not use `bestEffort` to silently change effective resolution.
- A later global extractor must batch by exact source tile/UTM projection or define and validate an explicit mosaic/reprojection and overlap policy. It may not silently take the first intersecting tile, double-count overlap pixels, or treat a mosaic's default projection as scientific metadata.

Official references:

- https://developers.google.com/earth-engine/apidocs/ee-image-reduceregions
- https://developers.google.com/earth-engine/guides/reducers_intro
- https://developers.google.com/earth-engine/apidocs/export-table-tocloudstorage

Access/cost preflight:

- Earth Engine requests require a registered Cloud project, including noncommercial use. Python initialization must name that project explicitly.
- Verified noncommercial projects now use monthly EECU quotas. The default Community tier provides 150 EECU-hours; Contributor provides 1,000 EECU-hours and requires a billing account, although Earth Engine use remains uncharged while the project stays registered noncommercial. Noncommercial status requires periodic reverification.
- A real extraction receipt should record the project registration class/tier and pre/post usage evidence without storing account identity, access tokens, application-default credentials, or service-account keys.

Official access references:

- https://developers.google.com/earth-engine/guides/auth
- https://developers.google.com/earth-engine/guides/access
- https://developers.google.com/earth-engine/guides/noncommercial_tiers
