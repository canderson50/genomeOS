## Body

The single design-constrained hardware-seam attempt for the short-support scorer completed with honest `UNSUPPORTED` outcomes, but it exposed two controller/evidence gaps that must be repaired before any separately authorized successor attempt.

## Scientific objective

Determine whether the unchanged public CuPy CDF path can expose the accepted physical object/transfer evidence. The completed attempt did not test that question: S2 stopped during environment/import/installed-wheel preflight before `public_attempt`, and S1 remained the expected static refusal. Preserve this as an unsupported feasibility result; do not reinterpret it as numerical failure or lack of GPU support.

## Measurable output and acceptance evidence

Produce a new, versioned, independently reviewed probe/controller package that:

- records bounded, typed preflight checkpoints sufficient to distinguish the accepted meta-path finder check from installed-wheel/version/RECORD/source validation failures without retaining tracebacks, frames, secrets, or arbitrary exception graphs;
- preserves exact one-shot accounting, fixed S1/S2 order, unchanged public CDF call, source/wheel/image hashes, output limits, and all refusal behavior;
- launches an independently persistent deletion watchdog whose liveness is verified after its creating process exits, with durable deletion and absence receipts;
- receives source and controller review before any new hardware attempt.

A successor hardware result must still be `UNSUPPORTED` unless every accepted S2 identity, call, array, transfer, completion, and cleanup join is observed. No retry, replacement computation, new numerical path, or relaxed evidence condition is accepted.

## Engineering component and interface

Limit changes to the private hardware-seam runner/controller and their recording tests. Add explicit preflight events around the existing finder and installed-wheel checks, and a control-plane watchdog handoff whose process lifetime does not depend on the invoking shell/tool session. The scientific scorer and production routing remain unchanged.

## Assumptions, refusals, and downstream consumer

The retained attempt is immutable and independently audited. It contains no `installed_distribution`, `device`, `original_callable`, `public_attempt`, transfer, arithmetic, output, or cleanup-sync event. The most specific supported cause is a preflight `ValueError`; naming a particular finder or wheel would invent evidence. The attempted local watchdog did not persist, although manual retrieval, deletion HTTP 204, and absence HTTP 404 completed 380.99 seconds after creation, within the 660/720/900-second deadlines.

The consumer is the independent reviewer deciding whether one new bounded hardware feasibility attempt is admissible. This issue does not authorize that attempt by itself and does not reopen accepted numerical qualification.
