## Body

## What

`scripts/check_private_files.py` is a mandatory pre-commit gate, but it passes a tracked file containing a hardcoded personal home directory. Found in review of #188, and **verified empirically** rather than inferred: run against that PR's head the gate reports `private-file check passed (619 tracked files)`, exit 0, while `scripts/build_hbb_salih_fixture.py:43` contains

```python
PAYLOAD_DIR = Path("C:/Users/Bola/.hermes/genomeos/hbb-rs334/payloads")
```

## Why the gate misses it

The checker matches two things: secret-shaped regexes (PEM blocks, `gh*_` / `github_pat_`, `AKIA…`, `AIza…`, `xox*-`, `sk-…`) and forbidden *path components* of the files being scanned (`.codex`, `.agents`, `.env`, …). A personal path that appears as a **string literal inside** a tracked file is neither. The gate is checking which files are tracked, not what they say about someone's machine.

## Why it is worth closing

Two distinct harms, and the second is the surprising one.

**Privacy.** It commits a personal machine path and an inferable OS username to a public repo permanently. Not a credential, so not urgent, but it is exactly the class of thing this gate exists to keep out, and AGENTS.md lists "personal caches" among what must never be committed.

**It also breaks portability in a way that is silent.** `Path("C:/Users/...")` is **not absolute on POSIX** — `pathlib` treats `C:` as an ordinary relative segment. So a `mkdir(parents=True)` on it creates a junk `./C:/Users/<name>/...` tree inside the working copy, unignored and stageable, with no error and no warning. A gate that caught the string would have caught the portability bug for free.

## Suggested check

Scan tracked text files for absolute-home-directory shapes, and fail with the file, line and matched text:

- `C:/Users/<name>` and `C:\Users\<name>` (any drive letter, either separator)
- `/Users/<name>/` where `<name>` is not a placeholder
- `/home/<name>/`
- `%USERPROFILE%`, and `~/` only where it is clearly a literal rather than documentation

Two things to get right so it does not become noise:
1. **Allow documentation and examples.** AGENTS.md itself, `docs/`, and `.env.example`-style templates legitimately show paths. Either skip those trees or require an obvious placeholder (`<user>`, `youruser`, `$HOME`).
2. **Make the failure actionable.** Print the offending line, not just the filename, and say what to do instead — `argparse` with a git-ignored relative default, which is what every other `scripts/build_*.py` already does.

## Acceptance evidence

- The gate fails on a file containing `Path("C:/Users/Bola/...")`, naming file, line and match.
- The gate still passes on `main` as it stands today, and on legitimate placeholder paths in `docs/` and `.env.example` templates.
- A regression test with one fixture file per accepted shape and one per allowed placeholder.
