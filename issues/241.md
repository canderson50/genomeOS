## Body

## Confirmed invariant violation

`aggregate_raster_to_h3` silently turns a finite negative population count that
is **not** the raster's declared nodata into a valid zero-population H3 cell.
This violates the fail-closed/no-silent-coercion contract and conflates malformed
denominator evidence with a measured/modeled zero-population value.

Observed in current original checkout source (last relevant commit
`813edd05b0ffe6ba4bfe241cb361ff797554a5de`) and identical modeling-branch source:
`genomeos/geo/population.py` SHA256
`8143e722f49809ebc9263f9bd5b5b4e0d8c7d6e32e5cc17cc4c6ecb155423299`.
No dirty change touches this file. This diagnosis does not establish that any
published WorldPop artifact contains such malformed values.

## Minimal reproduction

Run from the repository with the locked atlas/geo environment. It creates four
one-pixel synthetic rasters in memory only; no dataset download or file write:

```python
import numpy as np
from affine import Affine
from rasterio.io import MemoryFile
from genomeos.geo.population import aggregate_raster_to_h3

for value in (7.0, 0.0, -1.0, -9999.0):
    with MemoryFile() as memory:
        with memory.open(
            driver="GTiff", height=1, width=1, count=1, dtype="float32",
            crs="EPSG:4326", transform=Affine(0.1, 0, 3, 0, -0.1, 8),
            nodata=-9999.0,
        ) as raster:
            raster.write(np.array([[value]], dtype="float32"), 1)
        grid = aggregate_raster_to_h3(
            memory.name, 4, source_version="synthetic-negative-audit",
            coverage_stride=1,
        )
        print(value, grid.cells.to_dict("records"), grid.pixels_nodata)
```

Observed (2026-09-10; exit0):

| Input | Output population | Nodata pixels |
| --- | --- | --- |
| 7 | 7, one valid cell | 0 |
| 0 | 0, one valid cell | 0 |
| -1 (not nodata) | **0, one valid cell** | **0** |
| -9999 (declared nodata) | no cell | 1 |

Expected: `-1` must raise a clear validation error before emitting a grid;
explicit declared nodata remains excluded and a valid zero remains valid zero.
`publication_target_cells` subsequently accepts the malformed-derived zero grid
(with no positive targets), so its negative-value check cannot recover the lost
input distinction.

## Cause and bounded acceptance

`valid` at line174 means finite and unequal to nodata. `valid & (block <= 0)` at
line195 then routes negative values into the zero-coverage branch. Existing
tests cover positive, zero and nodata but not undeclared finite negative counts.

Add an isolated failing regression for this case, refuse undeclared negative
counts at raster ingress, and retain existing zero/nodata/count conservation
behavior. No automatic clipping, inferred nodata, or change to clinical parity
denominators. This is a separate bounded follow-up, not a reason to halt B0H work.

Related: #43 (completed denominator implementation), #189 (WP3 qualification).
No production fix made by this diagnostic.
