## Body

## TL;DR

The global allele-frequency benchmark pods were reported as running by RunPod, but four pods using our custom `sleep infinity` startup command never provided usable SSH. No benchmark data was uploaded and no model ran. A diagnostic pod using the same official image and SSH settings connected immediately when the custom command was omitted, which justifies testing the default command on A100; because the diagnostic used a different RTX PRO 4500 host, it does not prove unique causation or qualify A100 transport.

## What happened

The B0H comparison controller created four A100 pods across M12–M15. Each provider response reported `RUNNING`, but the public SSH endpoint remained unreachable for 41–42 probes over 902–914 seconds. The controller correctly proved that execution was absent, preserved receipts, and deleted every pod.

The shared launch configuration passed:

```text
--docker-args '/bin/bash -lc "sleep infinity"'
```

A no-data diagnostic held the image, `--ssh`, and `22/tcp` exposure constant while omitting `--docker-args`, but used a different RTX PRO 4500 host. Both the RunPod-managed key and the campaign key completed an SSH `true` command immediately. The diagnostic pod was then deleted and final inventory was empty. This proves default-command SSH startup on that diagnostic pod and supports an A100 trial; it does not prove that Docker arguments uniquely caused the earlier failures or that A100 transport will work.

Sanitized local evidence: original receipt `data/research/b0h-ssh-diagnostic-20260920/receipt.json` (SHA-256 `c5369dc3888a2d04e71fce81e29c9fd1a1e6d55a88920f9069acb03b82fcc916`) and its scope correction `receipt-v2.json` (SHA-256 `55d5fccc240bf636dfa8e1afcf8d16ee96b7794887581f7f0700c03d9024309d`).

## Scientific objective and acceptance evidence

The objective is to execute the frozen 24-run HbS comparison across cohort stage, count definition, prior choice, and random seed without changing the scientific plan.

Acceptance requires a reviewed transport profile that:

- preserves the official image, SSH exposure, secrets handling, placement order, immutable inputs, and frozen scientific plan;
- omits the custom Docker command and lets the official image start normally;
- successfully completes an authenticated SSH command before any upload;
- uploads and verifies the admitted bundle, starts the remote process, retrieves checksum-verified results, and deletes every pod;
- refuses recovery records from the old transport profile and leaves no campaign pod allocated.

## Engineering interface

The affected interface is the offline RunPod comparison controller's pod specification and `runpodctl pod create` argument builder. The corrected transport profile must be explicit in launch, recovery, and reconciliation receipts so records produced under the broken profile cannot authorize a corrected-profile continuation.

## A100 trial update

The first corrected-profile A100 trial reused `US-MD-1` candidate a011 and completed authenticated SSH on its first probe after 24 seconds. This establishes that default image startup works on A100 and resolves the original SSH blocker.

The next boundary then failed: three SCP-plus-separate-SSH verification attempts did not publish the 18 MB bundle. The later provider readback also omitted `gpuTypeId`; the controller refused authority rather than filling it from the request. Direct inspection found the expected remote project root absent, no execution occurred, and the pod was deleted with final inventory empty.

A different-GPU diagnostic streamed the exact 13-member seed-42 bundle and performed receive, extraction, checksum verification, and atomic publish in one SSH connection. A follow-up checksum verification passed. This qualifies single-connection streaming for an A100 trial; it does not identify the cause of the A100 upload failure or qualify A100 transport/science. Sanitized receipt: `data/research/b0h-upload-diagnostic-20260920/receipt.json` (SHA-256 `f2ed6fc0ea745034a13803c1509d12fe17d2df259e38f1a023babe9514d6e5f6`).

## Assumptions and refusal conditions

- The official RunPod PyTorch image provides its normal SSH startup when its default command is preserved.
- Prior placement exclusions describe the broken startup profile and must not be generalized to the corrected profile.
- Any missing or inconsistent transport-profile identity, provider response field, history record, receipt, or deletion proof remains a hard refusal.
- No scientific result may be published until all 24 runs and their postprocessing artifacts pass the existing admission, convergence, and provenance gates.
