## Body

## What

The module docstring in `genomeos/observations/sources/afnd_frequencies.py` states:

> The frequency is printed to four decimal places, which bounds the reconstruction error at `0.00005 * 2n` — under half an allele for any sample below 10,000, so the recovered integer is almost always exact.

Measured against `data/raw/afnd_frequencies.tsv` (123,502 rows), **10,040 rows carry more precision than 4 dp** — rare HLA alleles printed to 7 dp:

```
group gene   allele  alleles_over_2n
hla   A     A*01:02  0.0000980
hla   A     A*01:02  0.0000050
hla   A     A*01:03  0.0000580
```

All 10,040 are in the `hla` group.

## Impact

**The science claim is safe.** More printed precision means *less* reconstruction error, so the stated `0.00005 * 2n` bound is conservative rather than violated for those rows. Nothing published is wrong because of this.

**The factual claim is not, and it actively misleads.** The 4-dp premise is what made a fixed-precision identity format (`f"{af:.4f}"`) look like a safe canonical improvement in #228. It is not: it collapses `0.0000980` and `0.0000900` onto one `source_record_id`, and formats a real observed rare allele to `0.0000`. The proposal was rejected on that evidence, but only because the corpus was measured rather than the docstring trusted.

## Suggested fix

State the range rather than a single precision, and keep the error bound tied to the *worst* case, which is what makes it a bound:

- most rows print to 4 dp, which is what sets the `0.00005 * 2n` bound;
- ~8% of rows (all HLA) print to 7 dp, where the bound is correspondingly tighter;
- so the 4-dp figure is the conservative worst case across the corpus, not a description of every row.

Worth adding the one-line warning that a fixed-decimal format must never be used for an identity or an equality comparison on this column, since that is the mistake the current wording invites.

## Acceptance evidence

The docstring states a precision range consistent with the corpus, and a reader cannot come away believing every value is 4 dp. No code change.
