## Body

## Invariant violated

P1 stores measured integer counts and explicit date bounds. Schema violations must be hard errors;
they must not silently turn fractional values into different evidence. This also undermines
modern-only research guards when a fractional nonzero date becomes the legacy zero sentinel.

## Reproducer

On Python 3.12.13 / pandas 3.0.5 / pandera 0.32.1, using the existing synthetic test helper:

```python
import sys
sys.path.insert(0, "tests")
from test_observations_schema import _row
from genomeos.observations.schema import OBSERVATIONS_SCHEMA

for field, value in [("ac", 12.9), ("an", 200.9), ("date_lower", 0.5)]:
    result = OBSERVATIONS_SCHEMA.validate(_row(**{field: value}))
    print(field, value, result[field].iloc[0])
```

Observed output:

```text
ac 12.9 12
an 200.9 200
date_lower 0.5 0
```

Expected: fail loudly on noninteger values before lossy dtype conversion. Integral values and
documented lossless input coercions should remain explicit and tested; Boolean values must not
masquerade as counts or dates. Check the analogous carrier schema as well.

The root cause is schema-level `coerce=True` plus integer columns: coercion happens before the
nonnegative and cross-column checks, so those checks see already truncated evidence.

## Scope and acceptance evidence

Track the shared P1/frozen-contract fix here. Do not casually disable all coercion or add a
permissive option. Any schema change must regenerate `contract/` and preserve source round-trip
tests. Add negative tests for fractional AC/AN/date bounds, their lossless integral equivalents,
Boolean values and boundary/missing values.

The #189 benchmark will add an explicit pre-coercion refusal at its input boundary so it cannot
score these changed counts or call a truncated date modern. That narrow benchmark safeguard does
not claim to resolve the shared P1 schema issue, and does not alter existing source data/artifacts.
