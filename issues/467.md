## Body

## Problem

The Python publication pipeline (`export_atlas_web.py` → `encode_atlas_web.py` → `publish_atlas_web.py`, plus `encode_natural_earth_borders.py`) and the website's Atlas client share a data format: `catalog.json`, the GOSA surface objects, the canonical surface/observations JSON, the external caches and the GOBD borders. Nothing names a version for that format as a whole. The catalog carries `schema_version: 1`, and GOSA and GOBD each have a u16 `format_version` slot, but there's no rule for which change bumps what. The strict zod contract means every catalog change, including a purely additive one, has to land in Python and TypeScript together.

Since August, 14 of the 34 commits that touched `website/` also had to change Python. If the repository is ever split into a science repo and a web repo, an explicit, checked format version is the prerequisite for that.

## Contract (AGENTS "Scientific contract before implementation")

1. **Claim.** The site never renders a catalog it can't read correctly. An incompatible catalog fails loudly, both at build time and in the browser; it is never silently coerced. A backward-compatible (additive) producer change no longer forces a lockstep client change.
2. **Measurable output.**
   - `catalog.json` declares `format_version` as `"MAJOR.MINOR"`.
   - The TypeScript client refuses an unknown MAJOR with a dedicated error, and accepts a newer MINOR by ignoring catalog keys it doesn't know.
   - Python writers emit exactly the current version and refuse to write anything else.
   - Python readers (publisher, deploy gate) refuse an unknown MAJOR, or a MINOR newer than the one they know.
   - A cross-language test proves the Python and TypeScript constants agree with each other and with the committed catalog.
3. **Interfaces.**
   - Python: a new pure module `genomeos/publication/web_format.py`, called from `export_atlas_web.py`, `encode_atlas_web.py` and `web_layout.py`.
   - TypeScript: a new module `website/src/atlas/format-version.ts`; `parseAtlasCatalog` in `contracts.ts`, used by `catalog-build.ts` and `static-provider.ts`.
   - Docs: `docs/web-data-format.md`, linked from AGENTS.md and amending fast-load design 2026-10-07 §B.4.
4. **Assumptions, refusals and consumers.**
   - Rollout must not re-upload the published GCS objects. The version lives in the committed catalog, which is deployed with the site (§B.4 ruling). Per-object version slots (GOSA/GOBD `format_version`, JSON `schema_version`) are left as they are and pinned by the format MAJOR.
   - There's no "missing field = 1" default: a catalog without `format_version` is refused.
   - Consumers: the `/app/` build and runtime, `publish_atlas_web.py`, `check_atlas_web_data.py`, and the e2e, golden and parity fixture builders.

## Acceptance

- Tests on both sides, including the refusal paths: unknown MAJOR, malformed or missing version, a newer MINOR with an unknown key accepted, and a writer refusing a non-current version.
- The Python and website gates pass; the pages deploy gate still passes against the unchanged bucket.

Spec: fast-load design 2026-10-07 §B.4 and §C.2 (`docs/superpowers/specs/2026-10-07-atlas-mobile-fast-load-gcs-design.md`); Atlas design §11, §12.
