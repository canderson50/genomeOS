## Body

## TL;DR

Our contributor guide lists the checks you should run before opening a pull request, but it only
lists the Python ones. CI also runs three checks on the website, and if you have not memorised them
you find out by getting a red build. That happened to me on #295 over a formatting rule.

Adding three lines to the command list would fix it.

---

## What is missing

`AGENTS.md` has a "Commands" section headed "Current, and what CI must keep passing". It lists
`ruff`, the contract freeze check, the module-size check, the private-file check, the smoke script
and `pytest`. CI additionally runs, in the `validate` job:

```bash
cd website
npm run format:check   # prettier
npm run check          # astro check / TypeScript
npm test               # vitest
```

## Why it matters more than it looks

The website contract in `website/src/atlas/contracts.ts` is one half of a two-sided agreement with
the Python exporter — a change to a published payload has to land in both, and the TypeScript side
is only verified by these commands. Someone who runs the documented gate list and sees green can
still be one contract short.

On #295 the typecheck caught three test fixtures missing a newly required field, which is exactly
the gate doing its job. I only ran it because I happened to know it existed.

## Suggested fix

Add the three commands to the same block, noting they run from `website/`. `CONTRIBUTING.md` points
at `AGENTS.md` for the gate list, so one edit covers both routes in.
