**CPU vs CuPy timing for count scoring, using `scripts/profile_count_scoring.py`**

I ran the existing profiler on synthetic inputs to answer when `--cdf-backend cupy` is worth using. These numbers measure speed only. They say nothing about model accuracy or allele frequencies, and they're not publishable.

**Setup:** source `f3357ce` (main), RunPod Secure Cloud **NVIDIA A40** (compute 8.6, CUDA runtime 12.9), CuPy 14.2.0, SciPy 1.18.1, NumPy 2.4.6, Python 3.12.15. Every size used `--repeats 1 --seed 42`, with a 25-minute cap per size. Each timing builds `CountPredictive` and runs the full `predictive_diagnostics`. GPU times include host/device transfers and synchronisation.

| Draws × observations, AN, concentration | CPU first | CPU warm | GPU incl. first-run setup | GPU warm | Warm speed-up | CPU/GPU parity |
|---|---|---|---|---|---|---|
| 200 × 100, AN 200, c 20 | 150.9 s | 148.8 s | 15.7 s | 1.85 s | **80×** | passed |
| 200 × 100, AN 2000, c 20 | 272.1 s | 272.7 s | 6.3 s | 5.84 s | **47×** | passed |
| 200 × 100, AN 200, c 5000 | 153.8 s | 154.0 s | 2.5 s | 1.87 s | **83×** | passed |
| 500 × 300, AN 200, c 20 | did not finish within the 25-min cap (CPU side) | — | — | — | — | — |
| 2000 × 1505, AN 2000, c 20 (the real workload shape in `test_cupy_chunk_plan…`) | did not finish within the 25-min cap (CPU side) | — | — | — | — | — |

Parity covered diagnostics within `atol=1e-11`, exact count quantiles at 0.025–0.975, and sampled counts. It passed at every completed size. The largest extra GPU memory sampled was about 250 MB, at AN 2000.

**Reading:**
- At every completed size, CuPy was 47–83× faster when warm, and still about 10–100× faster counting first-run setup.
- At the real workload shape, the CPU side alone didn't finish within 25 minutes.
- For any run with a GPU, `--cdf-backend cupy` looks like the right default. The high-concentration path gains as much as the standard one.

**Limits:**
- Each size is a single repeat on one A40.
- CPU times depend on the pod's CPU, which I didn't record or optimise, so a fast many-core CPU would narrow the gap.
- The two largest sizes have no GPU timing, because the profiler always times CPU first and that hit the cap. An option to skip or limit the CPU side would let those be measured. I can open that as a small PR if it's useful.
