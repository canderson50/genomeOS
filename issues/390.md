## Body

## TL;DR

A spatial-activity fit can finish successfully and then leave the GPU idle while one CPU core
spends many minutes calculating exact count intervals. The activity predictor currently calls
SciPy's generic beta-binomial CDF, which constructs every integer from zero to the queried count.
That is unusable for this campaign's denominators, which reach 2,571,112. Reuse the repository's
bounded count-probability implementation and its CuPy path without changing the statistical
distribution or approximating the result.

## Trigger and measured evidence

During the registered three-task simulation probe for #384, the strong-signal candidate completed
NUTS and entered prediction with no registered convergence retry. GPU utilization then fell from
about 97% to 0%, while the Python process held one CPU core for more than eight minutes and did not
write its task artifact. The scorer was interrupted after the convergence decision was already
known; the incomplete task artifact was not retained.

The path is `ActivityCountPredictive.quantiles -> _cdf_matrix -> scipy.stats.betabinom.cdf`.
Inspection of the installed SciPy implementation shows that `rv_discrete._cdf_single` executes
`arange(0, k + 1)` and sums the PMF. This bypasses the bounded beta-binomial CDF implementation and
optional CuPy backend already used by `CountPredictive`.

## Scientific objective and claim

Compute the same analytically marginalized activity/beta-binomial count distribution at bounded
memory and practical runtime. This is an implementation correction only. It must not change the
model, priors, simulated truth, split identities, sampler results, decision thresholds, or the rule
that observed zeros remain compatible with both latent states.

## Measurable output and acceptance evidence

- Exact CPU-reference and CuPy parity for mixture mass, CDF, quantiles, coverage, and randomized
  PIT, including `q=0`, `q=1`, interior activity probabilities, `AC=-1`, zero/all counts, heterogeneous
  denominators, and the documented million-scale count domain.
- No allocation or work proportional to the full `0..AN` support. Temporary memory must be bounded
  by explicit draw/row/support chunks.
- A complete-workflow hardware profile on an actual CUDA device, including cold and warm runtime,
  transfers, peak-memory semantics, and numerical discrepancies.
- The offline campaign manifest records the chosen diagnostic backend. Missing CUDA must fail
  before sampling when the GPU backend is requested; there is no silent CPU fallback.
- Existing `ActivityCountPredictive` behavior and all frozen scientific gates remain unchanged
  within declared numerical tolerances.

## Engineering component and public interface

Add a focused weighted activity-mixture CDF backend under the validation boundary, preferably by
extending the existing bounded `predictive_cupy.CuPyCDF` contract rather than creating another
special-function stack. Route `ActivityCountPredictive.cdf` and `quantiles` through an explicit
typed backend choice. Keep file/network/RunPod orchestration outside science modules.

## Assumptions, refusals, and downstream consumers

- Do not replace the exact beta-binomial mixture with a normal, binomial, Monte Carlo, or truncated
  support approximation.
- Do not use a faster score to rescue the already failed target-acceptance-0.90 campaign; its
  nonconvergence evidence remains unchanged.
- Do not launch the 720-task replacement campaign until actual-device parity and complete-workflow
  timing pass on the exact merged source and frozen manifest.
- The immediate consumer is the #384 simulation preflight. This advances #189 but does not permit a
  real HbS fit or publication.

A spatial-statistics reviewer should confirm that the weighted mixture CDF is exactly
`mean((1-q) + q*F_beta-binomial)` for nonnegative count thresholds and zero at `AC=-1`.
