## Body

## What

`genomeos/observations/sources/afnd_carriers.py` reads the sample size in three inconsistent
forms, the same defect fixed for `afnd_frequencies.py` in #160. Found while reviewing that PR;
the reviewer asked for the sibling to be tracked separately rather than widening #160's scope.

On current `main`:

- **line 128** — the duplicate check compares the parsed float:
  `presence.duplicated(subset=["group", "gene", "allele", "population", "carrier_fraction", "n_indiv"])`
- **line 140** — the canonical value silently rounds:
  `n_individuals = rows["n_indiv"].round().astype(int)`
- **line 154** — the identity hashes a third conversion:
  `stable_source_record_id("afnd-carriers", gene, population, fraction, int(n))`

## Why it matters

Two consequences, both of which #160 established as defects in the frequency adapter:

1. **Silent truncation of malformed scientific input.** A non-integral `n` is rounded into a
   sample size the source never published, contrary to the fail-closed schema invariant in
   AGENTS.md ("Never silently drop a row, coerce a bad value, or substitute a default").
2. **Identity collision that rejects both rows.** Two otherwise identical rows whose sample
   sizes differ only fractionally survive the float duplicate check but hash to one
   `source_record_id`, so pandera's `unique=True` then rejects the pair rather than the
   duplicate — the failure mode of #154.

Note `.round()` here is worse than `afnd_frequencies.py`'s pre-fix `int(n)`: rounding maps
`100.5` to `100` **and** `101`-adjacent values inward, so the invented denominator can differ
from the printed one in either direction.

## Not yet reproduced

The line-level analysis above is confirmed by reading `main`. I have **not** run a two-row
reproduction against this adapter, so the collision is inferred from the identical code shape
rather than observed. First step is to write that reproduction, mirroring
`test_sample_sizes_differing_only_by_a_fraction_cannot_collide_into_one_identity` from #160.

## Suggested fix

Port #160's pattern rather than inventing a second one:

1. `refuse(presence["n_indiv"].notna() & (presence["n_indiv"] % 1 != 0), "fractional_sample_size")`
   on the raw parsed float, before any cast and before the duplicate check, so the row is
   reported for its actual defect.
2. Build one `n_individuals` `Int64` column after the safety checks, and read only that in the
   duplicate check, the carrier-count reconstruction, and `stable_source_record_id`.
3. Drop the now-redundant `.round()`.

## Acceptance evidence

- A fractional sample size is refused as `fractional_sample_size`, not rounded.
- `retained + sum(refusals) == total` still holds (§12).
- Two rows differing only fractionally in `n` do not collide; `OBSERVATIONS_SCHEMA` validates.
- The pinned `source_record_id` digest test, if one exists for this adapter, is unchanged —
  `str(np.int64(100))` equals `str(int(100.0))`, so integral inputs must hash identically.

## Also worth checking

`afnd_cytokines.py` was checked in #160 and is **not** affected: it iterates
`cyt.groupby(["locus", "population"])`, emitting exactly one record per group, so its narrower
key is unique by construction. These three are the only callers of the helper.
