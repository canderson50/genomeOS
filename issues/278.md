## Body

The accepted E4 runtime globally requires qualified GPU process attribution before any ledger or CPU worker can be created. This conflicts with the original frozen protocol: when requested GPU attribution is unavailable, retain all 24 GPU rows as `unstarted_unavailable`, permit the already planned CPU stream after its own qualification, and keep the joint result incomplete.

Evidence is a read-only source/contract audit, not a newly executed CPU measurement. The original rationale E4 section explicitly specifies this behavior. `e4_runtime_v8` reexports `e4_runtime_v6.load_manifest`, which requires `process_attribution.status == qualified_target`, host proc namespace/qualification fields, and qualified NVML metadata globally. The final guardian calls that loader before output/ledger creation. The CPU adapter itself uses local proc identity and skips NVML, so the dependency is not needed by CPU measurement.

The intentionally execution-disabled template and the retained third GPU run's `source-review manifest cannot execute` refusal are correct; they must not be modified or relabeled. This bug concerns the missing truthful executable-manifest availability branch, not that historical refusal.

Scientific/engineering objective: obtain valid planned CPU cost observations without inventing GPU qualification or claiming a complete joint benchmark. Add an explicit, versioned, evidence-bound GPU-unavailable outcome; preserve the original requested CPU+GPU plan of 60 rows (36 CPU, 24 GPU), source/native/input bindings, 600-second total/60-second call deadlines, RSS limits, external guardian, full diagnostics workload, immutable evidence and nonzero incomplete result. Qualified GPU execution must retain every existing host-identity/UUID/NVML check.

Acceptance:

- Exercise the actual final loader/guardian/factory/runner wiring with a valid common/CPU contract and explicit GPU-unavailable evidence. Keep all 60 rows, run no GPU worker/context/provider, preserve CPU row order and unchanged preflight, and retain 24 GPU `unstarted_unavailable` outcomes.
- Record the unavailable transition durably before worker startup. Do not misuse generic worker-failure accounting or invent cleanup for a worker never created. Actual spawned-worker failures retain their existing cleanup obligations.
- Missing/common-invalid source/native/input bindings, changed schedules/limits, malformed or mixed availability states, absent refusal evidence, or GPU dispatch under unavailable status fail closed.
- Preserve cap/interruption/evidence-loss accounting and CPU cleanup. Keep the complete-success reconstruction strict: partial CPU evidence cannot become a successful 60-row reconstruction or a speedup/scientific-acceptance claim.
- Focused regression evidence and smoke, then independent review before any runtime execution. Numerical E1-E3 source, oracles, thresholds and accepted results remain unchanged.

Advances #189 and the existing count-scoring qualification effort. Public scorer integration, GPU cost qualification, calibration and real model comparisons remain separate gates.
