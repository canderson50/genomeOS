## Body

## TL;DR

The public data store (#468) works, but two things need the owner: how people find its URL, and a budget alert on its egress.

## 1. How people find the base URL

Readers need `GENOMEOS_DATA_BASE_URL`, of the form `https://storage.googleapis.com/<bucket>/`. Under the repository rule (`docs/repo-gcloud-auth.md`), no bucket name is committed, so a fresh clone cannot discover it from git alone. The options:

- **(a) Keep the rule. Publish the URL at deploy time**, from a repository variable, on the site's docs page and in release notes. Optionally the site could serve a small `data-store.json` pointer that `scripts/fetch_data.py` reads from the already-public site domain. This costs nothing; it needs a small site and `pages.yml` change.
- **(b) Custom domain `data.genome-os.org`.** HTTPS needs the load balancer and managed certificate already scripted for the web bucket (`provision_atlas_web_bucket.py --mode cloud-cdn`), plus a DNS A record at the registrar. That is a human step with a recurring load-balancer cost. A plain CNAME to `c.storage.googleapis.com` would serve HTTP only.
- **(c) Carve an exception to the rule** for this one public bucket's URL, so README and `docs/data-store.md` can name it.

No DNS was changed.

## 2. Egress and a budget alert

The release is about 0.27 GB. Internet egress from us-east1 Standard storage is roughly $0.12/GB, so one full download costs about $0.03 and 1,000 full downloads about $30. Storage costs well under $0.01 a month.

Setting a budget alert on the project needs billing permissions, so it is an owner step. Requester-pays is not used, because it would require readers to have credentials.

## 3. Smaller follow-ups (optional)

- A cheap CI check of the newest manifest against the bucket, once a repository variable holds the URL: for example HEAD plus `x-goog-meta-sha256`.
- Set repository variables `GENOMEOS_DATA_BUCKET` and `GENOMEOS_DATA_BASE_URL`, as was done for the web bucket.
- Record a data licence for project-authored data and model outputs. The README's Apache-2.0 notice covers only code and docs, and the manifest records this as `not_checked`.

## 4. Cache lifetime of data-store objects

This was raised by a security review after the upload.

Release 2026-10-17 is uploaded with `Cache-Control: public, max-age=31536000, immutable`; all 246 objects carry it. The keys are immutable, so the year-long cache is safe for correctness. The cost is takedowns: GCS edge caching can't be invalidated, so if an object ever had to come down, cached copies could keep being served for up to a year after it was deleted. That matters most for a `not_checked` source such as MAP or WorldPop that turned out to restrict redistribution.

The objects were **not** changed. The options:

- **(a)** Keep the year-long cache.
- **(b)** Use `public, max-age=3600` for future releases. This is a one-line change to `IMMUTABLE_CACHE_CONTROL` in `genomeos/publication/data_release.py`.
- **(c)** Also rewrite the existing objects' metadata with `python scripts/gcloud_repo.py run storage objects update "gs://<bucket>/releases/2026-10-17/**" --cache-control="public, max-age=3600"`. This is a metadata-only update and does not touch the bytes. It cannot shorten copies that are already cached.

Details: data store design 2026-10-17 §9 item 6, in PR #474.

## Update: owner decisions applied in #474

**Decision 1, discoverability: decided.** The public base URL is committed: `https://storage.googleapis.com/genomeos-atlas-data/`, in `genomeos/publication/data_release.py`. It is `scripts/fetch_data.py`'s default, and a variable or flag naming anything else is refused.

`docs/repo-gcloud-auth.md` now allows committing public read-only bucket URLs and names. Project ids and numbers, accounts and credentials are still not allowed. `test_no_concrete_bucket_url_is_tracked` exempts exactly that URL form.

The bucket's settings were also changed in place. No object was rewritten: 246 objects, 246 versions.

- Object versioning: on.
- Soft delete: 30 days, up from the default 7.
- `allUsers` holds `roles/storage.legacyObjectReader`, so anyone can read an object by key but nobody can list the bucket. Anonymous listing now returns 403/401. It held `roles/storage.objectViewer` before.

**Still open here:**

- item 2, the budget alert (needs billing permissions);
- item 4, the cache lifetime of the uploaded objects. They are still `public, max-age=31536000, immutable`, unchanged.

Item 3's CI check now belongs with the planned CI automation through Workload Identity Federation.
