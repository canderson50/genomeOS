## Body

## TL;DR

The coverage SVG exists, but the README embeds it directly from `raw.githubusercontent.com`. GitHub does not proxy that image through its normal image cache, so the badge can be broken in clients or networks that block the raw-content host. Serve the committed SVG through the project's public GitHub Pages domain, matching the working seqlab pattern.

## Objective and measurable result

Make the first-party coverage badge load reliably from the public project domain. Both the badge image and its click destination must return HTTP 200, and GitHub's rendered README must reference `https://genome-os.org/_static/coverage.svg`.

## Engineering change

Point the README badge image at `https://genome-os.org/_static/coverage.svg`. Keep the badge hyperlink pointed at the CI workflow, where the coverage value is produced and checked. Retain `website/public/_static/coverage.svg` as the generated, version-controlled source copied into the Pages build.

## Assumptions and consumers

The SVG remains generated by `scripts/render_coverage_badge.py`, reviewed in git, and freshness-checked by CI. The Pages workflow already deploys `website/public/**` to the custom domain. GitHub README rendering and users opening the repository are the direct consumers. This changes no scientific behavior or coverage calculation.
