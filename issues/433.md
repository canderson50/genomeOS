## Body

## Request and scope

The user requested an audit of the current Atlas map and overlayable data, followed by a plan for users to ask an AI agent questions and request map overlays. Gemini 3.8 Flash is a supported provider candidate (`gemini-3.8-flash`, function calling and structured outputs; https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash).

This is a proposal for triage, not an implementation PR. The design currently defers conversational agents to P12 (§16); this narrow first release composes existing published artifacts and does not perform fitting or scientific inference on requests. No implementation has begun. Private per-user conversations are the planning assumption; shared rooms require an explicit room/role/concurrent-map-state contract and are a separate phase.

## Scientific and engineering contract

- Claim: users can discover, display and explain published geographic evidence through natural language without turning estimates into observations or visual similarity into trait correlation.
- Output: cited answers and reproducible, reversible map actions tied to immutable artifact identities. Acceptance: requested IDs/versions/measurement semantics remain exact, unknown/prior-dominated masks remain visible by default, unsupported requests leave map state unchanged, and another user can restore the same versioned view.
- Components/interfaces: strict overlay manifest and action schemas; P4 read API tool adapters; backend Gemini provider adapter and bounded chat orchestrator; the existing Cesium viewer and comparison component. Dependencies point toward schemas and pure validators. The AI receives bounded API results rather than raw SQL, file access or arbitrary fetch capabilities.
- Assumptions/refusals/consumers: current published artifacts only; public evidence only; no personal-genome uploads, new burden estimates, disease-risk inference, GWAS correlation/colocalization, or pleiotropy results. The association database remains empty. Browser clients render validated action results; researchers/users consume cited answers and versioned map views.

## Inventory verified 2026-10-11

The deployed https://genome-os.org/data/atlas/catalog.json exactly matches the local catalog.

- 30 maps, all with observations: HbS (1), G6PD deficiency in hemizygous males (1), cytokine variants (4), HLA alleles (20), KIR carrier frequencies (4).
- Measurements: 25 allele-frequency, one phenotype-frequency and four carrier-frequency maps. Preserve these different denominators and meanings.
- Current layers: measured points, inferred surface, support mask, geographic context, country outlines. Posterior mean/standard deviation are selectable metrics. One scientific artifact per explorer; the local integration in PR #432 adds two independent synchronized explorers.
- Natural Earth country boundaries and populated places are geographic context. Basemap/terrain options depend on provider capability and credentials.
- HbS gnomAD, dbSNP and AlphaGenome caches are evidence panels, not geographic phenotype overlays. Provider presence does not authorize arbitrary geographic rendering.
- AlphaEarth satellite embeddings are registered as `candidate_only`; other climate/demographic research inputs are not admitted map overlays merely because they were investigated.
- No currently exposed burden/region-aggregation endpoint in `genomeos/atlas_api.py`; offline burden functions do not imply a published burden layer.
- Source restrictions remain field-specific. Preserve commercial-use declarations, provenance and biocultural notices. The recorded decision in #66 permits derived-surface publication subject to explicit source restrictions; it does not grant access/redistribution for every source.

## Delivery sequence

1. **Admission and policy:** address #54's class-based server enforcement. The current read service checks `surface_eligible` in a manifest; an agent must not rely on prompts or caller-set flags to enforce governance. Expose a bounded, versioned manifest aligned with the existing publication catalog. Include identity, measurement, available metrics/layers, source/licence declarations, uncertainty/support semantics, hashes, and permitted actions. Candidate datasets remain unavailable.
2. **Deterministic map actions:** strict typed actions for selecting an artifact, showing observations/surface/uncertainty/support, focusing a named region, opening source evidence, and launching side-by-side comparison. Validate against the server-authoritative manifest. Keep independent legends and masks; do not blend two frequency surfaces into a single scientific quantity. Include an action ID, catalog revision, state preconditions, applied-state acknowledgement, undo and shareable URL.
3. **Chat UI and Gemini backend:** a map-adjacent chat panel with streamed answers, source links, action receipts, cancellation and undo. Server-side credentials only. Tools read P4 through bounded adapters; Gemini proposes structured commands and the server validates them. Distinguish proposed/applied/failed actions and report success only after renderer acknowledgement. Limit tool steps, request time and token use; isolate sessions and reject stale map actions.
4. **Grounded evaluation and release:** test 'Show HbS observations in West Africa', 'Show uncertainty', 'Compare HbS and G6PD', and 'Explain this unknown region'. Refuse absent artifact IDs/versions, candidate-only environmental layers, invented numerical summaries and trait correlation/pleiotropy. Test malicious instructions in retrieved text, direct tool calls, field restrictions, provider failures, session isolation, undo, URL restoration, mobile accessibility and exact agreement with source records. Release first to existing approved maps.
5. **Later expansions:** independently qualified environmental/demographic overlays; validated regional aggregations and publishable burden artifacts; collaborative rooms with roles, room membership, ordered map actions and explicit shared-state ownership. Each expansion needs its own data admission and acceptance evidence.
