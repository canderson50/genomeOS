## Body

`tests/test_surface_fit.py::test_the_inducing_approximation_fits_and_predicts[kmeans]` fails in CI on every branch opened since 2026-10-19, and it passed on main two days earlier. The difference between the two runs is the resolved `jax` version, and `jax` is the one surface dependency in `pyproject.toml` with no upper bound.

## The failure

```
genomeos.surfaces.fit.ConvergenceError: sampler did not converge
(r_hat 1.224 > 1.05 (worst: lengthscale); effective sample size 13 < 200 (worst: lengthscale)).
Per §12 this variant is excluded from the surface set rather than published.
```

Three things follow from that table.

1. **It is not branch-specific.** It fails on four unrelated PRs, and the three from 2026-10-19 have nothing in common with each other or with #498.
2. **It is deterministic rather than flaky.** Every failing run reports the identical `r_hat 1.224` and `effective sample size 13`, which is not what a race or a time-out looks like. Re-running will reproduce it.
3. **The only thing that changed is the resolved dependency.** `numpyro 0.22.0`, `pymc 6.3.2` and `arviz 1.3.0` are identical in the passing and failing runs. `jax` and `jaxlib` moved from 0.11.2 to 0.12.0 on 2026-10-19, and were already 0.12.0.1 by 2026-10-25.

## The pin gap

`pyproject.toml` bounds the other three deliberately, and the comment above them says why:

```
"pymc>=5.16,<7",
"arviz>=0.18,<2",
"numpyro>=0.15,<1",
```

`jax` and `jaxlib` arrive transitively through `numpyro` with no bound at all, so a new JAX release reaches CI without a commit. The note beside those bounds ("PyMC changed how NUTS options are passed between 5.x and 6.x, enough for two contributors…") describes exactly this failure mode, and it happened through the dependency that was left open.

## Options

1. **Bound jax in the `surfaces` extra**, the same way the other three are bounded, and let a JAX upgrade be a deliberate change with the convergence test run against it. Minimal, and it restores main for the four blocked PRs.
2. **Investigate the 0.12 behaviour** before bounding. `r_hat 1.224` with an effective sample size of 13 says the chains barely moved, which is a sampler or gradient change rather than a small numerical drift, so it is worth understanding before it is pinned away.
3. **Both**: bound now so PRs can land, and keep the investigation as its own item.

## What this issue does not claim

I did not bisect JAX between 0.11.2 and 0.12.0, and I could not reproduce locally: this machine cannot install the `surfaces` extras, so `tests/test_surface_fit.py` does not collect here. The version comparison above is from the two runs' install logs, and the failure is read from the CI log rather than re-derived.
