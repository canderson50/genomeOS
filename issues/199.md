## Reproduction and expected behavior

In a clean Python process with the checkout explicitly on PYTHONPATH:

```bash
PYTHONPATH=. python -c 'from genomeos.surfaces.persistence import load_fit'
```

Observed during #191's compatibility checks at `c74b617`:

```text
persistence.py:15: from genomeos.surfaces.fit import SurfaceFit
fit.py:706: from genomeos.surfaces.persistence import FIT_FORMAT, load_fit, save_fit
ImportError: cannot import name 'FIT_FORMAT' from partially initialized module
'genomeos.surfaces.persistence' (most likely due to a circular import)
```

The established `from genomeos.surfaces.fit import load_fit` succeeds. The persistence
module is unchanged from parent `6692d1e` (SHA256
`c152de8af5021e4eee031dda122b952517ebfeb1c7c5b2180044830b37f78402`), and the parent's
fitter also has the reciprocal re-export. This is an existing import-order problem;
it was not fixed as a side effect of configuration extraction. Searches of open and
closed issues for cache/persistence/pickle reproducibility found no matching report;
closed #112 was inspected and concerns exposing draws, not this cycle.

Expected: the module that owns persistence functions can be imported in isolation,
without a circular runtime dependency solely to annotate `SurfaceFit`.

## Contract and acceptance evidence

Engineering objective: keep the science/cache boundary independently importable
(design §§5–6), preserving the existing `fit` re-exports and trusted-cache format.
Add isolated-subprocess regression tests for both import orders and retain actual
trusted synthetic old/new cache checks. A typing-only class reference should not
force a runtime import cycle. No model, prior, convergence criterion, source data,
serving behavior, or artifact-format change is implied. Never load an untrusted pickle.

This is a distinct scoped bug report, not a request to expand #191's configuration
task or an assertion that existing callers through the supported old seam fail.
