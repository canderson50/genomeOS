## Body

## Problem

The Python `test` job in `.github/workflows/ci.yml` runs on every pull request, whatever it touches, and takes 17–50 minutes. Docs-only pull requests #424, #401 and #403 each ran it for 24–52 minutes, and so does every website-only pull request. `pages.yml` already filters by path; `ci.yml` does not.

## What "safe to skip" has to mean

Correctness beats savings. A pull request that could break a Python test or a Python CI gate must still run them. A path is skippable only if nothing in the Python job reads it, and that has to come from evidence (a trace of the job's reads), not intuition. Three facts make this less obvious than "skip `website/**`":

- **Python tests read website files.** These include the byte-identical fixture copies under `website/tests/fixtures/atlas/`, `website/public/data/atlas/` (the catalog and the borders binary), `website/src/atlas/public-artifacts.json` (also read by `check_commercial_use.py`), and the coverage badge `website/public/_static/coverage.svg`. Tests also read `docs/literature-evidence-curation.md`.
- **Two checks read every tracked file.** `scripts/check_private_files.py` (and `test_the_repository_itself_is_clean`) and `test_web_layout.py::test_no_concrete_bucket_url_is_tracked` (`git grep` over the tree) can each be failed by a website-only or docs-only pull request. They are the checks most likely to catch a website mistake, such as a hard-coded bucket URL or a personal path.
- **`ruff check .` lints every `.py` file anywhere**, including under `website/`.

## Proposal

- A small `changes` job classifies the pull request's changed paths, with a `git diff` on the merge commit and no third-party action. The `test` job skips only when that job answers exactly `false`. A failed classification runs the tests, and a skipped job still reports a status, so `test` can later be made a required check.
- A cheap `tracked-files` job runs the two whole-tree checks on every event. They need only the standard library and pytest.
- Pushes to `main` are never filtered: the coverage badge and the container publish (`docker.yml`, via `workflow_run` on `ci`) depend on that run.

Acceptance: a backtest over the last 40 merged pull requests shows which would have skipped. None of the skipped ones touched a path the Python job reads. The workflow passes actionlint.
